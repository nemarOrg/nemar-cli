# Python dependencies for the NEMAR Zarr converter driver (generate_zarr.py).
#
# Declaring biosigIO here (instead of only as a `uv pip install` command in the
# workflow) makes it a real entry in GitHub's dependency graph, so this public
# repo shows up under biosigIO's "Used by" / Dependents and the converter work is
# credited to neuromechanist/biosigio. It also single-sources the version pin for
# both the Actions workflow and the Hallu cron.
#
# Extras: [zarr] -> zarr v3 store writer/reader; [meg] -> mne (.fif + BrainVision
# .vhdr + CTF .ds + KIT/Yokogawa + 4D-BTi importers); [mef3] -> mne>=1.12 + pymef
# (MEF3 .mefd iEEG import; kept as its own extra upstream because it pins a newer
# MNE than [meg] alone needs). Core biosigIO covers .set/.fdt/.edf/.bdf.
# >=1.2.0: streams EDF/BDF via pyedflib (importer parity), so generate_zarr.py's
# _biosigio_streams_edf() gate flips on and large EDF converts instead of OOMing
# (nemar-cli#944).
# >=1.2.1: int16 export zero-fills non-finite (NaN/inf) samples and flags the
# channel instead of failing the whole recording -- a NaN in one MISC/aux channel
# (MoBI accelerometer/force/sync) no longer sinks a dataset's EEG coverage
# (biosigio#107). Bumping the pin forces the idempotent cron install to upgrade.
# >=1.2.2: EEGLAB importer loads column-form (N, 1) chanlocs/event struct arrays
# instead of silently truncating the recording to one channel (biosigio#110,
# root cause of nemarDatasets/on002718#1); pairs with this repo's
# channel_count_mismatch fidelity gate.
# >=1.2.3: adds MEF3 .mefd import (mne.io.read_raw_mef + pymef, [mef3] extra) and
# 4D/BTi import (mne.io.read_raw_bti, content-detected -- no extension), both with
# bounded-memory streaming support. This is the release generate_zarr.py's
# .mefd/BTi discovery (dir_recording_of/bti_recordings) depends on; the [mef3]
# extra must be added here too, or .mefd recordings raise ImportError at convert
# time even though discovery finds them. nemarOrg/nemar-cli#1095 (track: #1097).
# >=1.2.4: two classes of recording that were being discarded despite being fully
# readable now convert.
#   - MATLAB v7.3 (HDF5) EEGLAB `.set` (biosigio#114, closing biosigio#21).
#     MNE refuses these outright and scipy.io.loadmat cannot read them either,
#     since a v7.3 `.set` is an HDF5 container, not a classic MAT file. Read via
#     h5py, which is the `[hdf5]` extra -- added below for exactly the same reason
#     `[mef3]` was: without it these raise ImportError at convert time even though
#     discovery finds them. 544 recordings measured across the archive.
#   - Three false EDF/BDF rejections (biosigio#116, closing biosigio#109):
#     a channel with physical_min == physical_max (legal EDF -- a referential
#     montage's reference electrode is identically zero by construction, and one
#     such channel was discarding the whole recording), a numeric header field
#     NUL-padded instead of space-padded, and discontinuous EDF+D. Recovered reads
#     are numerically identical to a pyedflib read (verified at machine-epsilon on
#     real recordings, all channels) and are flagged via `edf_tolerant_read`.
#     Genuine truncation is still reported as corruption. ~4,332 recordings across
#     23 datasets, the largest single cluster.
# >=1.2.5: reads CTF `.ds` recordings whose `.hc` names the head coils
#   `Nasion`/`LPA`/`RPA` (biosigio#117). MNE substring-matches that descriptor
#   against a case-sensitive `nasion`/`left ear`/`right ear` table, so every coil
#   parsed as unknown and the whole recording failed with "Some of the mandatory
#   HPI device-coordinate info was not there" -- the coil coordinates were
#   present and correct the entire time. 380 recordings in on006502, which is
#   every recording it has (nemarOrg/nemar-cli#1125). Fixed upstream too
#   (mne-tools/mne-python#14191, merged), but no MNE release carries it yet;
#   biosigIO's shim is gated on that and no-ops once one does.
# >=1.2.6: three things index format v3 reads or depends on (epic #1181 phase 7).
#   - View levels are chunked at a CONSTANT 1024 COLUMNS instead of a constant
#     ~4 s, and the geometry is declared in attrs instead of having to be probed
#     (biosigio#126, this repo's #1178 items 1-2). A viewport needs ~1000-2500
#     columns at ANY level, so constant-seconds chunking made a zoomed-out read
#     594 requests for 1.16 MB on a 40-minute store; constant-columns makes it 3.
#     The attrs are what index v3 republishes per group: group `n_view_levels` /
#     `view_levels` / `view_downsample` / `view_chunk_columns` / `chunk_seconds` /
#     `shard_seconds`, level-0 `source_rate_hz` / `chunk_samples` / `shard_samples`,
#     view-array `chunk_columns`, root `view_chunk_columns`.
#   - `bids.apply_channels_tsv` CONVERTS a channel's samples into the unit the
#     BIDS sidecar declares rather than only relabelling them, exempts the
#     discrete channel types, and reports what it did per file in
#     `rec.metadata["channels_tsv_units"]` (biosigio#125, closing #122). The
#     converter now calls it on the in-memory path and republishes that report as
#     the index's per-store `units_report`, so a unit that could NOT be adopted is
#     visible on the public surface instead of silently served.
#   - Resource exhaustion propagates as `MemoryError` (and friends) instead of
#     being reclassified as a data failure (biosigio#124), which is what keeps
#     `convert_one`'s `except MemoryError` handler -- and therefore the retryable
#     `recording_memory_exceeded` code -- reachable for reader-side exhaustion.
# NOT yet a floor: biosigio#127 (`stream_to_zarr` applying channels.tsv). Until it
# ships, the STREAMING path leaves units as the importer read them while the
# in-memory path adopts the sidecar's, so one dataset's small and large recordings
# can disagree on units. That is why `ZARR_ENGINE_VERSION` stays at "2" in
# zarr_queue.py: the back-catalog re-conversion must not be armed while that
# disagreement exists. Raise this floor to the #127 release and bump the engine in
# the same change (see AGENTS.md's Zarr paragraph for the two-step ack).
biosigio[zarr,meg,mef3,hdf5]>=1.2.6

jsonschema>=4.21
