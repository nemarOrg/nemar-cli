> **STATUS: CURRENT design input.** Written 2026-10-02. Decisions will land as ADRs with the phases; where this document and an ADR disagree, the ADR wins.
> The architect's plan below was produced before the owner's hosting decision. Where it disagrees with the overrides in this section, the overrides win.

## Owner overrides (2026-10-01 and 2026-10-02), binding

1. **Hosting.** The stock Neurobagel node (recipes stack, graph mode: GraphDB, node API, federation API, query tool) runs on `nemaring.ucsd.edu`, a persistent local server. It is NOT a Workers-native node and NOT Cloudflare Containers. The plan's node-catalog, node-subject-level and differential-test phases, and its upstream-contract risks U2 and U3 for a custom node, are dropped: the node is stock, so contract conformance holds by construction. Graph-mode JSON-LD is therefore the primary output; the catalog-mode pair is optional.
2. **Conversion** runs as a step of publication and import. The plan's daily writer becomes a hook in those flows, with a reconcile as a safety net.
3. **Scope.** OpenNeuro mirrors (`on` datasets) are INCLUDED; the plan excluded them. This was agreed with Neurobagel's PI because NEMAR adds value (Zarr serving, the viewer, richer metadata, soon data quality, HED and processed data). Anonymous, private, unpublished, sandbox and fixture datasets remain excluded.
4. **Delivery.** nemaring pulls artifacts from a private store. No ssh push and no inbound access to nemaring.
5. **Viewer.** Link out only; the first link on each record is the NEMAR dataset page.
6. **nemaring is shared.** It runs Infisical (the secrets store) and Umami. Existing containers must never be stopped, restarted or reconfigured, and the node runs under hard memory and CPU limits. Read-only check on 2026-10-02: 8 CPUs, 7.7 GiB RAM (about 5.2 GiB available), 23 GB disk free, Ubuntu 24.04, Docker 29.1, Compose 2.40, loopback ports 8080 and 3000 in use.

## 1. Recommendation
One pure TypeScript transform in shared/neurobagel/. Input: one dataset's data-plane documents (metadata.json, participants.tsv, participants.json), a pinned snapshot of the Neurobagel vocabulary, optional reviewed curation entry. Output: catalog-mode pair (<id>_dataset_description.json, <id>_annotated.json), graph-mode JSON-LD, one compact node-index entry; deterministic uuid5 identifiers.
Runs in two places: (1) a scripts/neurobagel/ gatherer reading data.nemar.org over plain HTTP (the owner's "Apache server" path; spikes, golden fixtures, local validation with stock recipes); (2) ONE production writer in the API Worker: picks candidates from D1 with a single eligibility predicate, collects the same documents via the functions that already serve them, writes artifacts and one index object to a new private R2 bucket (ADR 0076 pattern; not D1, ADR 0034).
Node: served from the same Worker on a new host `neurobagel.nemar.org`; a Workers-native implementation of the n-API contract limited to the 7 endpoints the f-API calls. Records always protected. Eligibility re-checked against D1 on every request (ADR 0017; same way as ADR 0066's 2026-09-28 amendment). Every outgoing record validated against a vendored copy of the f-API response model. Behaviour proven by differential tests against real containers (v1 = stock catalog-mode n-API; v2 = stock graph-mode n-API on the same JSON-LD). Registration in neurobagel/menu only after a production soak. `on` mirrors excluded.
Confidence: medium-high on transform, eligibility, storage; medium on the node choice (depends on Neurobagel's attitude to a non-reference node).
Rejected: stock graph mode/GraphDB (cannot run at the edge; recipes wipes /data and reloads on every start, docker-compose.yml:11-12; nemaring only a labeled fallback); stock catalog-mode n-API on Cloudflare Containers as end state (catalog mode returns [] for any modality filter, crud.py query_dataset_catalog_attributes; needs dummy graph credentials and GitHub raw access per cold start, main.py; kept as fallback F1); unmodified bagel in GitHub Actions (Python, uuid4 churn, pybids, ADR 0020 machinery for ~200 small docs); upstream-only with Neurobagel hosting a community catalog node (planning#342; cheapest, but removal latency and contract tracking not NEMAR's; fallback F2); .nemar/neurobagel.json sidecars, GitHub App PRs, mirror org (touch ~200 published PR-only repos (ADR 0001), add a publicly served backend-written surface needing the ADR 0065 blind).
Unknowns that could flip it: U1 Neurobagel objects to a non-reference node (-> F1 or F2). U2 the f-API calls response_cls.model_validate() per node record with no try, so one malformed NEMAR record could take down the whole federated /datasets query for every user (if upstream won't harden, a custom node carries a zero-defect burden). U3 parsed index competes with manifest scans for memory in the shared 128 MB isolate (-> separate Worker, needs an ADR 0078 decision). U4 owner's answers on "dot ath" and "federate core".

## 2. The transform
Inputs only: GET data.nemar.org/<id>/metadata.json (neuroschema 0.4.1: anonymous, authors[], keywords[], license, demographics, external_links, provenance, tasks, datatypes, extensions.nemar.bids_index); .../<id>/latest/participants.tsv; .../participants.json. NOT inputs: dataset_description.json (identity only from metadata.json, which the backend writes and blinds, ADR 0065:67-69; depositor files cannot be blinded, ADR 0067:26-28); the manifest (ADR 0072; structure comes from bids_index, built as a streamed digest, routes/data.ts:1835-1946, services/data-router.ts buildDatasetMetadataFromDigest).
Manifest bound resolved: per branch, 38,000 unsigned/public (data.ts:487) and 30,000 presigned (:495), ADR 0074:72-86 (ADR 0072:60's 30,000 amended to point at 0074). nm000281 (102,532 entries) 413s under either.
bids_index = subjects -> {sessions:[...], modalities:{<datatype>:{tasks:{<task>:{runs}}}}} (BidsIndexBuilder, data-router.ts ~985-1040). Sessions and modalities are sets per subject: the session-to-datatype pairing is LOST. Fine for catalog mode and subject-level modality; not enough for graph-mode acquisitions in multi-session datasets (nm000104 hundreds of session labels, nm000284 33). Phase P6 adds an additive `session_modalities` map per subject to the NEMAR extension block.
Outputs: <id>_dataset_description.json (recipes catalog model: Name, Authors, required ParticipantCount, ReferencesAndLinks, Keywords, RepositoryURL, AccessInstructions, AccessType, AccessLink); <id>_annotated.json (data dictionary with Annotations: Identifier, Categorical+Levels, Continuous+Format+ValueRange, Collection+IsPartOf); <id>.jsonld (bagel graph: Dataset -> Subject -> PhenotypicSession/ImagingSession -> Acquisition{hasContrastType}); <id>.index.json (uuid, card fields, compact per-subject rows); <id>.report.json (counts only, never participant values).
Identifiers: dataset nb: + uuid5(NEMAR_NB_NS, https://nemar.org/dataset/<id>); subjects/sessions/acquisitions extend the name (/<sub>, /<ses>, /<datatype>). NEMAR_NB_NS fixed UUID committed once. SHA-1 from Web Crypto (no dependency, no WASM, ADR 0050). bagel mints uuid4 by default (models.py) and recipes' catalog init mints nb:+uuid4 on EVERY start (process_jsonld.py), so NEMAR ids never churn.
Field mapping (mechanical unless marked): metadata.name -> Name/hasLabel; authors[].name -> Authors; constant https://nemar.org/dataset/<id> -> ReferencesAndLinks[0] (becomes card homepage; first valid URL wins, get_homepage_url); external_links.dataset_doi -> ReferencesAndLinks[1] = https://doi.org/<doi>; keywords[].term -> Keywords; constant https://data.nemar.org/<id>/ -> RepositoryURL (never built from GitHub); AccessType public; AccessLink nemar.org page; AccessInstructions from license+latest version; AccessEmail NEVER set; ParticipantCount from demographics.subjects_count else bids_index subjects else TSV rows (all unknown -> dataset refused); participant_id -> nb:ParticipantID; age column (Units absent or years) -> nb:Age with FromFloat/FromRange/FromBounded/FromISO8601 chosen by value grammar and ValueRange computed (months/days -> curation); sex -> nb:Sex (snomed:248153007 male, 248152002 female, 32570681000036106 other; gender -> curation); group healthy/control/HC -> ncit:C94342 (as in neurobagel/openneuro-annotations); other group values and assessments -> CURATION ONLY (terms from pinned diagnosis.json/assessment.json); bids_index eeg/meg -> hasContrastType nidm:Electroencephalography / nidm:Magnetoencephalography (main branch vocab); ieeg, emg, nirs, motion, beh, others -> no term, dropped and counted; handedness, weight, height, species -> dropped.
Missing data: MissingValues ["", "n/a", "N/A", "NA"]; NEMAR auto-generated all-n/a placeholder TSVs (services/participants-tsv.ts:1-27) become entirely missing; unparseable value treated as missing and counted; >10% of non-missing ages unparseable -> age column goes to curation; unknown field never emitted (catalog age_range null, which the n-API excludes from any age-filtered query: correct behaviour); subjects = union of TSV rows and bids_index subjects, phenotype only from TSV, imaging only from bids_index, mismatch size in report.
Edge classes (measured live across all 199 nm datasets): no participants.json (6: nm000109, 110, 112, 113, 114, 133): column-name and value-grammar rules still apply, units assumed years only for an `age` column with values 0-120, reported. No participants.tsv (3: nm000270-272, 27+ subjects each in bids_index): minimal dictionary, subjects from bids_index with imaging sessions only, ParticipantCount from demographics, flagged as a data-quality finding. Both files annexed/302 (3: nm000147, 150, 153): HTTP gatherer follows the 302, size-capped 4 MB; Worker resolves the annex object with one manifest EntryQuery; flagged as an ADR 0015/0060 violation for a separate issue.
iEEG/EMG gap: main vocabulary has 8 nidm terms, only eeg and meg for electrophysiology. Unmerged `auto-generate-bids-vocab` branch of neurobagel/communities holds 58 bids: terms incl. eeg, emg, ieeg, meg, nirs (last commit 2026-04-22); communities#70 stale-flagged 2026-07-07. Emit no term for unmapped datatypes, ever (EMG never mis-mapped to EEG); pure-EMG datasets (nm000104-107, 281) list no modality, honestly. Switching nidm -> bids is one pinned-snapshot change timed to planning#377.
Curation: reviewed repo file shared/neurobagel/curation.json keyed by dataset id; partial Neurobagel Annotations blocks per column (annotation-tool export format); pins to git blob SHAs of participants.tsv and participants.json (the manifest checksum of a git-tracked file IS the blob SHA, ADR 0066:36-37); evidence (source, reviewer, date). Loader strict: rejects unknown keys, terms not in pinned vocab, level maps not covering observed values; stale pin -> curated columns skipped, mechanical ones ship, report says curation_stale. Why: spends no columns (ADR 0034), no new written surface needing the blind (ADR 0065), analogue of ADR 0073; Neurobagel keeps OpenNeuro curation the same way (neurobagel/openneuro-annotations, 1,220 per-dataset JSON files). Scale: of 196 readable TSVs, 148 have `group`; "about 30 datasets need diagnosis curation" not re-verified.
Tests (no mocks): real fixtures with provenance (URL, date, version, sha256) from data.nemar.org: nm000132 (clean EEG), nm000103 (float ages, assessments), nm000104 (EMG, n/a placeholders, Levels), nm000109, nm000270, nm000147, one iEEG, one MEG; anonymous negative control = nm099998 from data-test.nemar.org (NOT nm000284, to keep a live concealed deposit out of a public repo). Golden outputs with stable bytes; determinism by building twice. CI runs Neurobagel's own code: recipes init_data over generated pairs must log every dataset catalogued with zero skipped; stock catalog n-API container loaded with our metadata; real neurobagel/federation_api container pointed at nodes via local_nb_nodes.json with NB_FEDERATE_REMOTE_PUBLIC_NODES=False; JSON-LD: recipes graph-mode validation + GraphDB and a differential of the phenotypic part against real `bagel pheno` (needs no pybids, so pybids is skipped by design (I)).

## 3. Eligibility and the blind
Predicate: one exported SQL constant NEUROBAGEL_ELIGIBLE_SQL plus a pure re-check isFederationEligible(row): status='active' AND visibility='public' AND anonymous=0 AND first_published_at IS NOT NULL AND withdrawn_at IS NULL AND EXISTS version row AND ((dataset_id LIKE 'nm%' AND dataset_id < 'nm099900' AND not sandbox AND not exemplar) OR (allowExemplars=1 AND is_exemplar=1)).
The data plane alone is NOT a filter: its gate checks visibility only (routes/data.ts:112-144) and serves nm000284 (anonymous:true, authors:[], DOI null): exactly the ADR 0065:108 trap. The anonymity half is permanent: migration 0085's backfill stamped every public row and its triggers abort setting anonymous=1 on any stamped row (0085_anonymous_deposit.sql:68-94), so a federated dataset can never become anonymous; removal only handles visibility, status, withdrawal, deletion. Exemplars on staging: allowExemplars bound from isNonProductionEnv, fails closed in production; nm099998 stays excluded on anonymity terms. `on` mirrors: EXCLUDE (415 of NEMAR's 579 on mirrors already have Neurobagel annotations upstream, by join of the data.nemar.org index with openneuro-annotations).
Enforcement: the one writer selects only via the predicate and re-checks every row (like buildZarrCatalog's postcondition), deciding from the D1 row (ADR 0065) never an HTTP `anonymous` value; the transform itself refuses any input with anonymous !== false (missing = unknown, shared/contract/dataset.ts:58-64); a source scanner asserts only neurobagel-writer.ts calls env.NEUROBAGEL.put/delete and never projects d.concept_doi except via CONCEPT_DOI_SQL (anonymity.ts:245).
Removal: (1) immediate: the node re-runs the predicate filtered by id list on every /datasets and /subjects request; (2) within 24 h: writer deletes ineligible artifacts and rebuilds the index; (3) sweep reports residue; nothing in Neurobagel caches results (f-API fans out each query).
Scheduled verification: daily sweep, production-only cron wiring (function unguarded so admin route works on staging, ADR 0067:291-294): (a) index vs predicate: residue, eligible-but-missing >48 h; (b) node self-probe: no ineligible uuid, every record validates; (c) after registration: federate.neurobagel.org/nodes lists NEMAR and /diagnoses does not list NEMAR under errors; (d) upstream drift: release tags of api, federation-api, query-tool and blob hashes of communities vocab files vs pinned. Rules: heartbeat even if it throws; verdicts healthy/alarm/unknown (ADR 0053); alarms only when work was outstanding; unknown never shown as zero (ADR 0054); reports in a new section of the existing weekly issue; an anonymity-class finding goes to audit_log and the dataset_anonymity mail category ONLY, never GitHub (ADR 0067:80-87); ADR 0067's own sweep gains one invariant: no anonymous deposit present in the Neurobagel index.
Never exposed: participant-level records (records_protected hard-coded true; /subjects returns "protected" (graph) or [] (catalog, per api/routers/subjects.py)); no NB_RETURN_AGG toggle in NEMAR code; no participant ids/values; no AccessEmail, owner identity, reserved DOI, or constructed GitHub URL.

## 4. Regeneration
Triggers: new published version; metadata/enrichment change; curation-file change (on deploy); transform or vocabulary version bump. All picked up by the daily writer; each dataset skipped if a cheap fingerprint matches (D1 row fields, latest version tag, manifest ETag, curation-entry hash, transform version, vocab commit) stored as R2 customMetadata (derive, don't store). No hook in the publication orchestrator (24 h ingestion latency acceptable; removal does not depend on the writer). Idempotent: uuid5 + sorted keys; a test asserts a second run does zero PUTs. Cost negligible (~200 datasets, mostly edge-cache hits per ADR 0066, R2 ops in the hundreds/day); rides the existing 03:00 tick (ADR 0054), regenerates at most N datasets per tick (N measured in P3; that tick shares an unbudgeted subrequest allowance, ADR 0054:187-195). Backfill via POST /admin/neurobagel/regenerate (dry run default) and `nemar admin neurobagel regenerate|status`.
Upstream contract change detection (2026-09-14 removed /query same day across api v0.11.0 and f-API v0.10.0): (1) weekly CI matrix (and on PRs touching shared/neurobagel): f-API and n-API at pinned tag, latest, and main, including a test comparing the f-API BaseQueryModel field list with filters the node accepts so any new filter fails CI; (2) outgoing validation drops and reports failing records (fail closed); (3) daily drift canary; (4) upstream hardening PR U2. Public f-API exposes no version (openapi 0.1.0; api#511 open, stale), so tags are the only signal.
Fences: dev node host neurobagel-test.nemar.org never registered; no code path writes to any neurobagel/* repo (registration is a human PR); dev writer writes only to nemar-neurobagel-dev (bindings scoped per environment, ADR 0076); writer sends no mail; federation canary production-only; cron wiring production-only, outside DEV_CRON_ALLOWLIST (index.ts:395-399, :878-882).

## 7. Viewer
Verdict: LINK OUT; do not define an embed contract now. The card already renders AccessLink, a Repository button and every http link in references_and_links (query-tool ExpandedDetails.tsx; isCatalog = num_matching_subjects === null in ResultCard.tsx); with nemar.org first in the links the homepage opens the dataset page where the viewer lives, with no upstream change. Existing deep links: https://nemar.org/dataset/<id>?v=<tag>&view=<entities> (BIDS entity syntax, 256-char cap; the viewer reads only v and view; website/src/lib/eeg-viewer/recording-nav.ts:301-345; website#326 closed). Under protected mode Neurobagel never sees participant ids, so per-recording links cannot come from Neurobagel; only dataset-level or ?view=task-<label> links are expressible and Neurobagel has no task concept. Worth publishing now: the ?v=/?view= contract on docs.nemar.org as a stable partner contract (EBRAINS asked).
Minimum Neurobagel ask per reading of "dot ath": (1) data/dataset path = a per-dataset viewer or browse URL: NONE today (use ReferencesAndLinks/AccessLink); a dedicated field touches five repos (bagel description model, recipes init, api DatasetQueryResponse, federation-api (drops unknown fields), query-tool types.ts/ExpandedDetails.tsx). (2) a dotted path or config key = node-level URL template: template key in the node directory, must key on dataset_uuid (one-way uuid5), so NEMAR serves a resolver neurobagel.nemar.org/go/{dataset_uuid} redirecting to nemar.org; touches menu schema, federation-api /nodes, query-tool (api#511 /info as alternative carrier). (3) "auth": nothing (NB_ENABLE_AUTH unnecessary for public data). (4) NEMAR dot-dir sidecar: not a Neurobagel ask; rejected. (5) URL suffix with {sub}/{task}: {sub} incompatible with protected records; reduces to (2) plus a task concept Neurobagel lacks. (6) data-plane path: none, RepositoryURL = data.nemar.org/<id>/ already.
Embed cost if ever wanted (M, website): /embed/dataset/[id] route; per-path CSP branch allowing only frame-ancestors https://query.neurobagel.org (today frame-ancestors 'self' at middleware.ts:209 and X-Frame-Options SAMEORIGIN in path-independent headers at :232-235; XFO dropped on that route only); no OSA widget hosts in script-src/connect-src/frame-src on that route; minimal chrome and "Open on nemar.org" link; only federation-eligible datasets (anonymous deposits 404); unsafe-eval stays (iframe runs on NEMAR's origin); annotations in IndexedDB (website ADR 0013) are storage-partitioned inside a third-party frame (I); bytes follow the existing allowlisted nemar.org path to zarr.nemar.org, NEMAR pays; Neurobagel needs an iframe slot plus the reading (1) or (2) field chain. Defer.
