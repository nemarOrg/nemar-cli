## Goal

A test boots the local stack and drives one runner job through NEMAR's real routes from dispatch to a settled `finished`, including outputs uploaded under the lease and downloaded by the stack's `outputs` command, so the first full flow is proven before any workstation is involved.

## Context

- Read DM-08's `backend/scripts/compute-local-stack.ts` and its test, DM-07's routes and `backend/test/compute-runner-queue.test.ts`, `backend/test/helpers/compute-lifecycle-fixture.ts` (the launcher stand-in that decodes a received launch value strictly as the launcher does), and `backend/test/compute-e2e.test.ts`.
- The launcher stand-in is the test's external party, as in the existing compute tests; NEMAR's logic is all real.

## Scope

- New `backend/test/compute-local-stack-runner.test.ts`; a fix to `backend/scripts/compute-local-stack.ts` only if the test exposes a defect, with its own assertion.

## Decided design

Settled: the test starts the stack (ephemeral ports, temporary state, a fixture dataset seeded through the pipeline fixture helper), registers a runner and exchanges a token with the stored owner key, dispatches `nemar-floor-zarr` with `executor: "runner"` through the admin route, claims it with `free_slots: 1`, sends `started`, plays the launcher's side with the existing launcher stand-in (bundle, outputs with `X-Compute-Lease`, outputs complete, the launcher documents), sends `uploading`, completes with usage, then asserts through `GET` routes and the job record: `finished`, `executor` `runner`, `accounting` `none`, `launch_spec_digest` equal to the SHA-256 of the decoded text, `settled_final_at` set, `charged_milli` 0, zero ledger rows; then runs `outputs --job <id>` and asserts every declared output file arrived with its size.
A second case uses an operator-style reference `localhost/nemar-python@sha256:<64 hex>` as the stack's `--image` and shows it is accepted end to end (plan, unverified item 15).
The implementer may choose: test helpers inside the test file.
