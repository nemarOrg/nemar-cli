## Goal

`signaljourney_validator`, installed from a built wheel with no repository checkout beside it, validates a document against its own packaged schema with no `schema_dir` argument, refuses an unresolved `$ref` with an exception, logs instead of printing, and a tag-triggered workflow can publish it to PyPI once the owner sets up trusted publishing.

## Context

- Repository signalJourney/signalJourney, default branch `main`. Read issue #6 (`gh issue view 6 -R signalJourney/signalJourney`), `pyproject.toml` (`signaljourney_validator`, setuptools, the `signaljourney-validate` command), `src/signaljourney_validator/` (`Validator(schema=None, schema_version=None, schema_dir=None)`, `.validate(...)`, `cli.py`), `schema/` (`signalJourney.schema.json`, `definitions/`, `extensions/`, `versions/0.1.0/`, `examples/`), `tests/`, `.github/workflows/`.
- Why now: nemar-process vendors a pinned copy of the schema (`recipes/nemar_process/_vendor/signalJourney/schema/`, recorded by tree SHA-256) and installs the validator from a git commit, because a wheel cannot find `schema/` today.
- The merge, the version and the PyPI release are the owner's; the PyPI trusted publisher is configured by the owner.

## Scope

- Move `schema/` to `src/signaljourney_validator/schema/` (git move, history kept), and update every path that names it in `src/`, `tests/`, `docs/` and `mkdocs.yml`.
- `pyproject.toml` (package data), `src/signaljourney_validator/` (default schema loading, logging, unresolved `$ref`), new `.github/workflows/publish.yml`, tests, `README.md`.

## Decided design

Settled:
- The default schema directory is `importlib.resources.files("signaljourney_validator") / "schema"`; `schema_dir` and `--schema` still override it.
- An unresolved `$ref` raises `SchemaResolutionError` (a new exception class) at `Validator` construction, not at validation time.
- Every `print` in the package becomes a `logging` call on the logger `signaljourney_validator`; the command line prints results as it does today.
- `publish.yml`: on a pushed tag `v*`, `uv build`, then PyPI trusted publishing (`pypa/gh-action-pypi-publish`, pinned by commit SHA) in an environment named `pypi`; no token secret.
- The schema bytes do not change: a test compares the SHA-256 of every packaged schema file with the same file at the base commit.
- The `version` in `pyproject.toml` is not changed (the owner sets it at release).
The implementer may choose: test structure, the logger's message texts.

## Acceptance

- `uv run --with pytest pytest -q` passes, including new tests for packaged loading, the unresolved-`$ref` exception and the unchanged schema bytes.
- `uv build` succeeds, and `uv run --isolated --no-project --with dist/*.whl python -c "import json, importlib.resources as r; from signaljourney_validator import Validator; d = json.loads(r.files('signaljourney_validator').joinpath('schema/examples/minimal_valid.json').read_text()) if r.files('signaljourney_validator').joinpath('schema/examples/minimal_valid.json').is_file() else None; print(Validator().validate(d, raise_exceptions=False) if d else 'no packaged example')"` run from a directory outside the checkout prints `[]` (or the implementer names the packaged minimal example it used instead, and the command prints `[]` for it).
- `uv run --isolated --no-project --with dist/*.whl signaljourney-validate validate <the minimal valid example>` exits 0 from outside the checkout.

## Gates

- `uv run --with ruff ruff check src tests`, `uv run --with ruff ruff format --check src tests` (report "not configured" instead if the repository has no ruff settings, and do not add any), `uv run --with pytest pytest -q`, `uv build`.

## Stop conditions

- The schema's relative `$id` or `$ref` values break when loaded from package data: stop and report the smallest fix; never edit schema content in this card.
- Publishing would need a token secret: stop.
