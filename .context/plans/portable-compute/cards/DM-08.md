## Goal

`bun backend/scripts/compute-local-stack.ts serve` runs NEMAR's real compute, runner, webhook and admin routers on loopback over a persistent SQLite database with every migration and a persistent R2 behind the S3 stand-in with per-run credentials, seeded so an owner can register a runner, and keeps its state across a restart; `outputs <job>` downloads a job's results through the real links route.

## Context

- Read `backend/test/helpers/compute-harness.ts`, `compute-s3-standin.ts` (its default key `STANDINKEYID` must not be used here), `compute-seed.ts`, `compute-routes-app.ts`, `helpers/d1.ts` (`migrate`, `realD1`), `compute-pipeline-fixture.ts`, `backend/test/compute-e2e.test.ts` (its CLI leg: the real CLI against a `Bun.serve` of the real routers, and how it points the CLI at it), `backend/src/routes/compute.ts` (`POST /compute/jobs/:id/links`: bearer first, the job's account).
- This is the test harness made long-running, not a deployment; it says so on start.
- The runner on the demo workstation reaches it through `ssh -R` on ports 8787 and 8788 (DM-15), which exposes the loopback ports on that host: hence per-run S3 credentials and keys only in mode-0600 files.

## Scope

- New `backend/scripts/compute-local-stack.ts` and `backend/test/compute-local-stack.test.ts`.
- A helper under `backend/test/helpers/` may change to accept a persistent database, fixed ports or given S3 credentials, with a test. Only this card edits those helpers.
- Nothing in `backend/src/` except an exported constant a helper needs.

## Decided design

Settled:
- `serve --state <dir> [--port 8787] [--s3-port 8788] --image <ref@sha256:hex> [--seed-from-catalog <id>]...`: `<dir>` created mode 0700; binds 127.0.0.1 only and refuses any other host.
- Database `<state>/stack.sqlite`, migrated with the tests' `migrate` on first start and checked at every start (a missing migration is applied, never a reset).
- R2: Miniflare buckets persisted under `<state>/r2/`, behind the S3 stand-in on `--s3-port`, with an access key and secret of 32 random bytes each generated on first start into `<state>/s3.json` (mode 0600) and reused; `globalThis.NEMAR_COMPUTE_S3_URL = http://127.0.0.1:<s3-port>`.
- Environment object in memory: `ENVIRONMENT=development`, `COMPUTE_ENABLED=1`, `COMPUTE_RUNNERS_ENABLED=1`, `COMPUTE_RUNTIME_IMAGE` from `--image`, `API_BASE_URL=http://127.0.0.1:<port>`, `PRESCREEN_CALLBACK_SECRET` from `<state>/secret` (32 random bytes, mode 0600). No Tapis configuration.
- Seeds on first start through the real services: an owner, an admin, the `nemar-pipelines` service account, the default policy version, the `pipelines` and `people` pools; API keys in `<state>/keys.json` (mode 0600, keys `owner`, `admin`, `pipelines`), never printed.
- `--seed-from-catalog <id>`: refuses `nm000103`-`nm000107` and reserved-band ids; reads `https://api.nemar.org/datasets/<id>` and its versions with User-Agent `nemar-local-stack/0`, and inserts only the public values the eligibility predicate and `resolveRun` read (including the version's commit); prints the field names it copied.
- `--seed-fixture`: seeds the fixture dataset of `compute-pipeline-fixture.ts` (no network), for nemar-process CI (DM-18) and this card's test.
- `outputs --state <dir> --job <id> --to <dir>`: calls `POST http://127.0.0.1:<port>/compute/jobs/<id>/links` with `Authorization: Bearer <pipelines key>` and no body, follows the `after` cursor, downloads every link into `--to`, prints file names and sizes only.
- Banner on start: `NEMAR local compute stack (not a deployment) at http://127.0.0.1:<port>, <git branch>@<short sha>`.
The implementer may choose: internal structure, logging.

## Acceptance

- `bun test backend/test/compute-local-stack.test.ts` passes: the stack starts on ephemeral ports in a temporary state directory, seeds a fixture dataset through the existing pipeline fixture helper (no network), registers a runner through the real admin route with the stored owner key, exchanges a token, restarts, and still answers `GET /compute/runners/me` for a new token; `s3.json` holds no `STANDINKEYID`; every file in the state directory is mode 0600 or 0700.
- `bun backend/scripts/compute-local-stack.ts serve --state <tmp> --image ghcr.io/nemarorg/nemar-python@sha256:<64 hex> --seed-from-catalog <DM-02 id>` prints the banner, and `curl -s http://127.0.0.1:8787/health` answers (quote it).
