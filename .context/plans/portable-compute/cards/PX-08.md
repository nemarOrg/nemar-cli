## Goal

The image installs eegprep-lean from sccn/eegprep's `develop` merge commit of PR 616 (`af914512`) instead of the PR's head commit (`14ba46e8`), so the pin names a commit on the owner's branch, and records say so; the later move to a release is named and ready.

## Context

- sccn/eegprep PR 616 was merged into `develop` on 2026-11-13 with the merge commit `af914512` (full hash from `git -C $EEGPREP rev-parse af914512` after a fetch); `14ba46e8` is its second parent and stays reachable. `packages/eegprep-lean/pyproject.toml` says version `0.5.0` at both commits.
- No release contains eegprep-lean yet: eegprep 0.5.0 on PyPI predates it and eegprep-lean is not on PyPI (checked 2026-11-14). The move to a release belongs to whichever card first pins an eegprep release (PX-05 when the owner releases eegprep, owner question QA of the CP-2 note).
- nemar-process records the reader as `eegprep-lean@<version>+<commit>` (`zarr_input.reader_string()`, the commit read from the installed package's `direct_url.json`), so the records of a new image will name `af914512`'s full hash.
- The comment above the pin in `pyproject.toml` and `docs/recipes.md` and `docs/images.md` describe the PR-head pin; `docs/recipes.md` also cites `14ba46e8` as the commit that added the micro-sign unit, which stays true and stays.

## Scope

- `pyproject.toml` (the `runtime` group's eegprep-lean line and its comment), `uv.lock`, `docs/images.md`, `docs/recipes.md` (the pin sentences only), `docs/upstream.md` (if it names the pin), and any test that asserts the old commit (`git grep -n 14ba46e8 -- tests` lists them).

## Decided design

Settled:
1. The requirement becomes `eegprep-lean[zarr] @ git+https://github.com/sccn/eegprep@<the full 40-hex hash of af914512>#subdirectory=packages/eegprep-lean`; `uv lock` updates only eegprep-lean's entry (check with `git diff uv.lock` that no other package moved).
2. The comment says: pinned to PR 616's merge commit on `develop`; the next move is to the eegprep release that contains it, by the card that pins that release.
3. If an eegprep release that contains `packages/eegprep-lean` exists at dispatch (PyPI `eegprep-lean`, or a `v*` tag of sccn/eegprep whose tree contains the package), pin that instead (PyPI version if published, else the tag's commit) and say so in the report.
