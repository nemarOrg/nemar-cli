## Goal

A tag `nemar-runner-vX.Y.Z` on a commit of `main` makes CI build a deterministic runner bundle (runner plus launcher) and sign it with cosign keyless; on a workstation, `nemar_runner install` and the daily `self-update` accept only such a bundle, and a systemd user service runs the installed version and switches to a new one only while it holds no job; a machine of another institution turns updating off with one key.

## Context

- How the runner runs today: from a checkout (`docs/runner.md`, "Running it"; the `runpy` boot line of DM-15 step 6). The runner's version is its own (`nemar_runner.__version__`); nemar-process releases (`vX.Y.Z`) attach no files and publish nothing (`docs/release.md`).
- The image workflow is the model for a signing workflow: `.github/workflows/image-nemar-python.yml` (it refuses a commit not on `origin/main`, only its `sign` job has `id-token: write`); `tests/release/test_workflows.py` pins that no trigger matches another artifact's tag, so the new tag family is added there.
- The runner refuses links and group- or other-writable paths in `launcher_dir`, its configuration and its root; the installed layout must pass those checks.
- Exit 3 (`runner_outdated`) already makes a runner drain and exit when the Worker's `min_runner_version` is newer.
- Lingering (`loginctl enable-linger`) and the cosign binary on a workstation are the owner's (OQ3 of `cp2-note-S.md`); this card is CI-only and installs nothing on a workstation.
- The owner (2026-11-14): the workstations are shared with other people's work (`cp2-note-N.md`). The runner takes only idle capacity through the `availability` object of `config.json` (card L2) and decides the GPU per job (card L3); the service adds the lowest scheduling and I/O priority for the runner and everything it starts. On a host whose user manager has no `cpu` or `io` controller delegated (workstation B has no `cpu` delegation, DM-01), systemd ignores `CPUWeight=` and `IOWeight=` in a user unit; niceness, the I/O class and the containers' hard limits still apply.

## Decided design

Settled:
1. Tag family `nemar-runner-vX.Y.Z`, whose `X.Y.Z` must equal `nemar_runner.__version__` at the tagged commit; the workflow refuses a commit not reachable from `origin/main`, builds with `uv run python scripts/build_runner_bundle.py --out dist/` (a `.tar.gz` of `runner/` and `launcher/` with sorted entries, fixed mtimes, owner and mode, so two builds are byte-identical, and a test proves it), signs with `cosign sign-blob --bundle nemar-runner-X.Y.Z.tar.gz.sigstore.json --yes`, verifies its own signature, and attaches both files to the GitHub release of the tag without overwriting an existing asset. Only the signing job has `id-token: write`; only the release job has `contents: write`.
2. Runner identity: `^https://github\.com/nemarOrg/nemar-process/\.github/workflows/runner-release\.yml@refs/tags/nemar-runner-v[0-9]+\.[0-9]+\.[0-9]+$`, issuer `https://token.actions.githubusercontent.com`, a constant in `install.py`; a test asserts the workflow file's trigger and this regexp agree.
3. `install --version X.Y.Z --prefix <dir>`: downloads the two assets of that release over HTTPS with `urllib`, runs `cosign verify-blob <tarball> --bundle <bundle> --certificate-identity-regexp <identity> --certificate-oidc-issuer <issuer>` (cosign from the trusted PATH or `cosign_path`), refuses on any failure, unpacks into `<dir>/versions/X.Y.Z/` with no link, no absolute path and no `..` member accepted, sets modes 0700 or 0600, and writes `<dir>/current` (the version, written to a temporary name and renamed). It never deletes the version that is running; older versions beyond the newest two are removed.
4. `self-update`: off when the configuration's `self_update` is false (the opt-out); otherwise lists the repository's releases, picks the highest `nemar-runner-v*` that is newer than `current` and not a prerelease, and runs step 3 for it. It never restarts anything.
5. The idle switch: between claims, when `<prefix>/current` names a version other than the running one and the runner holds no job, it logs `update_pending from=<a> to=<b>` and exits 0; systemd starts the new version. A running job is never interrupted by an update.
6. Units (user units): `nemar-runner.service` with `ExecStart=/usr/bin/python3 -I -S %h/<prefix>/bin/boot.py run --config <config>` (boot.py, installed by `install`, reads `current`, accepts only `^[0-9]+\.[0-9]+\.[0-9]+$`, and runs `nemar_runner` from that version's directory with `runpy`), `Restart=always`, `RestartSec=30`, `KillMode=mixed`, `TimeoutStopSec=180`, `NoNewPrivileges=yes`, `UMask=0077`, and the shared-workstation priority `Nice=19`, `IOSchedulingClass=idle`, `CPUWeight=1`, `IOWeight=1`; `nemar-runner-update.service` carries the same four priority lines; `nemar-runner-update.timer` daily with `RandomizedDelaySec=3600` running `self-update`. The prefix and config path are filled in by `install --write-units`. The live-availability configuration lives in `config.json`, not in the unit: if L2 (and L3) have merged before this card's PR is opened, `docs/runner.md`'s service section shows a complete shared-workstation `config.json` with their `availability` (and `gpu`) objects; otherwise the report carries that as a patch note for L2 and L3.
7. Tests: the bundle builds identically twice; `install` against a real loopback file server (`http.server`; loopback `http://` is accepted only through a test-only base-address parameter) refuses an unsigned bundle, a bundle whose signature does not match, and a tarball with a link or a `..` member, and accepts a bundle signed in the test with a throwaway cosign key pair through an injected trust-anchor parameter that production code never sets (the default is the keyless identity constant, exercised for real in S2D); the idle switch exits 0 only with no job; both service units carry the four priority lines; `systemd-analyze --user verify` on the units when available (skipped with a reason otherwise); `test_workflows.py` covers the new tag family.
The implementer may choose: the asset download code's structure and the test helpers.

- A test can only pass by trusting an identity other than the constant in production code: stop and report.
