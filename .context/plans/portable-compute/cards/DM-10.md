## Goal

With `NEMAR_CONTAINER_RUNTIME=docker` (or `podman`) the launcher runs the same image digest with isolation equivalent to its Apptainer argv and with CPU and memory limits, and with the variable unset or `apptainer` nothing changes.

## Context

- Read `launcher/nemar_launch/run.py` (`build_argv`: `--containall --cleanenv --no-home --no-mount bind-paths --pwd /work`, binds `/work`, `/tmp`, `/code:ro`, `/data/<id>:ro`, `--env NEMAR_OUT=/work/outputs`, `--nv` only for GPUs), DM-09's limits rule, `docs/launcher.md`, `tests/launcher/`, `.github/workflows/ci.yml`.
- `image.uri` ends `@sha256:<hex>`; Docker and Podman verify the digest on pull.

## Scope

- `launcher/nemar_launch/run.py` (or a new `runtime.py`), `codes.py`, `tests/launcher/test_runtime_docker.py`, `tests/e2e/test_docker_launch.py`, `docs/launcher.md`, `.github/workflows/ci.yml` (one job running the Docker end-to-end test on `ubuntu-latest`).

## Decided design

Settled:
- `NEMAR_CONTAINER_RUNTIME`: unset or `apptainer` keeps today's path; `docker` uses `docker`; `podman` uses `podman`; another value ends with the launcher's existing image-missing exit and detail.
- Argv: `run --rm --pull=missing --network=bridge --user <uid>:<gid> --cap-drop ALL --security-opt no-new-privileges --read-only --tmpfs /tmp:rw,nosuid,nodev --workdir /work --cpus <cores> --env NEMAR_OUT=/work/outputs`, plus `--memory <memory_mb>m` when set, `--mount type=bind,src=<host>,dst=<path>[,readonly]` for exactly the four binds and their flags, `--gpus <n>` only when gpus > 0, then `image.uri` and the command. No `--privileged`, no host network, no `-v`, no host environment beyond what the Apptainer path passes.
- `NEMAR_SIF_ROOT` is not required under Docker or Podman.
- A pull failure maps to the existing image-missing detail; exit 137 with `OOMKilled` true (`docker inspect`) maps to `out_of_memory`.
The implementer may choose: the internal selection, test helpers.

## Acceptance

- `uv run --no-project --python 3.9 --with pytest --with jsonschema pytest tests/launcher -q` passes with argv tests pinning every flag above and the Apptainer argv byte-identical to DM-09's.
- `uv run pytest tests/e2e/test_docker_launch.py -q` on a host with Docker: a real container from a digest reads its read-only data bind, cannot write it or `/`, writes `/work/outputs`, and is killed at its memory limit; if your host has no Docker: "not run, would check: the new CI job".
