## Goal

A public-safe capability table for workstations A and B is committed as `.context/plans/portable-compute/probe-findings.md`, with a runtime verdict per host and one line naming the demo workstation by the rule below; raw host detail stays in the operator's scratch.

## Context

- Owner decisions (2026-11-13): a read-only probe over the two existing ssh aliases, as the owner's own login, once the plan is approved. The manager gives you the aliases as `$WS_A` and `$WS_B` and the scratch path of each as `$SCRATCH_A` and `$SCRATCH_B`; none of them is ever written into the repository.
- Creating a directory, pulling an image or installing anything on a workstation needs the owner's separate confirmation (Q12) and is not this card: the container smoke test is DM-14's.
- One of the two machines also runs the production Zarr conversion cron (ADR 0101: slots, a shared RAM and scratch admission ledger, a lock). Find which one WITHOUT touching it: read the crontab only; never list, open, lock or write anything under the converter's base, lock or ledger directory.

## Scope

- Create only `.context/plans/portable-compute/probe-findings.md` in nemar-cli.
- On the hosts: only the commands below; none writes a file; never `sudo`; nothing started or left running.

## Decided design

Settled: run exactly these through `ssh "$WS_A" '<cmd>'` (then `$WS_B` with `$SCRATCH_B`), saving full output to `<operator scratch>/dm01/<A or B>.txt`:
`uname -srm`; `cat /etc/os-release`; `nproc`; `free -g`; `df -hTP $HOME /tmp "$SCRATCH_A"`; `findmnt -no SOURCE,FSTYPE,OPTIONS -T "$SCRATCH_A"`;
`crontab -l 2>/dev/null | grep -c -E 'zarr'` (conversion cron yes if above 0); if yes, take the `ZARR_BASE` value from that crontab line (in scratch only) and run `df -P <that value>` and `findmnt -no SOURCE -T <that value>` (mount information only, nothing under it);
`command -v apptainer singularity docker podman sbatch squeue nvidia-smi python3 uv bun tmux`; `apptainer --version`; `docker version --format '{{.Server.Version}}'`; `docker info --format '{{.SecurityOptions}}'` (rootless shows `name=rootless`); `podman info --format '{{.Host.Security.Rootless}}'`; `id -nG`;
`cat /proc/sys/kernel/unprivileged_userns_clone 2>/dev/null; cat /proc/sys/user/max_user_namespaces`; `stat -fc %T /sys/fs/cgroup`; `cat /sys/fs/cgroup/user.slice/user-$(id -u).slice/cgroup.controllers 2>/dev/null`;
`sinfo -s 2>/dev/null | head -5`; `nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader`; `python3 -c 'import sys; print(sys.version)'`;
`curl -sS -o /dev/null -w '%{http_code}' -A nemar-runner-probe/0 https://zarr.nemar.org/`, the same for `https://ghcr.io/v2/` and `https://api.nemar.org/health`;
`sshd -T 2>/dev/null | grep -i allowtcpforwarding` ("unknown" if refused).
Public-safe fields per host: operating system family and major version; cores; memory GiB rounded; scratch free GiB rounded and filesystem type; conversion cron yes/no; scratch on the converter's filesystem yes/no/not applicable; runtimes with versions; rootless yes/no; user namespaces yes/no; cgroup v2 and delegated `cpu` and `memory` yes/no; `docker` group yes/no; SLURM yes/no; GPU count and memory class; Python version; uv, Bun, tmux yes/no; egress yes/no to the three addresses; TCP forwarding yes/no/unknown; verdict `runtime: apptainer | docker | podman | none` (first present, in that order).
Demo workstation rule, written as the last line `demo workstation: A | B | none`: the host without the conversion cron if its runtime is not `none` and its Python is at least 3.9; else the conversion host only if its scratch is NOT on the converter's filesystem (it then runs with one slot, scratch at most 50 GB and at most 10 percent of that filesystem's free space, memory at most a quarter of its RAM: DM-15 uses these); else `none`.
The implementer may choose: the table layout.
