## Goal

`nemar-recipe run nemar-floor-zarr --out <dir> --dataset-id <id> --dataset-version <tag> --source-commit <40 hex> --image-digest sha256:<hex> --zarr-base https://zarr.nemar.org` runs nemar-floor's steps on every EEG store of the dataset's Zarr serving copy (or the `--recording` stores named), refuses a serving copy whose index was built from a commit other than the one its caller attests, records the caller's tag-equivalence attestation, counts every skipped recording, writes the floor's outputs under the `nemarfloorzarr` label with signalJourney provenance, and the image's lock contains the reader.

## Decided design

Settled:
- A recipe declares `input: "bids" | "zarr"`. For `zarr`, `--dataset-dir` is refused (usage error) and `--zarr-base` (an `https://` origin, declared as the recipe's option) and `--dataset-id`, `--dataset-version`, `--source-commit` are required; for `bids`, nothing changes.
- Network rule (lead ruling of 2026-11-13), replacing "the CLI opens no network connection" in the docstring and `docs/recipes.md`: a recipe whose input is `zarr` may open HTTPS connections only to the hosts in a fixed allowlist written in code, `ZARR_HOSTS` (the Zarr host) and `ZARR_DATA_HOSTS` (the data bucket host), in `recipes/nemar_process/common/zarr_hosts.py`, with a comment naming nemar-cli's serving configuration as their source; every other recipe opens none.
  `--zarr-base` must be `https://` on a host in `ZARR_HOSTS`; the index's `data_base` must be `https://` on a host in `ZARR_DATA_HOSTS`, else the recipe refuses before reading any chunk (the CLI's refusal exit, naming the field, not the value). No host is ever taken from data.
  Redirects: at most one hop, only `https://` to a host in `ZARR_DATA_HOSTS`; any other redirect is refused. A `sys.addaudithook` on `socket.getaddrinfo` and `socket.connect` refuses any other host, as a second fence. Requests carry no credentials.
  signalJourney records the hosts actually contacted (`extensions.nemar.input.hosts_contacted`).
- Commit attestation (lead ruling of 2026-11-13). The serving index is often built a few metadata-only commits after the version tag. `--source-commit` is the commit the caller attests the index was built from.
  Optional `--tag-commit` (40 hex), `--commit-equivalence` (`exact` or `metadata_only`) and repeatable `--commit-delta-path` (at most 32, each under `.nemar/` or `.github/`) carry the caller's check, made with DM-02's GitHub compare rule. When they are absent, the run is `exact` with the tag commit equal to `--source-commit`.
  The recipe reads `index.json` once and refuses (the CLI's existing refusal exit, naming the commits) when the index's `source_commit` differs from `--source-commit`. It also refuses an inconsistent attestation: `exact` with a different tag commit or any delta path; `metadata_only` with equal commits, no delta path, or a delta path outside `.nemar/` and `.github/`.
  Its network reaches only `--zarr-base`, so it cannot verify the ancestry itself, and the provenance says so. It records `index_sha256`.
- Stores: every store whose group is EEG, in index order, or exactly the `--recording` values (store paths from the index; an unknown one is a usage error). A store whose whole read exceeds eegprep-lean's `max_bytes` is skipped with reason `too_large`, a read failure with `read_failed`; both are rows of `desc-nemarfloorzarr_recordings.tsv` and counts in the final JSON summary line (`processed`, `too_large`, `read_failed`); the run fails only when nothing was processed.
- Per store: `to_eeg(load_recording(...))`, `eegprep.eeg_checkset`, then exactly nemar-floor's chain and parameters.
- Outputs: the floor's files with label `nemarfloorzarr` (`_channels.tsv`, `_badsegments.tsv`, `_filters.json`, `_qc.json`, `_signalJourney.json`, `_recordings.tsv`), keyed by store path; nothing written outside `--out`; no cache directory.
- signalJourney: the floor's document plus `extensions.nemar.input = {"kind": "zarr", "profile": "serving", "zarr_base", "dataset_id", "version", "source_commit", "tag_commit", "commit_equivalence", "commit_delta_paths", "commit_check": "attested_by_caller", "index_sha256", "zarr_engine_version" (from the index), "stores", "bytes_read"}` and `extensions.nemar.reader = "eegprep-lean@<version>+<commit>"`; the engine stays `eegprep@<installed version>`, which the image must report as `eegprep@0.5.0`.
- `scripts/validate_signaljourney.py <file>`: exit 0 when valid, 1 with the validator's messages.
The implementer may choose: module layout, how the floor's chain is shared.
