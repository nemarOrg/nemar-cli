## Goal

`nemar-recipe run nemar-floor-zarr --out <dir> --dataset-id <id> --dataset-version <tag> --source-commit <40 hex> --image-digest sha256:<hex> --zarr-base https://zarr.nemar.org` runs nemar-floor's steps on every EEG store of the dataset's Zarr serving copy (or the `--recording` stores named), refuses a serving copy built from another commit, counts every skipped recording, writes the floor's outputs under the `nemarfloorzarr` label with signalJourney provenance, and the image's lock contains the reader.

## Decided design

Settled:
- A recipe declares `input: "bids" | "zarr"`. For `zarr`, `--dataset-dir` is refused (usage error) and `--zarr-base` (an `https://` origin, declared as the recipe's option) and `--dataset-id`, `--dataset-version`, `--source-commit` are required; for `bids`, nothing changes.
- Network rule, replacing "the CLI opens no network connection" in the docstring and `docs/recipes.md`: a recipe whose input is `zarr` may open HTTPS connections to the `--zarr-base` host only; every other recipe opens none. A test installs a `sys.addaudithook` on `socket.connect` and fails on any other host.
- The recipe reads `index.json` once, refuses (the CLI's existing refusal exit, with a message naming both commits) when the index's `source_commit` differs from `--source-commit`, and records `index_sha256`.
- Stores: every store whose group is EEG, in index order, or exactly the `--recording` values (store paths from the index; an unknown one is a usage error). A store whose whole read exceeds eegprep-lean's `max_bytes` is skipped with reason `too_large`, a read failure with `read_failed`; both are rows of `desc-nemarfloorzarr_recordings.tsv` and counts in the final JSON summary line (`processed`, `too_large`, `read_failed`); the run fails only when nothing was processed.
- Per store: `to_eeg(load_recording(...))`, `eegprep.eeg_checkset`, then exactly nemar-floor's chain and parameters.
- Outputs: the floor's files with label `nemarfloorzarr` (`_channels.tsv`, `_badsegments.tsv`, `_filters.json`, `_qc.json`, `_signalJourney.json`, `_recordings.tsv`), keyed by store path; nothing written outside `--out`; no cache directory.
- signalJourney: the floor's document plus `extensions.nemar.input = {"kind": "zarr", "profile": "serving", "zarr_base", "dataset_id", "version", "source_commit", "index_sha256", "zarr_engine_version" (from the index), "stores", "bytes_read"}` and `extensions.nemar.reader = "eegprep-lean@<version>+<commit>"`; the engine stays `eegprep@<installed version>`, which the image must report as `eegprep@0.5.0`.
- `scripts/validate_signaljourney.py <file>`: exit 0 when valid, 1 with the validator's messages.
The implementer may choose: module layout, how the floor's chain is shared.
