## Goal

A registered runner claims a list of waiting runner jobs, keeps each with heartbeats, uploads only under the current lease, and completes each through the existing verification to a settled terminal state; lost runners, deadlines, cancels and expired leases end or release jobs exactly as plan D4 says.

## Decided design

Settled:
- `POST /compute/runners/claim`: `runnerAccess`, switch on, `protocol` equal to `RUNNER_PROTOCOL`, `runner_version` at least `RUNNER_MIN_VERSION = "0.1.0"` (else `runner_outdated`); first `sweepRunnerLeases` (at most `RUNNER_SWEEP_BATCH` rows); then up to `free_slots` times one conditional UPDATE that admits the oldest waiting job (`executor = 'runner' AND accounting = 'none' AND state = 'created' AND runner_claimed_at IS NULL AND records_written_at IS NOT NULL AND cancel_requested_at IS NULL AND claim_attempts < RUNNER_MAX_CLAIMS`) of the runner's pool that fits (`cores_per_node <= cores`, `COALESCE(memory_mb, 0) <= memory_mb`, `gpus <= gpus`) and whose dataset still passes the pipeline eligibility predicate inside the same statement, and only while `EXISTS (SELECT 1 FROM compute_runners WHERE id = ? AND revoked_at IS NULL)` and the runner's registering owner is still an approved, undeleted owner (the predicate `ownerMiddleware` applies, written as SQL over `users` in the same statement), so a claim that passed `runnerAccess` before a revoke and commits after it wins nothing; it sets `runner_claimed_at`, `runner_id`, `runner_backend`, `lease_id`, `lease_expires_at` (D1's clock plus 600 s), `claim_attempts + 1`, and a fresh `webhook_nonce` when the row's is NULL (DM-05's release may clear it; the job token is minted from it); `meta.changes = 1` is the winner test.
  For each winner the route builds the launch specification, writes `launch_spec_digest` (SHA-256 of its JSON text) under the same `lease_id` guard (a re-claim overwrites it), and answers it in `jobs[]` with the lease; `image_digest` is the row's.
- `POST /compute/runners/heartbeat`: `lease_lost` unless `runner_id` and `lease_id` match a live row; `started` writes `created -> running` with `started_at`; `uploading` writes `running -> archiving`; both renew the lease unless the job is terminal; `cancel` is `cancel_requested_at IS NOT NULL`.
- `POST /compute/runners/complete`: lease must match; idempotent for `(job, lease_id)` (a repeat answers the stored state); records the usage columns; the terminal decision is the code path the Tapis lifecycle uses once a job has ended (launcher documents from the results bucket, then `verifyResults`); with no launcher document, the runner's `launcher_failure_code` and `launcher_detail` are used only if declared together in `LAUNCHER_DETAILS`, else the exit number maps through `launcherExitNumber`'s inverse, else `runner_lost` `lease_expired`; a requested cancel ends `cancelled`; `lease_id` is kept after completion.
- Terminal batch for `accounting = 'none'`: no ledger statement; a new `NONE_SETTLED_STAMP_SQL` sets `settled_provisional_at` and `settled_final_at` with `charged_milli = 0` in the same batch, so `UNCOPIED_TERMINAL_SQL` copies its records like any settled job.
- Bundle, outputs and outputs-complete, for `executor = 'runner'` only, also require `X-Compute-Lease` equal to the row's `lease_id`, compared only when both the header and the row's value are present and match `LEASE_ID_RE`; a missing header, a malformed one, or a row whose `lease_id` is NULL (a cleared lease) is refused, never compared as equal (`(header ?? null) === row.lease_id` is forbidden); a refusal is the routes' existing single refusal (`job_not_found`).
- `sweepRunnerLeases(env, db)`: expired lease with `started_at` NULL clears the claim and lease (fails `runner_lost` `claims_exhausted` at the third); expired lease with `started_at` set moves the job to `unreported`; an `unreported` runner job whose outputs completed goes through verification; one that did not fails `runner_lost` `runner_revoked` at once when its `runner_id` names a runner with `revoked_at` set (DM-05's revoke batch put it there; no 60-minute wait), and otherwise, after `RUNNER_LOST_GIVE_UP_MINUTES`, fails `runner_lost` `lease_expired`; a started job past `started_at` plus `minutes` plus `RUNNER_DEADLINE_GRACE_MINUTES` without completed outputs fails `runner_lost` `deadline_exceeded`; a runner job with `cancel_requested_at` set that is `unreported` (DM-05's revoke puts a cancel-requested job of a revoked runner there) or whose lease expired ends `cancelled` when its outputs did not complete, and is verified when they did, so no cancel-requested runner job stays live. After DM-05's revoke an `unreported` job keeps `runner_id` and `runner_claimed_at` with `lease_expires_at` NULL: the sweep selects it by state `unreported` and the runner's `revoked_at`, never by `lease_expires_at`. Bounded, one log line of counts, wired into the production 30-minute tick and called by the claim route (so it runs in every environment while a runner polls); `cron-sweep-wiring.test.ts` gains its entry.
- Records before claim: the claim admits only rows with `records_written_at` NOT NULL (as above). `sweepRunnerLeases` also finds waiting runner rows with `records_written_at` NULL, older than 5 minutes (at most `RUNNER_SWEEP_BATCH`), and replays the records write with the same function `createJob`'s idempotent retry uses to finish a job's records. Nothing else repairs such a row, since the dispatch can now answer `recordsWritten: false` for a runner job.
- Cancel of a waiting (unclaimed) runner job, from the admin route or the person's route: it ENDS in SQL in one batch. State `cancelled`, `cancel_reason` recorded, `NONE_SETTLED_STAMP_SQL` with charge 0, its pipeline stamp ended through the same path a cancelled Tapis job's stamp takes, so the tuple is no longer blocked (`live_attempt_exists`) and the `maxLiveJobs` slot is free; the answer is the cancelled state, not `cancel_requested`. A claimed one records the intent for the heartbeat, as before.
- Records copy for runner rows: the same copy function that sets `result_records_at` for a Tapis row, called right after the terminal batch in `complete` (through `waitUntil`) and again by `sweepRunnerLeases` for terminal runner rows with `result_records_at` NULL (bounded), so it works in every environment; `result_records_at` is set by that function exactly as for a Tapis row.
- Signals: `runner_cancel_pending_failed` (a live runner row whose `cancel_requested_at` is more than 60 minutes old) and `runner_copy_abandoned` (a terminal runner row whose `result_records_at` is still NULL past the same threshold the Tapis `copy_abandoned` uses), declared in `shared/contract/compute-admin.ts`, counted in `GET /admin/compute/status`'s attention block, and printed by `nemar admin compute status` as `Attention: runner_cancel_pending_failed` and `Attention: runner_copy_abandoned` when positive.
The implementer may choose: statement names (exported as `*_SQL`), the module split.

## Acceptance

- `bun test backend/test/compute-runner-queue.test.ts backend/test/cron-sweep-wiring.test.ts backend/test/compute-route-inventory.test.ts backend/test/compute-e2e.test.ts` passes.
- Through real routes over `freshDb()` with the R2 stand-in: two runners racing for one job 50 times concurrently never both win; a claim with `free_slots: 3` and three fitting jobs returns three distinct leases; a misfit is not claimed; a full run (claim, `started`, outputs through the real routes with the lease, `uploading`, complete) ends `finished` with `launch_spec_digest` set, usage set, `settled_final_at` set, `charged_milli` 0, zero ledger rows and records copied; a repeated complete answers the same state; a stale lease's outputs and complete are refused; three unstarted expiries fail `claims_exhausted`; a silent started job goes `unreported` then `lease_expired`, and one whose outputs completed is verified to `finished`; after a runner is revoked through DM-05's route, its started job without completed outputs fails `runner_revoked` on the next sweep, while one whose outputs completed is verified to `finished` (`runner_revoked` is written nowhere else, and a source search in the test says so); a job past its deadline fails `deadline_exceeded`; a cancel reaches the runner and ends `cancelled`; a dataset made private after dispatch is not claimed.
- Security tests in the same file: the claim service called with a runner context captured before a revoke, after the revoke has committed, admits nothing, and so does one whose registering owner was demoted or deleted; with the row's `lease_id` NULL, bundle, outputs and outputs-complete are refused both with no `X-Compute-Lease` header and with any well-formed one; a claimed job whose `webhook_nonce` was cleared gets a fresh one and its job token works; for every combination of state (claimed `created`, `running`, `archiving`, `unreported`), runner revoked or not, and lease expired or not, a job with `cancel_requested_at` set is terminal after one `sweepRunnerLeases` unless its lease is current.
- Lifecycle tests in the same file: a runner job created with `recordsWritten: false` (the R2 stand-in refuses the first records write) is not claimed, and after the replay sweep the next claim admits it; an admin cancel of a waiting runner job answers `cancelled`, settles with charge 0, frees the slot (a second runner job then fits under `maxLiveJobs.cpu = 1`), and a new dispatch of the same tuple succeeds instead of `live_attempt_exists`; a finished runner job gets `result_records_at` from `complete`, and one whose first copy failed gets it from the sweep; `GET /admin/compute/status` and the CLI print `runner_cancel_pending_failed` for a live row cancelled 61 minutes ago and `runner_copy_abandoned` for a terminal row left uncopied past the threshold; an `unreported` row with `runner_id` set, `lease_id` and `lease_expires_at` NULL and `cancel_requested_at` set ends `cancelled` on one sweep.
- A source-search test over `backend/src/services/compute-runner-queue.ts` asserts that every statement that writes a live state (`running`, `archiving`, `unreported`) to a runner job carries `cancel_requested_at IS NULL` in its WHERE clause, and that the claim statement contains the `compute_runners` `revoked_at IS NULL` predicate.

## Stop conditions

- The Tapis terminal path cannot be reused without changing it for Tapis rows: stop and report.
- The claim cannot be one conditional statement on D1 including the revoked-runner and owner predicates: stop (advisor).
- The lease check cannot refuse a NULL `lease_id` without changing a Tapis job's path: stop and report.
- A cancel-requested runner job can be left live by any path you cannot change in Scope (for example a DM-05 statement): stop and name it.
- Ending a cancelled waiting job's stamp needs a change to the stamp sync outside this Scope: stop and report.
