## Goal

A registered runner claims a list of waiting runner jobs, keeps each with heartbeats, uploads only under the current lease, and completes each through the existing verification to a settled terminal state; lost runners, deadlines, cancels and expired leases end or release jobs exactly as plan D4 says.

## Decided design

Settled:
- `POST /compute/runners/claim`: `runnerAccess`, switch on, `protocol` equal to `RUNNER_PROTOCOL`, `runner_version` at least `RUNNER_MIN_VERSION = "0.1.0"` (else `runner_outdated`); first `sweepRunnerLeases` (at most `RUNNER_SWEEP_BATCH` rows); then up to `free_slots` times one conditional UPDATE that admits the oldest waiting job (`executor = 'runner' AND accounting = 'none' AND state = 'created' AND runner_claimed_at IS NULL AND records_written_at IS NOT NULL AND cancel_requested_at IS NULL AND claim_attempts < RUNNER_MAX_CLAIMS`) of the runner's pool that fits (`cores_per_node <= cores`, `COALESCE(memory_mb, 0) <= memory_mb`, `gpus <= gpus`) and whose dataset still passes the pipeline eligibility predicate inside the same statement; it sets `runner_claimed_at`, `runner_id`, `runner_backend`, `lease_id`, `lease_expires_at` (D1's clock plus 600 s), `claim_attempts + 1`; `meta.changes = 1` is the winner test.
  For each winner the route builds the launch specification, writes `launch_spec_digest` (SHA-256 of its JSON text) under the same `lease_id` guard (a re-claim overwrites it), and answers it in `jobs[]` with the lease; `image_digest` is the row's.
- `POST /compute/runners/heartbeat`: `lease_lost` unless `runner_id` and `lease_id` match a live row; `started` writes `created -> running` with `started_at`; `uploading` writes `running -> archiving`; both renew the lease unless the job is terminal; `cancel` is `cancel_requested_at IS NOT NULL`.
- `POST /compute/runners/complete`: lease must match; idempotent for `(job, lease_id)` (a repeat answers the stored state); records the usage columns; the terminal decision is the code path the Tapis lifecycle uses once a job has ended (launcher documents from the results bucket, then `verifyResults`); with no launcher document, the runner's `launcher_failure_code` and `launcher_detail` are used only if declared together in `LAUNCHER_DETAILS`, else the exit number maps through `launcherExitNumber`'s inverse, else `runner_lost` `lease_expired`; a requested cancel ends `cancelled`; `lease_id` is kept after completion.
- Terminal batch for `accounting = 'none'`: no ledger statement; a new `NONE_SETTLED_STAMP_SQL` sets `settled_provisional_at` and `settled_final_at` with `charged_milli = 0` in the same batch, so `UNCOPIED_TERMINAL_SQL` copies its records like any settled job.
- Bundle, outputs and outputs-complete, for `executor = 'runner'` only, also require `X-Compute-Lease` equal to the row's `lease_id`; a mismatch is the routes' existing single refusal (`job_not_found`).
- `sweepRunnerLeases(env, db)`: expired lease with `started_at` NULL clears the claim and lease (fails `runner_lost` `claims_exhausted` at the third); expired lease with `started_at` set moves the job to `unreported`; an `unreported` runner job whose outputs completed goes through verification; one that did not, after `RUNNER_LOST_GIVE_UP_MINUTES`, fails `runner_lost` `lease_expired`; a started job past `started_at` plus `minutes` plus `RUNNER_DEADLINE_GRACE_MINUTES` without completed outputs fails `runner_lost` `deadline_exceeded`. Bounded, one log line of counts, wired into the production 30-minute tick and called by the claim route (so it runs in every environment while a runner polls); `cron-sweep-wiring.test.ts` gains its entry.
- A cancel of a waiting runner job ends it in SQL; of a claimed one records the intent for the heartbeat.
The implementer may choose: statement names (exported as `*_SQL`), the module split.
