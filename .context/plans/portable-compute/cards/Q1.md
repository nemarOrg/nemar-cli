## Goal

A `nemar-ica` job for the public dataset `nm000274` version `v1.0.5`, dispatched through a local NEMAR stack, is claimed by `nemar-runner` (a checkout of `feature/runner-epic` with L2 and L3) on workstation B in a GPU pool while the GPU is reserved, runs on the CPU from the CUDA image's digest, and ends `finished` with schema-valid records that say `device` `cpu`, `fallback` true and reason `gpu_reserved`; its products are the CPU reference that card Q1g compares a GPU run with.
This is the recipe's acceptance on a runner, and it never needs the GPU.

## Context

- This repeats card DM-15's procedure (local stack on the manager's machine, reverse tunnel, runner on workstation B with the Docker backend) with a GPU-pool registration, the CUDA image, and the runner's shared-machine rule (L2) and GPU rule (L3); read DM-15 in full and follow its steps where this card does not differ.
- The owner (2026-11-14): workstation B is shared with other people's work and its GPU is often busy (a deadline now). Never start anything there while it is busy: the runner's `availability` check guards the job, and step 1 guards the operator. The GPU is reserved for this whole card by a `gpu-all` file in the runner's own reservation directory, so the card leaves the GPU alone even when it is idle.
- Workstation B stays untouched until the Sunday demo ends (about 2026-11-15T12:00 Pacific) and the manager records it.
- Live facts from the manager: `$WS_DEMO`, `$SCRATCH_B` (set `Q1_ROOT="$SCRATCH_B/q1"`; never DM-15's runner root), the CPU and CUDA references by digest (`$CPU_REF`, `$CUDA_REF`), and `$RUNNER_EPIC_COMMIT` (the `feature/runner-epic` commit containing L2 and L3).
- `nemar-ica` is sized at 10 cores, 32,768 MiB, one GPU as a ceiling, and 720 minutes for the CPU path (Q1a); this card measures the CPU wall time against those minutes.
- Q9: public data only. The stack is a local test stack, never staging or production; its records are labeled so.

## Scope

- Operator commands only. On workstation B: only `$Q1_ROOT` and the Docker image `$CUDA_REF`; no GPU process, no `sudo`, no installs, nothing on the root filesystem.

## Decided design

Settled, in order (record each output under `<operator scratch>/q1/`):
1. Machine idle check (the shared-machine rule): `ssh "$WS_DEMO" 'read l1 rest < /proc/loadavg; echo "load1=$l1 cpus=$(nproc) mem_avail_mb=$(( $(sed -n "s/^MemAvailable: *\([0-9]*\) kB$/\1/p" /proc/meminfo) / 1024 ))"'`; idle only if `load1` divided by `cpus` is at most 0.9 and `mem_avail_mb` is at least 46000 (the job's 32,768 MiB plus the runner's default reserve). If busy, re-check every 15 minutes for up to 2 hours, then stop with "postponed: workstation B busy" (not a failure).
2. Stack and tunnel as DM-15 steps 1 to 3, with `--image "$CPU_REF" --image-cuda "$CUDA_REF" --seed-from-catalog nm000274` and state under `<operator scratch>/q1/stack`.
3. Runner: `git -C $NEMAR_PROCESS archive --format=tar "$RUNNER_EPIC_COMMIT" runner launcher | ssh "$WS_DEMO" "mkdir -p -m 0700 '$Q1_ROOT/src' && tar -x -C '$Q1_ROOT/src'"`; DM-15 steps 4 to 6 with root `$Q1_ROOT`, runtime `docker`, `slots` 1, and in the configuration `"availability": {"claim_memory_mb": 32768, "reservation_dirs": ["<the absolute path of $Q1_ROOT/reservations>"]}` and `"gpu": {"enabled": true}`; `ssh "$WS_DEMO" "mkdir -m 0700 '$Q1_ROOT/reservations' && touch '$Q1_ROOT/reservations/gpu-all'"`; the runner's `availability` command prints `availability: idle` and its `gpu-check` prints `busy reason=gpu_reserved` for every GPU; then register `gpu-1 --pool gpu --cores 12 --memory-mb 49152 --gpus 1 --scratch-gb 100 --backend local --runtime docker --arch amd64 --site lab_demo --trust lab` (at or under DM-15's caps for this host, and at or over `nemar-ica`'s sizing).
4. `bun run src/index.ts admin compute pipeline run nemar-ica --dataset nm000274@v1.0.5 --executor runner --json`; record the job id and the time; run the runner `once` in the foreground. If it logs `claim_skipped` (the machine became busy), run `once` again every 15 minutes, for up to 60 minutes.
5. Gates: `bun run src/index.ts admin compute jobs record <job> --json` shows `finished`, executor `runner`, `image_digest` equal to `$CUDA_REF`'s digest; `bun backend/scripts/compute-local-stack.ts outputs --state <operator scratch>/q1/stack --job <job> --to <operator scratch>/q1/out`; every signalJourney file passes `uv run --group signaljourney python scripts/validate_signaljourney.py <file>` in a nemar-process checkout at the release's commit; each `_ica.json` says `device_requested` `auto`, `device` `cpu`, `device_reason` `gpu_reserved`, `fallback` true, threads 1, dtype `float64`, the torch version, `image_flavor` `cuda`, `did_converge` and the stop reason; the dataset record's `devices` counts only `cpu`; the runner log shows `device_chosen` with `cpu` and `gpu_reserved`, and the launcher log shows no `--gpus` argument; `find "$Q1_ROOT/jobs" -mindepth 1 | wc -l` is 0.
6. The CPU reference: keep `<operator scratch>/q1/out`, and write `sha256sum` of every `_unmixing.tsv` (named by its recording) to `<operator scratch>/q1/cpu-reference.sha256`.
7. Cleanup: `bun run src/index.ts admin compute runners revoke gpu-1`; stop the runner, the tunnel and the stack; delete the stack's state; `rm -rf "$Q1_ROOT"` on workstation B; the CUDA image stays in Docker's cache unless the owner asks otherwise; write `<operator scratch>/q1/README.txt` (commits, digests, job id, times, the wall time from dispatch to `finished` against the 720 minutes, gate outputs, the labels "local stack, not staging or production" and "CPU path, GPU reserved").
The implementer may choose: nothing else; a failed step stops the card.

## Stop conditions

- Before the demo has ended: do not start.
- Step 1 busy for 2 hours, or the runner still skipping claims 60 minutes after step 4: run step 7 and report "postponed: workstation B busy" with the logged reasons (not a failure).
- Any record says `cuda`, or the launcher log shows a `--gpus` argument: stop after cleanup (the reservation was not honored: an L3 defect).
- The job ends `failed` `runner_lost` `deadline_exceeded` (the CPU path did not fit 720 minutes): stop after cleanup and report the wall time per recording (a sizing finding for the lead; never resolved by using the GPU).
- Anything would touch staging, production, a switch, a live dataset, the converter's directories, the demo image or DM-15's runner root: stop.
