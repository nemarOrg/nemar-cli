## Goal

docs.nemar.org has one public page that tells a researcher and a lab administrator what portable processing is, what runs today and where, what is not yet true, and how the same job will later run on clusters, with no host fact, no internal reference and no claim beyond the evidence.

## Context

- nemarOrg/docs is private at source; pages outside `src/content/docs/admin/` are public on the site; read its `AGENTS.md` before writing.
- The page goes at `src/content/docs/platform/portable-processing.md` with a sidebar entry in `astro.config.mjs` after "Compute partner integration" in the "Platform & APIs" group (the plan's `compute/` path has no section; this is the lead's correction). Related public pages: `ecosystem/compute.md` (the roadmap), `platform/compute-partner.md`, `cli/guides/compute-job-environment.md`; link to them, change none.
- Never cite ADRs, `.context/`, card ids or pull requests in a public page (they are not public references); say what is true in plain words.
- Facts to state, each true on the day you write (re-check the status line against the board and production): jobs name an executor (NEMAR's cluster path or a registered workstation runner); a runner pulls work over HTTPS and opens no port; one container image identified by its digest runs under Apptainer or Docker; runner jobs use public data only and write no service-unit charge, and their usage is shown as runner-reported core-hours; QC on Zarr input runs on NEMAR's serving copy (EEG capped at 250 Hz, 16-bit), not on the archived recordings; whether production runs runner jobs yet (as of S2's merge: no, it is off).
- Never say or imply: runs on HPC unchanged, private data on runners, EEGLAB support, EEGDash integration, derivatives published or citable, catalog-scale throughput, or that the runner verifies signatures before card C2 is in a release.

## Scope

- `src/content/docs/platform/portable-processing.md` (new), `astro.config.mjs` (one sidebar entry).

## Decided design

Settled:
1. Sections: what it is (three sentences); how a job runs (dispatch, claim, run in a container by digest, outputs, scratch deleted); what is true today (a status line with the date: built and tested, on staging or not, production off or on); what it is not yet (the list of the Context's "never" items as plain "not yet" statements); for lab administrators (a runner runs as an unprivileged account, needs Apptainer or Docker and outbound HTTPS, is registered by NEMAR, and can be revoked at any time; no host detail); fidelity (the serving-copy sentence).
