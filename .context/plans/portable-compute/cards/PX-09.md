## Goal

A product that ends with exit 9 (recordings skipped with the code `time_budget`) can be completed: a second run over just those recordings, merged with the first by `aggregate --resume`, gives a dataset record that is complete (no `time_budget` row, `pending_count` 0, exit 0 under the usual rule), and nothing else about `aggregate` changes.

## Context

- Read issue #16 (`gh issue view 16 -R nemarOrg/nemar-process`), `docs/recipes.md` (the command; `--time-budget-s`; `aggregate`'s refusals: two inputs naming the same recording are exit 1; the exit table, where 9 outranks 0, 4 and 7), `recipes/nemar_process/cli.py` (`aggregate`, `TimeBudget`, the exit decision), `common/recipe.py` (`TIME_BUDGET_S`), and `tests/recipes/test_hooks.py` (how a test gives a registered recipe `TIME_BUDGET_S` with `register(monkeypatch, ...)` and drives the budget with a clock, while the floor's real `run_recording` processes real recordings).
- The issue's three boxes: decide how a later run replaces the `time_budget` rows; the merged record is complete only when none is left; test it with a cut run and a second run of the remainder.

## Scope

- `recipes/nemar_process/cli.py` (`aggregate`'s duplicate rule under `--resume`, and the report field of item 3), `docs/recipes.md`, new `tests/recipes/test_aggregate_resume.py`.
- Not `run`, the recipes, the launcher or the runner.

## Decided design

Settled:
1. **The mode.** `nemar-recipe aggregate <recipe> --in DIR [--in DIR ...] --out DIR --resume`. Without `--resume` nothing changes. With it, when two inputs name the same recording and exactly one of the two rows is `skipped` with the code `time_budget`, the other row and its files are taken and the budget row is dropped; any other duplicate (two real rows, two budget rows, a duplicated file) is still exit 1 with the path, found before anything is copied.
2. **Agreement first.** Every refusal `aggregate` already makes (identity, recipe and its version, engine stamp, seeds, build, image tag) still applies to every input before any replacement, so a remainder made by another build or engine cannot complete a product.
3. **The record.** The merged dataset record's `pending_count` counts the `time_budget` rows left, the exit is 9 while one is left and otherwise follows the usual rule, and `extensions.nemar.report.resumed` is the number of budget rows replaced (0 when `--resume` replaced none); the input order does not change the merged product.
4. **The remainder** is the list of paths whose row says `skipped` and `time_budget` in the first product's recordings table; the test passes exactly those to `run --recording`.
The implementer may choose: helper names.

## Acceptance

- `uv run --frozen --group runtime --extra cpu pytest tests/recipes/test_aggregate_resume.py -q` passes: a real floor run on four copies of the repository's EEG fixture, cut by a budget after two (exit 9), then a run of the two remaining paths, merged with `--resume` (exit 0, `pending_count` 0, `resumed` 2, four succeeded rows, files byte-identical to a single run's after removing the clock and the run id); the same merge without `--resume` exits 1; a remainder whose build differs is refused (exit 6) before anything is written; swapping the `--in` order gives the same product.
- Mutations, each failing a test: `--resume` also replacing a non-budget duplicate; `pending_count` not recomputed.
