## Goal

Before a job's image is pulled or run, `nemar-runner` proves with cosign that the image digest (Docker or Podman) or the SIF artifact (Apptainer) was signed by nemar-process's image workflow from `main` or an image tag; a job whose image does not verify ends without launching as `runtime_error` `image_unverified`, and `sif_pull` defaults to true because a pulled SIF is now checked.

## Context

- The workflow identity, exactly the image workflow's `SIGNING_IDENTITY`: `^https://github\.com/nemarOrg/nemar-process/\.github/workflows/image-nemar-python\.yml@refs/(tags/image-nemar-python-v[0-9]+\.[0-9]+\.[0-9]+|heads/main)$`, issuer `https://token.actions.githubusercontent.com`.
- The demo image `ghcr.io/nemarorg/nemar-python@sha256:33922cad47b58098079905edb9a06e688e533c30e0a24e364c0306f0f14c431a` is signed from `main` (the demo brief's signature check) and serves as the positive network fixture.

## Decided design

Settled:
1. The signed repository and identity are constants in `verify.py`; a test parses `.github/workflows/image-nemar-python.yml` and asserts the identity equals its `SIGNING_IDENTITY`.
2. Accepted references: exactly `ghcr.io/nemarorg/nemar-python@sha256:` plus 64 lower-case hex, optionally prefixed `docker://`, whose hex equals the claim's `image.digest`; a tag, another repository or registry, or a mismatch is refused before cosign runs.
3. Docker and Podman: `cosign verify <reference> --certificate-identity-regexp <identity> --certificate-oidc-issuer <issuer> --output json` (flags as the pinned cosign version spells them), environment `PATH` plus `HOME=<root>/cosign` (0700, the runner's own), timeout 120 s; success needs exit 0 and every entry's `critical.image.docker-manifest-digest` equal to `sha256:<hex>`.
4. Apptainer: verify `ghcr.io/nemarorg/nemar-python-sif:sha256-<hex>` the same way and take the verified manifest digest D from the output; fetch that manifest by digest from the registry with `urllib` (anonymous pull token from the registry's token endpoint), require `sha256(manifest bytes) == D` and exactly one layer, whose digest is L; pull with `apptainer pull <sif_root>/.<hex>.sif.<pid>.part oras://ghcr.io/nemarorg/nemar-python-sif@<D>` (cache and temporary directories inside the job's `scratch/`), require `sha256(file) == L`, then rename to `<hex>.sif`. An existing `<hex>.sif` is used only if a cache entry records its L and the file hashes to it.
5. Cache: `<root>/verified/<hex>.json`, mode 0600, written to a temporary name and renamed, holding the digest, D and L when present, the identity, cosign's version and the time; an entry older than 24 hours is verified again.
6. Refusal: the job is completed without launching: exit 13, `launcher_failure_code` `runtime_error`, `launcher_detail` `image_unverified`, zero usage, scratch discarded, and the log line `image_unverified job=<id> digest=<hex> reason=<word>` with reason one of `reference_refused`, `digest_mismatch`, `cosign_missing`, `cosign_failed`, `cosign_timeout`, `manifest_mismatch`, `layer_mismatch`.
7. Configuration: `verify_images` (default true) and `cosign_path` (an absolute path, checked like `python3`: the user's or root's, not writable by group or others, no link; required when `cosign` is not on `/usr/local/bin:/usr/bin:/bin`). `verify_images: false` is refused at start unless `api_base` is a loopback `http://` address (the local stack and CI's stand-in image). `sif_pull` defaults to true.
8. `doctor` gains `cosign` (found, version 3 or newer) and, when an image is present, `signature <hex>` (verified or not).
9. `codes.py` gains `image_unverified` in `runtime_error` and the platform set; the pin moves to C2W's merge commit.
10. Tests: offline (reference parsing, the config rules, cache expiry, the refusal completion, cosign absent, and a real stand-in executable for cosign that exits 1 or sleeps past the timeout); network-marked against the registry: the demo digest verifies, the same digest with a wrong identity regexp is refused, a tag reference is refused without running cosign; under Apptainer (CI has it), the SIF path for the demo digest succeeds and a corrupted file fails `layer_mismatch`.
11. `ci.yml`: the runner test job installs cosign through `sigstore/cosign-installer` pinned by commit SHA, with the cosign version pinned.
The implementer may choose: helper names and log wording beyond the line above.

## Stop conditions

- `apptainer pull` refuses an `oras://...@sha256:` reference (docs/images.md lists it as unverified): stop and report the error; do not fall back to a tag.
- cosign 3's output carries no manifest digest field to compare: stop and report the output's shape.
