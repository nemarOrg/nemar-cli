## Goal

`eegprep_lean.load_recording(...)` reads one whole recording from NEMAR's public Zarr serving copy, `eegprep_lean.to_eeg(window, ...)` turns it into an EEGLAB-compatible dictionary that `eegprep.eeg_checkset` accepts, and `eegprep_lean.to_mne_raw(window)` returns an `mne.io.RawArray`, all on eegprep-lean's existing reader, with no second reader and no change to eegprep's numerics.

## Context

Read `packages/eegprep-lean/src/eegprep_lean/` (`index.py`: `read_index`, `DatasetIndex`; `window.py`: `read_window`, `Window`; `channels.py`; `transport.py`, which sends a native User-Agent), `packages/eegprep-lean/tests/` (offline fixtures and the `network` marker), `src/eegprep/functions/popfunc/eeg_emptyset.py` (the key set to match), `eeg_checkset`, `.github/workflows/test.yml`.

## Decided design

Settled:
- `load_recording(dataset_id, store, *, group=None, max_bytes=2 * 1024**3, transport=None, index=None) -> Window`: synchronous (`asyncio.run` over `read_index` and `read_window`), the whole level-0 recording of the store's EEG group (or `group`), physical units, `ValueError` when channels times samples times 8 exceeds `max_bytes`, nothing written to disk.
- `index_sha256(dataset_id, *, transport=None, index_url=None) -> str`: SHA-256 of the exact index bytes read.
- `to_eeg(window, *, dataset_id, store, index_digest) -> dict`: the key set of eegprep's `eeg_emptyset()` (written out literally in eegprep-lean, which must not import eegprep), with `data` channels by samples float64 in microvolts (convert from `V`, `mV`, `uV`; refuse any other unit), `srate`, `nbchan`, `pnts`, `trials = 1`, `xmin = 0.0`, `xmax`, `times`, `chanlocs` as a list of `{"labels": label}`, `setname = "<dataset_id>/<store>"`, and `etc = {"nemar": {"dataset_id", "store", "index_sha256", "reader": "eegprep-lean@<version>"}}`.
- `to_mne_raw(window, *, ch_types=None) -> mne.io.RawArray`: volts, `sfreq` = `rate`, names = labels, `ch_types` default `"eeg"`; `mne` imported lazily with an `ImportError` that names the `mne` extra.
- The User-Agent stays eegprep-lean's native one, never `Python-urllib`.
The implementer may choose: helper names inside the new modules, test structure.
