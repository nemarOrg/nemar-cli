## Goal

A set of small Zarr stores in the serving copy's layout, with expectations computed from the arrays that were written (never by reading them back through a reader), lives in one place in nemar-cli, and the collaborator's TypeScript read core decodes every case to exactly the expected integers, physical values and store content digest, so eegprep-lean (R1b), EEGDash (R5) and any future conversion comparison are judged against the same oracle.

## Context

- Read the reader branch's `shared/zarr/` (`read.ts`, `window-samples.ts`, `sharding.ts`, `codecs/blosc.ts`, `interfaces.ts`: the `Fetcher` type), her fixture scripts `scripts/zarr/generate_mcp_test_fixture.py` and `scripts/zarr/zarr_python_reference.py` and the fixtures they wrote (`backend/test/fixtures/mcp/`), the converter `scripts/zarr/generate_zarr.py` (the layout: array metadata, sharding, codec, chunk shape, the `scale` and `offset` attributes, labels, unit, the dataset `index.json`), and `shared/contract/derivatives.ts` with its vectors (card V1).
- A case's expectation is computed by the generator from the integer array and metadata it writes, with NumPy and `hashlib`; the TypeScript test then reads the written store and must agree. Agreement of two programs that share no code is the point.
- Stores stay small: every fixture directory under 64 KiB.

## Decided design

Settled:
1. **Generator.** `uv run --no-project --with zarr==3.4.0 python scripts/zarr/make_conformance_fixtures.py --out shared/contract/zarr-conformance` writes the stores with the converter's array layout and attributes and records in `cases.json` the exact zarr, numcodecs and NumPy versions it ran with; `--check` regenerates into a temporary directory, refuses to run under other versions than the recorded ones (naming them, so the command can be rerun with `--with` pins), and fails unless every byte equals the committed tree.
2. **Cases** (`cases.json` gives each an id, the fixture path, the group, the request, and the expectations):
   - `single-shard`: 4 channels by 1,000 samples, rate 250.0, unit "µV", labels `Fp1 Fp2 C3 C4`; the whole group;
   - `multi-shard-partial`: 3 channels by 10,007 samples at 200.0 Hz, so the last chunk and shard are partial; requests: the whole group, samples 4,990 to 5,030 (across a chunk boundary), channels 1 and 2 only;
   - `fill-value`: one chunk object deliberately absent; its samples decode as the array's fill value and are reported as filled, never as data;
   - `two-groups`: groups `eeg` (2 channels) and `misc` (1 channel) in one store; the `eeg` group;
   - `no-unit-no-labels`: no unit and no labels;
   - `offsets`: scale `[0.03125, 0.1]`, offset `[-3000.5, 12.25]`.
3. **Expectations per request:** `shape`, `digital_sha256` (int16 little-endian, channel-major), `physical_sha256` (binary64 little-endian of `float64(digital) * scale + offset`, two roundings), `filled` (the filled sample ranges), `labels`, `unit`, `rate`; per whole group also `store_content_sha256` by V1 item 1; and the five vectors of V1 repeated by reference to `shared/contract/derivatives-vectors.json`.
4. **The TypeScript test** reads each fixture through her core with a file-backed `Fetcher` (or `Bun.serve` on 127.0.0.1 serving the fixture directory), checks every expectation, and computes `store_content_sha256` with `storeContentSha256` from `shared/contract/derivatives.ts` over the core's decoded physical window.
5. **The suite's identity** is the tree digest of `shared/contract/zarr-conformance/` (sorted `path NUL sha256 LF` lines, hashed, as nemar-process's vendoring script defines it), printed by `make_conformance_fixtures.py --digest`; every copy in another repository pins it.
The implementer may choose: helper names, the fixture store paths' spelling.

## Acceptance

- `uv run --no-project --with zarr==3.4.0 python scripts/zarr/make_conformance_fixtures.py --check` exits 0 (with `--with` pins added for the numcodecs and NumPy versions `cases.json` records, if the resolver picks others).
- `bun test test/zarr-conformance.test.ts` passes every case; a mutation that reads one sample past a partial chunk's end, and one that treats a missing chunk as zeros without reporting it filled, each fail it.
- Stock zarr-python opens every fixture store (`zarr.open_group` of each, the generator's `--check` does it) with no NEMAR code.
