## Decided design

Settled:
- M1 (the manager, before dispatch): `sha=$(gh pr view 2144 -R nemarOrg/nemar-cli --json headRefOid --jq .headRefOid)`, `git -C $NEMAR_CLI fetch origin "pull/2144/head"`, `git -C $NEMAR_CLI push origin "$sha:refs/heads/feature/issue-2144-epic-reader"`, then `gh api repos/nemarOrg/nemar-cli/branches/feature/issue-2144-epic-reader --jq .commit.sha` equals `$sha`. The manager adds a one-line comment on #2144 naming the branch and why (CI with secrets, her commits unchanged).
- W1: in the read-only worktree, `bun install --frozen-lockfile` (and in `backend/`), then `bun test test/zarr-*.test.ts backend/test/zarr-core-*.test.ts backend/test/zarr-index-v3.test.ts backend/test/zarr-window-samples.test.ts backend/test/blosc-decode.test.ts backend/test/mcp-*.test.ts test/contract-neuroschema-record.test.ts`, `bun run typecheck`, `bun run lint`; quote the last lines.
- W2: `gh run list -R nemarOrg/nemar-cli --branch feature/issue-2144-epic-reader --workflow Tests --limit 1 --json databaseId,conclusion,status,headSha`; never wait: report the state, and for a finished failing run, the failing jobs from `gh run view <id> --json jobs`.
- W3: the ADR, status proposed, titled "Every reader is held to one conformance suite, and a private read goes through the reader's own authorization", states with one-line reasons:
  1. D9: a job reads only what it needs into its own directory (mode 0700), deleted in a `finally` and swept at runner start; private bytes never enter a shared cache.
  2. D11: a public store stays readable by stock zarr-python or xarray with no NEMAR code; three readers (the TypeScript core of ADR 0120, eegprep-lean, EEGDash's own) are held to one conformance suite.
  3. The suite's cases, fixtures and goldens live in nemar-cli `shared/contract/zarr-conformance/` (card R1) and are copied byte for byte, with a pinned digest, into each reader's repository, as the launch-specification schema is.
  4. The suite includes the store content digest `nemar.store-content.v1` (card V1's ADR), so every reader computes the same digest of the same store.
  5. The suite is the comparison oracle for any conversion change: two conversions are compared by decoding through the suite's readers with a pre-registered tolerance, never by bytes or timestamps (CP-F finding A4).
  6. The design goal: one reader reads public and private data by the authorization the person or job holds, through an authorization-aware Fetcher behind the core's `Fetcher` interface (anonymous for public data; the person's own credential path on ADR 0114's listed origins for private data; a job-scoped read grant on a runner later, R4); no shared cache holds private bytes.
  7. Q9: runners read public data only until launcher-staged, no-network private jobs exist (R3, R4).
- W4: a findings file for the Opus reviewer listing where to look (the core's `Fetcher` and its `Authorization` refusal, the engine protocol and frames, `backend/src/mcp/*`, ADR 0120's numbering against 0121 and 0122, the two fixture ids above, and W1 and W2's results).
The implementer may choose: the ADR's prose.
