## Decided design

Settled:
1. **uv version.** Every `uv lock` runs with the version `UV_VERSION` names in `ci.yml` at dispatch (0.13.4 at the lead's reading), `uv --version` quoted; if the installed uv differs, run that version through `uvx --from 'uv==0.13.4' uv ...`.
2. **Commit 1, the pure re-lock** (`chore: re-lock uv.lock with uv 0.13.4`). On the unmodified base run `uv lock --upgrade-package eegprep-lean`: eegprep-lean is pinned by a full commit hash, so the upgrade cannot move it, and it forces the full resolution that a plain `uv lock` skips. Then item 4. If the base has moved and the command changes nothing but the version line, commit 1 is empty: skip it and say so in the report.
3. **Proof that commit 1 is pure** (each quoted in the PR body): (a) a scratch script (uncommitted, in your private folder) loads the base's and commit 1's `uv.lock` with `tomllib` and prints the (name, version, source) triples only in one of them and the entries whose sdist or wheel hashes differ: all three lists empty; (b) `uv sync --frozen --dry-run --python 3.12 --python-platform P --group runtime --extra F` with `UV_PROJECT_ENVIRONMENT` set to a scratch folder (and `MACOSX_DEPLOYMENT_TARGET=14.0` for macOS, since the torch wheels are macOS 14), run in a detached worktree of the base and at commit 1, prints the same sorted package lines for P `x86_64-manylinux_2_28` with F `cpu` and `cuda`, P `aarch64-manylinux_2_28` with both, P `aarch64-apple-darwin` with `cpu` (the CUDA flavor has no macOS wheel, so its dry run fails on base and head alike), and for the default `uv sync --frozen --dry-run`; (c) `uv lock --check` passes and a plain `uv lock` leaves the file byte-identical; (d) the same command run again from a clean copy of the base, with item 4 applied, gives a file that `cmp` finds identical to commit 1's.
   Marker text that changed is accepted as serialization because (a) and (b) show nothing installed differently on any platform checked.
4. **The version line is avoided, not accepted.** After each `uv lock`, put the root entry's (`name = "nemar-process"`, `source = { virtual = "." }`) version line back to the base's text, byte for byte, and nothing else by hand. Proof: `git diff origin/feature/runner-epic -- uv.lock` shows no version line, `uv run python scripts/bump_version.py --show HEAD` prints the base's version, and `uv run python scripts/bump_version.py --check-unchanged origin/feature/runner-epic HEAD` exits 0.
5. **Commit 2, the pin** (`chore: pin the cpu extra's torch to 2.12.1`). `cpu = ["torch==2.12.1"]`: a public version matches the CPU index's `2.12.1+cpu` on Linux and its plain `2.12.1` on macOS, as `cuda = ["torch==2.12.1"]` matches `2.12.1+cu129`; never `==2.12.1+cpu`, which the macOS wheel does not carry. The comment above the extras says both flavors pin torch 2.12.1, pamica 0.4.0's floor, the CUDA 12.9 build in one and the CPU build in the other, so both images and the tests run one torch version. Then a plain `uv lock` and item 4.

- Commit 2 moves any package other than the two CPU-index torch entries, the `cpu` dry runs differ in anything but torch and setuptools, the `cuda` or default dry runs differ at all, or a locked torch hash differs from the index's listed sha256: stop.
- `uv lock` drops setuptools 84.2.1 from the lock (the build constraint would name a version the lock does not hold): stop; moving the build constraint is a supply-chain change of its own.
- The floor's golden decisions change: stop (torch would have reached the floor's numerics, a recipe version question for the owner).
- The diff against the base would change a `version` field, a Dockerfile, the image workflow, `smoke.py` or any recipe code: stop.
