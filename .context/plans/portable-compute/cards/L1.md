## Goal

The launcher sends its container's session SIGTERM at `NEMAR_JOB_END_TIME` and SIGKILL after its grace even when nobody signals it, records `time_limit`, and starts the container child so that the kernel signals it when the launcher dies, so a dead runner and a dead launcher no longer orphan a running container.

## Context

- `launcher/nemar_launch/run.py`: `TIME_LIMIT_MARGIN` (120 s), `TERM_GRACE_SECONDS` (10 s), `terminated_failure`, the `Terminator`, and the child started with `subprocess.Popen(..., start_new_session=True, preexec_fn=_raise_oom_score)`; the wait loop polls every 0.2 s.
- `launcher/nemar_launch/settings.py`: `end_time` reads the SLURM end time or `NEMAR_JOB_END_TIME` (codes.py `ENV_RUNNER_END_TIME`).
- `docs/runner.md`, "When the runner dies", names what is not guaranteed today and defers it to L1: an abnormally killed launcher orphans its container (forever under Apptainer).
- The runner already starts the launcher with `PR_SET_PDEATHSIG` through `ctypes`; follow that code's style. The runner sends SIGTERM at the end time plus 60 s and SIGKILL 30 s later, so the launcher's own timer acts first.
- Under Docker and Podman the container child is the engine's client: SIGTERM to it is forwarded to the container (the client's signal proxy); SIGKILL to it leaves the container to the runner's labeled removal.
- Changing launcher code changes the launcher zip: re-record `launcher_sha256` in `deploy/tapis/apps/nemar-launch.json` with `scripts/build_launcher_zip.py`, exactly as DM-09 and DM-10 did; `deploy/tapis/released-versions.json` stays empty.

## Decided design

Settled:
1. Deadline: in the wait loop, when `end_time` is set and `time.time() >= end_time`, and no SIGTERM has been received, the launcher records the moment as received, sends SIGTERM to the container's session (`os.killpg(child.pid, signal.SIGTERM)`), and the existing grace then sends SIGKILL after `TERM_GRACE_SECONDS`; the failure is `time_limit` (the existing `terminated_failure` already classifies a stop within the margin of the end time that way). The log line: `deadline reached; stopping the container`.
2. Parent death: the child's `preexec_fn` also calls `prctl(PR_SET_PDEATHSIG, <signal>)` through `ctypes` on Linux, with SIGKILL when the runtime is Apptainer (the starter's death ends the container's namespace) and SIGTERM when it is Docker or Podman (the client forwards it to the container). Elsewhere, or when `prctl` fails, the launcher logs `pdeathsig_unavailable` once and goes on. After `prctl`, the child checks `os.getppid()` still equals the launcher's pid and exits 1 at once if not (the race where the parent died before `prctl`).
3. The container child is started from the launcher's main thread (PDEATHSIG fires when the creating thread exits); a test asserts the start happens on the main thread.
4. `docs/runner.md`: the guarantee and the residuals are restated: under Docker or Podman a client killed with SIGKILL still leaves its container to the runner's removal at job end or at the runner's next start; a process that calls `setsid` inside the container's namespace is still bounded by the container.
5. Tests (Linux; skipped elsewhere with a reason, and required in CI): with the stand-in runtime the existing launcher tests use (a real executable in `tests/launcher/`), a child that ignores SIGTERM and runs past an end time two seconds away is killed within the grace plus one second and the record says `time_limit`; a launcher killed with SIGKILL while its child runs leaves no child after two seconds (read `/proc`); the `getppid` race path exits 1.
The implementer may choose: the helper names.
