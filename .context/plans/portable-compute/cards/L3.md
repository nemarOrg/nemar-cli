## Goal

For a claimed job whose `resources.gpus` is above zero, the runner decides the device just before start: the GPU only when a conservative multi-sample check finds it idle and no one has reserved it, otherwise the CPU; it passes the decision, its reason and a GPU memory cap to the launcher, which gives the container exactly that GPU or none and tells the recipe through three launcher-owned variables.
A job never waits for, and never fails because of, a busy GPU.

## Context

- The owner (2026-11-14): the GPU is usually idle, but busy whenever developers work (a deadline now); developers hold GPU memory while their compute is quiet; the CPU is uncontested; a lab member must be able to reserve the GPU without asking anyone. So the GPU rule is conservative and the CPU is always the safe answer.
- Accounting stays honest by the ceiling rule: the Worker counted the job's `resources.gpus` against the registration (pool, cores, memory, GPUs); the runner may use fewer (the CPU) and never more. No route, field or failure word changes, and nemar-cli is untouched.
- Read L2's `availability.py` and the before-start point in `job.py`; `launcher/nemar_launch/runtime.py` (`--gpus <n>` when `job.gpus > 0`, `NVIDIA_VISIBLE_DEVICES=void` when it is 0), `run.py` (`--nv`, `cuda_visible_devices`), `settings.py` (how launcher variables are validated), `provenance.py`; `docs/launcher.md` (the pinned command lines).

## Decided design

Settled:
1. **Configuration.** An optional `gpu` object: `enabled` false by default (a host turns it on); `memory_fraction` 0.5 (the most of one GPU's memory a job may take); `headroom_mb` 2048; `max_used_mb` 1024 (memory others may hold on a GPU that still counts as idle, for example a desktop); `max_utilization_pct` 10; `samples` 6; `sample_seconds` 5. The tool is `nvidia-smi`, looked up only in the launch path's directories with the trusted-binary check the runner applies to `python3`; `Tuning.gpu_tool` overrides it in tests and is never read from the file. Reservations are read from L2's `reservation_dirs`.
2. **The idle check** of the GPU with index `i`, from `nvidia-smi --query-gpu=index,uuid,memory.total,memory.used,utilization.gpu --format=csv,noheader,nounits` and `nvidia-smi --query-compute-apps=gpu_uuid,pid,used_memory --format=csv,noheader,nounits`, each call with a 10 s timeout. Idle only if no entry named `gpu<i>` or `gpu-all` exists in a reservation directory (`os.lstat`, never followed or read; any type of entry counts), and in EVERY one of `samples` readings taken `sample_seconds` apart: no compute process lists that GPU, `memory.used <= max_used_mb`, `utilization.gpu <= max_utilization_pct`, and `memory.total - memory.used >= cap + headroom_mb`, where `cap = floor(memory_fraction * memory.total)`. A tool that is missing, times out, exits non-zero or prints anything unparseable gives `gpu_check_failed`.
3. **The decision**, just before start, after L2's before-start check passed (the GPU check never makes the runner decline or wait): `cuda` on the lowest-index idle GPU that no other job of this runner holds (a lock per GPU, released when the job ends), reason `gpu_idle`; otherwise `cpu` with the first failing reason in this order: `gpu_disabled`, `gpu_unsupported_runtime`, `gpu_reserved`, `gpu_check_failed`, `gpu_busy` (a process, memory or utilization rule failed in some sample), `gpu_memory_short`, `gpu_in_use` (held by this runner). A job with `gpus` 0 gets no decision and no variable. Logged `device_chosen` with the job id, the device and the reason.
4. **Runner to launcher.** `NEMAR_DEVICE` (`cpu` or `cuda`), `NEMAR_DEVICE_REASON` (a word of item 3), and for `cuda` also `NEMAR_GPU_ID` (the GPU's identifier as `nvidia-smi` prints it) and `NEMAR_GPU_MEMORY_MB` (the cap). The launcher validates them (fixed words, `^GPU-[0-9a-fA-F-]{36}$`, digits) and refuses as `runtime_error` `invalid_spec`: a malformed value, a `cuda` decision for a specification whose `resources.gpus` is 0, and a GPU id without `cuda`.
5. **Launcher, when a decision is present.** Docker: `cuda` passes `--gpus device=` followed by the GPU id in place of `--gpus <n>`; `cpu` passes no `--gpus` and sets `NVIDIA_VISIBLE_DEVICES=void`. Apptainer: `--nv` and `CUDA_VISIBLE_DEVICES` set to the GPU id only for `cuda`; neither for `cpu`. The container gets `NEMAR_DEVICE`, `NEMAR_DEVICE_REASON` and, for `cuda`, `NEMAR_GPU_MEMORY_MB`, beside `NEMAR_OUT` (launcher-owned; never from the specification). The launcher's provenance records the decision, the reason, the cap and the GPU's index (never a host name). With no decision present the command line is exactly today's.
6. **Visibility.** `nemar_runner gpu-check --config <path>` runs the idle check once and prints one line per GPU, `gpu<i>: idle` or `gpu<i>: busy reason=<word>`, with the counts per sample (no process id, no user name); `doctor` adds `gpu` (tool found, GPUs seen, reservations present).
7. **Tests.** The stand-in `nvidia-smi` (an executable script in the test's directory reading a scripted sample file) drives: all six samples idle gives `cuda` with the cap; a compute process in sample 4 only gives `cpu` `gpu_busy`; `memory.used` above `max_used_mb` in one sample (memory held by a quiet process) gives `gpu_busy`; utilization above the limit gives `gpu_busy`; free memory under cap plus headroom gives `gpu_memory_short`; a `gpu0` file, a `gpu-all` link and a `gpu0` directory each give `gpu_reserved`; a stand-in that sleeps past the timeout, one that exits 1 and one that prints garbage each give `gpu_check_failed`; two concurrent jobs of one runner get `cuda` and `cpu` `gpu_in_use`; a job with `gpus` 0 gets no variable. Launcher: the command line for each decision under Docker and Apptainer, the refusal of `cuda` with `resources.gpus` 0, and the unchanged command line with no decision. A real container run in CI (Docker, no GPU) of a tiny image that prints `NEMAR_DEVICE` shows `cpu` for a `cpu` decision.
The implementer may choose: helper names, how the scripted samples are encoded.
