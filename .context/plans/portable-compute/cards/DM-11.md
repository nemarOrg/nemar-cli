## Goal

`nemar-runner` exists with `doctor`, `once` and `run`: it exchanges its secret, claims a list of jobs, runs each through the launcher in its own scratch under Apptainer, Docker or Podman, heartbeats, enforces deadline and memory, completes with measured usage, and always deletes the job's scratch; its integration with NEMAR's real routes is DM-18's.

## Decided design

Settled:
- Configuration JSON at `$XDG_CONFIG_HOME/nemar-runner/config.json` (default `~/.config/...`): `api_base`, `secret_file`, `root`, `sif_root`, `runtime` (`apptainer`, `docker` or `podman`), `slots`, `arch`, `max_scratch_gb`; refuse to start if the config or secret file is readable by group or others, or `root` is not owned by the user.
- HTTP: `User-Agent: nemar-runner/<version>`; every request carries `protocol` where the contract says so; the access token is exchanged at start and 60 s before expiry, kept in memory, never logged.
- Claim: `run` polls every 15 s while a slot is free; `once` claims once and waits for its jobs; the answer's `jobs` list is run in parallel up to `slots`.
- Per job, under `<root>/jobs/<job id>/` (mode 0700): `out/`, `scratch/`, `home/`. Refuse to claim when free space under `root` is below `max_scratch_gb`.
- Image: Apptainer needs `<sif_root>/<hex>.sif`; if absent, `apptainer pull <sif_root>/.<hex>.sif.part oras://ghcr.io/nemarorg/nemar-python-sif:sha256-<hex>` then an atomic rename; a failed pull completes the job with `exit_number` 13, `launcher_failure_code` `runtime_error` and `launcher_detail` the launcher's image-missing word, without launching. Docker and Podman pull by digest inside the launcher.
- Launch: `python3 -I -S -c '<the runpy boot line of docs/launcher.md>' <launcher dir>` in a new process group, environment built from nothing but `NEMAR_LAUNCH_SPEC`, `NEMAR_SIF_ROOT`, `NEMAR_OUTPUT_DIR`, `NEMAR_SCRATCH_DIR`, `NEMAR_JOB_END_TIME` (claim time plus the job's minutes), `NEMAR_LEASE_ID`, `NEMAR_CONTAINER_RUNTIME`, `NEMAR_ENFORCE_LIMITS` (`1` only when `doctor` proved cgroup delegation with `apptainer exec --memory 64M --cpus 1`), `HOME=<job>/home`, `PATH=/usr/local/bin:/usr/bin:/bin`, `LANG=C.UTF-8`.
- Heartbeat thread: `started` after spawn, then every 60 s; phase `uploading` once `<job>/out/launcher/result.json` exists (confirm the path in `launcher/nemar_launch/`; use the real one and say so).
- Deadline and memory: SIGTERM to the process group at `NEMAR_JOB_END_TIME` plus 60 s, SIGKILL 30 s later; without enforced limits, a watchdog sums the resident memory of the process tree every 10 s and sends SIGTERM above the job's `memory_mb`.
- Cancel or `lease_lost`: SIGTERM, 30 s, SIGKILL; then complete (cancel) or stop without completing (lease lost).
- Usage: `os.wait4` gives wall, CPU (user plus system) and max resident memory; under Docker or Podman `usage_partial` is true and the log says `usage_partial runtime=<runtime>`.
- Discard: `shutil.rmtree` of the job directory in a `finally`, then `scratch_discarded job=<id> bytes=<n>`; at start, every leftover under `<root>/jobs/` is deleted and logged.
- Logs: JSON lines to `<root>/runner.log` and stderr; never a secret, token, presigned address or launch value.
- `doctor` prints yes or no for: config and secret permissions, runtime and version, `sif_root` writable, egress to `api_base`, token exchange, limits; exit 0 only if all but limits are yes.
The implementer may choose: module layout, threads or selectors, test helpers.

## Acceptance

- `uv run --no-project --python 3.9 --with pytest pytest tests/runner -q` passes: configuration and permission refusals; the exact environment key set; SIF naming and atomic rename; request bodies validated against the pinned schema; a real child process killed at its deadline, on cancel and on lease loss; the memory watchdog on a real child; cleanup after an exception; transport failures (timeout, 5xx, dropped connection) through HTTP fixtures only.
