## Goal

A CI job in nemar-process starts nemar-cli's local stack from a full checkout, and `nemar-runner once` takes one job to `finished` in a real Apptainer container built in the job, and another to `failed` with the image-missing detail, through NEMAR's real claim, heartbeat, outputs and complete routes.

## Context

- Read DM-11's runner, DM-08's stack (`serve`, `--seed-fixture`, `keys.json`), `.github/workflows/ci.yml` (today it checks out nemar-cli at the pin sparsely and runs `bun install --frozen-lockfile --ignore-scripts --production`, which is not enough to run the backend: the stack imports test helpers and Miniflare), `tests/contract/nemar-cli-pin.json`.
- The test workload is a tiny image built from `tests/images/tiny-recipe/`: the real launcher runs it under real Apptainer; it is a workload, not a stand-in for NEMAR, and the test says so.

## Scope

- New `tests/e2e/test_runner_stack.py`, `tests/images/tiny-recipe/Dockerfile` and its `nemar-recipe` script, a new job in `.github/workflows/ci.yml`, the pin file moved to a nemar-cli commit on `feature/portable-compute-epic` that contains DM-17.

## Decided design

Settled:
- Tiny image: `FROM docker.io/library/python:3.12-slim@sha256:b18b261e1b4974b4f321451ad5251ded85abb22c2b8b262da527dda1d031ab30`, plus an executable `/usr/local/bin/nemar-recipe` (Python, standard library) that accepts any arguments, writes `<--out>/summary.json` and exits 0.
- CI job `runner-stack` on `ubuntu-latest`: full (not sparse) checkout of nemar-cli at the pin into `.nemar-cli`; `bun install --frozen-lockfile --ignore-scripts` there (development dependencies included); install Apptainer as the existing CI does; `docker build -t tiny:ci tests/images/tiny-recipe`; `<hex>` from `docker inspect --format '{{.Id}}' tiny:ci`; `apptainer build <sif_root>/<hex>.sif docker-daemon://tiny:ci`; then `NEMAR_CLI_DIR=.nemar-cli NEMAR_REQUIRE_APPTAINER=1 uv run pytest tests/e2e/test_runner_stack.py -q -rs`.
- The test starts `bun $NEMAR_CLI_DIR/backend/scripts/compute-local-stack.ts serve --state <tmp> --port <free> --s3-port <free> --image localhost/tiny@sha256:<hex> --seed-fixture`, registers a runner and dispatches `nemar-floor-zarr` with `executor: "runner"` through the real admin routes with the stored keys, runs `nemar-runner once` with a config pointing at it, and asserts through the job record: `finished`, `executor` `runner`, usage set, `<root>/jobs/` empty, and `scratch_discarded` in the log. A second case with an empty `sif_root` and no registry access ends `failed` with the image-missing detail.
- Without Apptainer the test skips with reason "apptainer absent"; `NEMAR_REQUIRE_APPTAINER=1` turns that skip into a failure, so CI cannot pass by skipping.
The implementer may choose: fixtures and helper names.

## Acceptance
