## Goal

Before each claim, and again just before a claimed job starts, the runner reads the host's live free memory, load per CPU and free scratch, and claims (or starts) only when they leave room for the job and for the people who share the machine; a lab member can pause it with one file; every process it starts runs at the lowest CPU and I/O priority, and a Docker or Podman job gets the lowest CPU weight.
The Worker is unchanged.

## Context

- The owner (2026-11-14): the workstations are not dedicated to this work; other people's CPU use is rare (uncontested), memory can be contested, the GPU is often busy during deadlines. The GPU is card L3's, which builds on this card. So the CPU and load rule here is lenient by default and the memory and scratch rules are the meaningful ones.
- Read `runner/nemar_runner/agent.py` (`room_for_a_claim` already declines below `max_scratch_gb`; `claim_once`), `job.py` (`_launch`: a claim whose image outlasted `lease_abandon_seconds` is abandoned through `Outcome.abandoned`; the launcher `Popen` with `preexec_fn`), `config.py` (`CONFIG_KEYS`, `OPTIONAL_KEYS`, `Tuning`), `doctor.py`, `launcher/nemar_launch/runtime.py` (`build_argv`; the engine information it reads), `docs/runner.md`, `docs/launcher.md`, and the request-recording stand-ins of NEMAR's routes under `tests/runner/`.
- The Worker's claim fits pool, cores, memory and GPUs against the registration's static numbers (nemar-cli `backend/src/services/compute-runner-queue.ts` on `feature/portable-compute-epic`). An unstarted lease that expires releases the claim and counts it (three claims, then `claims_exhausted`). Not calling the claim route is the only decline the Worker never counts; this card changes no route.
- The launcher already gives a Docker or Podman container hard `--cpus` and `--memory` limits and `--oom-score-adj=1000` (under memory pressure the kernel ends the job before a person's process); those stay.
- A container started by the Docker daemon is not a descendant of the runner, so niceness and the I/O class do not reach it; Apptainer and rootless Podman containers are descendants and inherit both.
- No preemption in this version: a started job runs to its end, its deadline, a cancel or a revoke.

## Decided design

Settled:
1. **Configuration.** An optional `availability` object in `config.json`, its keys and defaults: `enabled` true; `max_load_per_core` 0.9 (the one-minute load average divided by the CPUs this process may run on: `len(os.sched_getaffinity(0))` where it exists, else `os.cpu_count()`); `reserve_memory_mb` the larger of 8192 and a tenth of `MemTotal` (memory always left to people); `claim_memory_mb` `default_job_memory_mb` when set, else 4096 (the operator sets it to the largest memory a claim can hand this runner, its registered memory); `backoff_seconds` 1800; `reservation_dirs` a list of absolute paths, default the `reservations` directory beside the configuration file (L3 reads the same directories). An unknown key inside the object is refused as the top level's are. Without the object the defaults apply, so a configuration written before this card keeps working, now with the live check.
2. **Readings (Linux).** `MemAvailable` and `MemTotal` from `/proc/meminfo`, the one-minute load from `os.getloadavg()`, free scratch from the existing `scratch.free_bytes`. A reading that cannot be taken counts as busy (`reason=memory_unknown` or `load_unknown`). The reader takes a `proc_root` argument (default `/proc`) that only tests set.
3. **Before each claim** (`room_for_a_claim`): idle only when free scratch is at least `max_scratch_gb` (today's check), `MemAvailable - reserve_memory_mb >= claim_memory_mb`, load per CPU is at most `max_load_per_core`, no backoff is in force, and no entry named `pause` exists in any reservation directory (`os.lstat`, never followed or read; a file, a link or a directory of that name all count). Otherwise no claim is sent: the runner logs `claim_skipped` with `reason` (`scratch`, `memory`, `load`, `paused`, `backoff`) and the readings, once each time the reason changes rather than on every poll, and polls again after `poll_seconds`.
4. **Just before the launcher starts** (in `_launch`, after the image step and before `Popen`): the same check with the job's own memory (`effective_memory_mb`, or `claim_memory_mb` under Apptainer when the claim carries none). While it fails, the runner re-checks every `poll_seconds` until it passes or until `lease_abandon_seconds` after the claim; then the job is abandoned exactly as an image pull that outlasted the lease is (`Outcome.abandoned`: no heartbeat was ever sent, nothing is completed, the lease expires and the Worker releases the claim, counting it), logged `claim_abandoned reason=<word>`, and the runner sets the backoff: no claim for `backoff_seconds`, so one busy host never spends a job's three claims in a row.
5. **Priority.** In `prepare`, the runner raises its own niceness to 19 (`os.nice` by the difference; never lowers it) and sets its I/O scheduling class to idle (`ioprio_set` through `ctypes` on Linux, or `/usr/bin/ionice -c 3 -p` with its own pid from the trusted path), so every child inherits both: the launcher, image pulls, and Apptainer and rootless Podman containers. A failure is logged `priority_unavailable` and does not stop the runner. Under Docker or Podman, `build_argv` adds `--cpu-shares 2` only when the engine reports that it can apply CPU shares (Docker's `docker info` field `CPUShares`; Podman: the `cpu` controller among its cgroup controllers), and otherwise says so in the launcher log. No `--blkio-weight` (Docker refuses to start a container where the kernel lacks it).
6. **Visibility.** `nemar_runner availability --config <path>` prints one line, `availability: idle` or `availability: busy reason=<word>`, with the readings (no secret, no path), and exits 0 or 1; `doctor` adds `availability` (the same verdict, informational) and `priority` (yes when niceness 19 and the idle class took effect).
7. **Tests, with real readings and real processes.** The parser against the real `/proc/meminfo` (skipped with a reason off Linux) and against `/proc`-style files the test writes; thresholds set relative to the real readings decide idle and busy; with a busy threshold, `run_once` sends zero claim requests to the request-recording stand-in and logs `claim_skipped` once; a `pause` file, and a link of that name, block claims; before start: the test makes the `/proc`-style memory file busy after the claim (with a short `lease_abandon_seconds` tuning), the job is abandoned with no `started` heartbeat and no completion, and a `claim_once` inside the backoff sends nothing; with the file made idle again during the wait, the job starts exactly once; priority: after `prepare`, a real child process reads its own niceness (`os.getpriority`) and I/O class and reports 19 and idle (Linux; skipped elsewhere with a reason); `build_argv` carries `--cpu-shares 2` when the engine information says CPU shares, and not otherwise.
The implementer may choose: helper names, the order of the log fields.
