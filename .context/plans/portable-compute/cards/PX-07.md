## Goal

nemar-process installs the signalJourney validator as `signalJourney==0.2.0` from PyPI, validates against the schema packaged in that wheel, and keeps a pinned tree digest of that packaged schema instead of a vendored copy, so a later upgrade that changes a schema byte fails a test until someone reviews it.

## Context

- signalJourney 0.2.0 (distribution `signalJourney`, import package `signaljourney_validator`, command `signaljourney-validate`): `Validator()` loads the packaged schema from `importlib.resources`, raises `SchemaResolutionError` at construction for an unresolved `$ref`, and logs on the logger `signaljourney_validator` instead of printing.
- Computed by the lead on 2026-11-14: the 37 files of the vendored copy (`recipes/nemar_process/_vendor/signalJourney/schema/`, recorded from commit 169c3261 with `tree-sha256: d7bde496b931555f858c77d84e75373e72c08fe536d3325b34c83ac3159428cb`) are byte-identical to the 37 files of `src/signaljourney_validator/schema/` at the tag v0.2.0, and the tree digest of that directory, by `scripts/vendor_signaljourney.py`'s `tree_sha256`, is the same `d7bde496...`. Verify it from the installed wheel; do not trust this line.
- The rename happens now, because the pin moves now (board log, PX-02 patch note): nemar-process names `signaljourney-validator` in `docs/upstream.md`, `docs/images.md`, `pyproject.toml` (the `signaljourney` group and `[tool.nemar-process.build-backends]`), `images/nemar-python/smoke.py`, `tests/images/test_dependencies.py`, `tests/images/test_smoke.py`.
- The dependency group keeps its name `signaljourney` (the demo brief and `docs/` run `uv run --group signaljourney ...`).
- eegprep-lean is still a git source, so the Dockerfile's builder keeps `git`; only its comment changes.

## Scope

- `pyproject.toml`, `uv.lock`, `recipes/nemar_process/sj.py`, `images/nemar-python/Dockerfile` (the builder's comment only), `images/nemar-python/smoke.py`, `docs/upstream.md`, `docs/images.md`, `scripts/vendor_signaljourney.py` (removed, or reduced to the `tree_sha256` helper the new test imports), `tests/images/test_sj.py`, `tests/images/test_dependencies.py`, `tests/images/test_smoke.py`, and the removal of `recipes/nemar_process/_vendor/signalJourney/`.
- Not the recipes' records, any `RECIPE_VERSION`, `ci.yml`'s jobs other than dropping an environment variable that only served the vendored-copy check (`NEMAR_SIGNALJOURNEY_DIR`, `NEMAR_REQUIRE_SIGNALJOURNEY`) if it exists there.

## Decided design

Settled:
1. The `signaljourney` group is `["signalJourney==0.2.0"]`; `signaljourney-validator` leaves `[tool.nemar-process.build-backends]` (a wheel needs no build); `uv lock`.
2. `sj.validator()` returns `Validator()` over the packaged schema, after checking that `tree_sha256(importlib.resources.files("signaljourney_validator") / "schema")` equals the constant `SIGNALJOURNEY_SCHEMA_TREE_SHA256 = "d7bde496b931555f858c77d84e75373e72c08fe536d3325b34c83ac3159428cb"` and that `get_supported_versions()` is not empty; either failure raises `RuntimeError` before any record is validated. The stdout capture goes (0.2.0 logs).
3. The vendored directory is deleted; `docs/upstream.md` says the schema comes from the release, names the constant and how to move it (install the new release, recompute, review the schema diff, change the constant in the same PR).
4. `smoke.py` maps `signaljourney_validator` to the distribution `signalJourney`.
The implementer may choose: whether `tree_sha256` moves into `sj.py` or stays in a script.

## Acceptance

- `uv run pytest tests/images -q` passes, including a test that fails when the constant is changed by one character, and the dependency test that now requires `signalJourney==0.2.0` from PyPI (no git source).
- `uv run --frozen --group runtime --extra cpu pytest tests/recipes -q` passes (every record still validates).
- `uv run --group signaljourney python scripts/validate_signaljourney.py tests/fixtures/sj/<a valid record in that directory>` exits 0, and exits non-zero on a record with `pipelineInfo` removed.

## Gates

## Stop conditions

- The installed wheel's schema tree digest is not `d7bde496...`: stop and report the differing files (a schema change needs review, not a new constant).
- Records stop validating under 0.2.0: stop and report the first error.
