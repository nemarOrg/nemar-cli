## Goal

## Scope

## Decided design

Settled (re-checked by the lead against P3's merged code before dispatch):
1. P3's admitter's every selection has `executor = 'tapis'` at top level; a source-search test (the pattern of the existing predicate-regex tests) fails any compute selection of `created` rows that names neither `executor = 'tapis'` nor `executor = 'runner'`.
2. The runner claim never sets or reads `admitted_at`; P3's admitter never sets or reads `runner_claimed_at`; a test drives both paths at once over one database with a Tapis job and a runner job waiting and asserts each was admitted only by its own path.
3. The tenant guard and every count P3 adds for the cluster's limits keep `accounting = 'su'`; a runner job never occupies a tenant slot (test).
4. `GET /admin/compute/status` and `nemar admin compute status` show `queue { tapis: { waiting, admitted }, runner: { waiting, claimed } }` with one vocabulary ("waiting", "admitted" or "claimed").
5. No new state; no column renamed; `runner_claimed_at` stays.
The implementer may choose: the test helpers.
