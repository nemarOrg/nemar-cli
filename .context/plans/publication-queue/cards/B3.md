## Goal

A publication request can carry a resubmission note of at most 2,000 characters.
The CLI asks for one when the dataset's previous request was denied, and administrators see it everywhere they see the request.

## Decided design

Settled:
- **Flag:** `nemar dataset publish request [--note <text> | --note-file <path>]`.
  When the last request for the dataset was denied and not withdrawn, and no note was given:
  - an interactive session prompts once, with the text "This dataset's last request was denied on (the denial date), by (an automated agent or an administrator). Tell the reviewer what changed, or why the decision was wrong (optional, Enter to skip)".
  - a non-interactive session prints that a note can be added, and proceeds.
- **Server validation:**
  - at most 2,000 characters after trimming;
  - control characters other than newline are refused;
  - empty becomes NULL.
- **Where the note appears:** in `admin repo publish show`, in the admin mail as a fenced, quoted block labeled "Depositor's note", and in the admin web detail JSON.
  It never appears in a mail to the depositor.
- **Request detail:** the request also records the id of the previous denied request, `previous_request_id`, in the same migration, so a reader can link the two.

The implementer may choose: the prompt mechanics within the existing CLI prompt helpers.
