## Goal

A depositor runs `nemar dataset screen <path>` on their own copy and gets the report the server's screen produces for the same commit.
It shows the same status, the same per-format counts, the same finding kinds with remedies and docs links, and the same scanner and reader versions.
It changes nothing.

## Decided design

Settled:
- **Builder:** use A1's `shared/identifier-report-builder.ts`; do not build a second one.
- **Usage:** `nemar dataset screen [path] [--json] [--committed]`.
  - The default reads the working tree.
  - `--committed` reads `HEAD`'s tree through `git cat-file`.
    For an annexed file it reads the annexed content when present locally.
    When the content is absent, the file is `partial` with reason `content-absent`; add the reason and its copy entry here.
  - The header line states which one was read, and the commit.
- **Output:**
  - the status line;
  - the per-format "Recordings read" line;
  - each finding kind with its count, statement, remedy and docs link;
  - companion and incomplete lines;
  - the "Not read" lines;
  - the scanner and reader versions.
  - No value from a header is ever printed: kinds and counts only, as on the server.
  - `--json` prints the report v2 object.
- **Exit codes:** 0 for `clean`, `dates-only` or `no-recordings`; 3 for `direct-identifiers`; 2 for everything else.
- **Non-mutating:** no network, no git writes, and no file writes outside the OS temp directory, which is cleaned up.
- **History:** history paths come from the local `git log --all --name-only`.
  Superseded recordings are read when their content is present, and are otherwise named in a "Not read" line.
- **Parity with CI:** the CI's collect path and this command call one function that builds the report from a `RangeSource` factory.
  A test runs both on the same fixture tree and compares the JSON, excluding source-specific fields.

The implementer may choose: the internal names and the help text, which follows `.rules/documentation.md`.
