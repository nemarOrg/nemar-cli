## Goal

The identifier screen reads recordings through a registry of format readers, with EDF/BDF as the first reader and no change in its verdicts.
The report states, for each format, how many files there were, how many were read completely, and how many failed or were read only partly.
Every finding kind, dataset status and incomplete reason carries a statement, a remedy and a docs anchor from one typed table.

## Decided design

Settled:
- **Range source.** `interface RangeSource { size: number; read(offset: number, length: number): Promise<Uint8Array> }`.
  It is implemented for a local file (CLI preflight), for the CI's S3 or Worker reads, and for an in-memory buffer (tests and ZIP entries).
  Every source counts its reads and bytes and refuses past `ReaderLimits` (`maxBytesPerFile` 8 MiB, `maxReadsPerFile` 2,000) with a closed `limit` error.
- **Reader.** `interface FormatReader { id: ReaderId; extensions: readonly string[]; companions?(path: string, siblings: ReadonlySet<string>): CompanionCheck; scan(src: RangeSource, path: string, limits: ReaderLimits): Promise<ReaderResult> }`.
  `ReaderResult` is `{ findings: Finding[]; coverage: "complete" | "partial"; incomplete?: IncompleteReason }`.
  `ReaderId` is a closed union, starting with `"edf"`.
  A thrown error becomes a read failure of that format; it is never a clean read.
- **Registry.** `READERS` is one exported array, and `readerFor(path)` picks by extension, longest match first.
  EDF/BDF moves in as the first reader; `scanEdfHeader` keeps its behavior.
  The golden test: every existing screen and preflight test passes unchanged, apart from report-shape fields this card adds.
- **Coverage.** `formatCoverage` returns `{ byReader: Record<ReaderId, number>; unscreened: Record<string, number> }`.
  An extension with a registered reader leaves `OTHER_RECORDING_EXTENSIONS`; the list keeps the rest.
- **Report v2.**
  - `REPORT_VERSION = 2` adds `read_by_format: Record<ReaderId, { files: number; read: number; partial: number; failed: number }>`, plus `companion_missing` counts.
  - v1 reports still parse, and stored ones render as before.
  - A new status, `partially-screened`, means some formats were read and others were not.
    New reports use it in place of `clean-edf-only-others-unscreened`, which stays parseable for stored reports.
    Both gate to `acknowledge`.
  - `clean` and `dates-only` need every recording file to have a reader and to have been read completely; the door enforces this from the counts.
  - `isComplete` and `classifyDataset` are generalized from EDF to every reader.
- **Copy table.** `shared/identifier-screen-copy.ts` exports `KIND_COPY: Record<FindingKind, Copy>`, `STATUS_COPY: Record<DatasetStatus, Copy>` and `INCOMPLETE_COPY: Record<IncompleteReason, Copy>`.
  `Copy = { statement; read; remedy; anchor }`.
  - The anchor is a slug under one constant `SCREEN_DOCS_URL`; A10 creates the page.
    Until then, set the constant to the existing docs page about the identifier screen, which you find through `https://docs.nemar.org/llms.txt`, so that `test/docs-links.unit.test.ts` stays green.
  - Each statement names no value, only kinds and counts.
  - Every existing user-visible screen sentence is moved here, and `describeScreen` and `identifierScreenLines` print from it.
- **Lines.**
  - "EDF/BDF headers read: x of y" becomes "Recordings read: EDF/BDF x of y; ..." for each reader with files.
  - A partial read or a failure is named with its count.
  - Each finding kind and status line is followed by its remedy line and its docs link.
- **Reproducibility.** The scanner id stays in the report.
  A `readers` map records each reader's version string (a constant in each reader, bumped when its rules change).

The implementer may choose: internal helper names, how a source tallies its reads, and how the copy table is split across files when it grows.
