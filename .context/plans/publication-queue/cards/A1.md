## Goal

The identifier screen reads recordings through a registry of format readers, with EDF/BDF as the first reader and no change in its verdicts.
The report states per format how many files were read completely, read only partly, failed, or were not read.
The Worker accepts the new report.
Every finding kind, status and incomplete reason prints a statement, a remedy and a docs link from one typed table.

## Decided design

Settled:
- **`RangeSource`:** `{ size: number; read(offset: number, length: number): Promise<Uint8Array> }`.
  - It is implemented for a local file, for the CI's S3/Worker reads, and for an in-memory buffer.
  - A shared wrapper adds a page cache: 64 KiB pages, adjacent reads coalesced, and a tally of reads and bytes.
  - It refuses past the reader's limits with a closed `limit` error.
- **`ReaderLimits`:**
  - It is declared per reader in the registry: `{ maxBytes, maxReads, maxInflatedBytes, timeMs }`.
  - The EDF reader keeps 256 bytes.
  - Defaults for readers this card does not build: 8 MiB, 2,000 reads, 256 MiB inflated, 60 s.
  - A per-dataset time budget is `ctx.limits.datasetTimeMs`, default 20 minutes.
    Past it, every remaining file is `partial` with reason `time`.
- **`FormatReader`:** `{ id: ReaderId; extensions: readonly string[]; limits: ReaderLimits; version: string; companions?: (path: string, siblings: ReadonlySet<string>) => CompanionCheck; scan(src: RangeSource, path: string, limits: ReaderLimits): Promise<ReaderResult> }`.
  - `CompanionCheck` is `{ claimed: string[]; missing: string[] }`, where both lists hold sibling paths.
  - Claimed companions leave `unscreened`; they count as part of their header's recording.
  - Missing ones are counted in `companion_missing` and make that recording `partial` with reason `companion-missing`.
  - Only a reader's declared companion pairing claims a file; a `.dat` with no header naming it stays unscreened.
- **`ReaderResult`:** `{ findings: Finding[]; coverage: "complete" | "partial"; incomplete?: IncompleteReason }`.
  A thrown error is a read failure of that format, never a clean read.
- **`ReaderId`** is a closed union: `edf`, `brainvision`, `nirx`, `snirf`, `hdf5`, `eeglab`, `homer-nirs`, `mat`, `zip`.
  - Only `edf` gets a reader in this card.
  - The door accepts every id now, so that later cards change no vocabulary.
  - The incomplete reasons are added now too, each with its copy entry: `limit`, `time`, `companion-missing`, `encrypted`, `corrupt`, `unsupported-version`, `unsupported-filter`, `unsupported-datatype`, `external-link`, `content-absent`.
- **Registry:** `READERS` is one array, and `readerFor(path)` picks the longest extension match.
  EDF/BDF moves in with its behavior unchanged.
- **Coverage:** `formatCoverage` returns `{ byReader: Partial<Record<ReaderId, number>>; unscreened: Record<string, number> }`.
  - An extension with a registered reader leaves `OTHER_RECORDING_EXTENSIONS`.
  - Inner archive keys have the form `zip:<ext>`, and the door's `FORMAT_KEY` accepts them.
- **Superseded recordings:** the history collection (`findSuperseded`) works for every registered reader's extensions, not only EDF.
  A recording replaced in a later commit is read in its old version too (ADR 0086).
- **Report v2:**
  - `REPORT_VERSION = 2` adds `read_by_format: Partial<Record<ReaderId, { files; read; partial; failed }>>`, `companion_missing`, and `readers: Partial<Record<ReaderId, string>>` (versions).
  - `checkStatus` branches on the version, and the v1 path stays verbatim.
  - In v2, `clean` and `dates-only` need every recording file to have a reader and to have been read completely.
  - `no-recordings` needs zero recording files of any format.
  - The new status `partially-screened` replaces `clean-edf-only-others-unscreened` in new reports; the old value still parses.
    Both gate to `acknowledge`, and no other state's gate changes.
- **Worker first:** the backend parses v1 and v2.
  The CI emitter writes v2 in the same change; risk R7 covers the deploy window, and D4 re-runs a screen caught in it.
- **Copy tables:** `shared/identifier-screen-copy.ts` exports `KIND_COPY`, `STATUS_COPY` and `INCOMPLETE_COPY`.
  - Each is a `Record` over its union of `Copy = { statement; read; remedy; anchor }`.
  - `SCREEN_DOCS_URL` is set to the existing docs page on the identifier screen (find it through `https://docs.nemar.org/llms.txt`), so that `test/docs-links.unit.test.ts` passes; A10 adds the anchored sections.
  - Statements name kinds and counts, never values.
  - Every existing user-visible screen sentence moves here, and `describeScreen` and `identifierScreenLines` print from these tables.
- **Lines:**
  - "Recordings read: EDF/BDF x of y; ..." for each reader with files, then partial and failed counts.
  - Each finding kind and status line is followed by its remedy line and docs link.
- **Shared builder:** `shared/identifier-report-builder.ts` builds the report from a `RangeSource` factory, a path list and the history paths.
  The CI path, the upload preflight and A9's command all call it.

The implementer may choose: helper names, cache internals, and the split of the copy file.
