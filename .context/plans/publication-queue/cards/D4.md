## Goal

An administrator re-screens many publication requests in one paced batch.
The batch sends no per-request admin mail and no requester mail.
One digest goes to the administrators when the batch ends.
Each request's stored result is the same as a single `screen` would produce.

## Context

- `nemar admin repo publish screen <dataset-id>` (`src/commands/admin-publish.ts`, about line 433) re-runs one request's screen.
  Its route, the dispatch, and the callback (`backend/src/routes/callbacks/identifier-screen.ts`) store the result, start the review (`startPublicationReviewForScreen`) and mail the administrators (`notifyAdminsOfScreen`, `backend/src/services/identifier-screen.ts`).
- ADR 0086 holds the mail rule.
  This card adds a batch exception: the per-request mail is replaced by a digest, and it is never dropped silently.
- The dev Worker shares about 609 real addresses (AGENTS.md).
  The digest goes to `getAdminEmailsForCategory`, which is production-only.
  Tests use the existing mail test seams; send no real mail.
- **Pacing:** each screen is one GitHub Actions run in `nemarDatasets/.github`.

## Scope

- `src/commands/admin-publish.ts`: a new `screen-batch` subcommand.
- The admin route for the screen, extended with a `batch_id`.

- `backend/src/routes/callbacks/identifier-screen.ts` and `backend/src/services/identifier-screen.ts`: skip the per-request mail when the request carries a batch id, and claim the digest when the last one reports.

- Tests.

## Decided design

Settled:
- **Usage:** `nemar admin repo publish screen-batch [--ids <file> | --status <requested|blocked> | --all-active] [--per-minute <n, default 4, max 10>] [--apply]`.
  - It is a dry run by default, printing the selection and its count.
  - `--apply` starts the batch.
  - The CLI paces the dispatch calls itself and prints progress.
  - Ctrl-C stops dispatching; started screens still report.
- **Batch rows:** a request in a batch carries the batch id until its screen reports.
  - The per-request admin mail and any requester mail on a block are skipped for it.
  - Everything else (the stored result, the gate, the review start) is unchanged.
- **The digest** is claimed atomically, once, when `reported` equals `total`, or by the existing sweep 2 hours after the last dispatch.
  It lists:
  - the counts by screen state, before and after;
  - the counts by finding kind;
  - the requests whose state changed;
  - the requests that did not report, by name.
- **Blocked requests** in the batch are screened, but their status is not changed.

The implementer may choose: names, the migration number (the next free one at the time), and the digest's layout.
