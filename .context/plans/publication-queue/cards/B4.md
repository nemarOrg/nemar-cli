## Goal

The publication review receives the dataset's metadata besides ADR 0102's root documents: enrichment, upstream registry records, the license lineage outcome, the screen's coverage counts, and the resubmission note.
It never receives data.
Every review stores and shows a reproducibility record.

## Context

- ADR 0102 §2 stays: no header value, identifier finding, finding kind or count, screen report, `.tsv` or recording ever reaches the model, and every byte is pre-send scanned (`ClearedText`).
  ADR 0139 decision 6 lists exactly what is added.
- The review script runs in the `nemarDatasets/.github` workflow `run-publication-review.yml`, from nemar-cli `main`:
  - `scripts/ci/publication-review.ts` makes the model call;
  - `scripts/ci/publication-review-prompt.ts` holds the prompt;
  - `shared/publication-review.ts` holds the inputs (lines 137-189), the questions, the findings and `verdictOf`.
  The Worker side is `backend/src/services/publication-review.ts`, which dispatches the run and stores the result.
- D1's `shared/license-lineage.ts` (merged into this branch first) resolves the lineage; call it from the script.
  The script has network access, and the cache is per run.
- Coverage counts come from the stored screen report, `read_by_format` in v2 or the v1 counts.
  The Worker puts counts only into the dispatch payload.
  The payload is visible in the run log (memory `actions-step-header-prints-payload-env`), so it holds nothing else.
- The enrichment is `.nemar/metadata.json` at the reviewed head.
  It is model-written, so it is fenced as untrusted, like the README.

## Decided design

Settled:
- **New inputs**, each one a fenced section with its own byte budget, pre-send scanned, and dropped with a recorded `text_withheld` part if the scan finds anything:
  - enrichment: 12k, only the fields `title`, `description`, `keywords`, `license`, `related_identifiers`, `funding_references`, `creators`;
  - registry records of the lineage sources: 8k, with title, creators, publisher, resource type, license and URL for each;
  - the lineage outcome code and its sources' normalized licenses: 2k;
  - coverage counts per format, as files, read, partial and failed: 1k;
  - the resubmission note: 2k.
- **A fifth question, `note_addresses_reasons`**, is asked only when a note exists.
  Its answer can lower the verdict to `action_required`, never to `fail`, and never to `pass` by itself.
  When there is no note it is `not_asked`, which does not count.
- **Lineage in the verdict:**
  - `needs_permission`, `share_alike_mismatch`, `redistribution_prohibited`, `source_is_publication` and `unresolved` become one new reason code, `license_lineage_unconfirmed` (class: unknown, clears with an override), with its copy.
  - `compatible_attribution` without `IsDerivedFrom` in `dataset_description.json` adds the finding `source_credit_missing` (concern).
- **Review record**, new columns: `head_sha` (exists), `scanner_id`, `reader_versions`, `resolver_version`, `models` (JSON of model id and effort per call), `prompt_version`, `input_digest` (SHA-256 of the exact fenced input).
  These are shown by `admin repo publish show` and in the depositor-visible status.
- **Prompt version:** bump the prompt version constant, and keep the calibration scripts' fixtures working.

The implementer may choose: the section order in the prompt, and the budget split within the stated totals.

## Lead ruling, 2026-11-25 (after the first stop)

The workflow `run-publication-review.yml` is not changed.
The Worker owns the widened inputs and serves them through one new endpoint, combining options B and C of the stop report:

- **Route:** `POST /publication-review-inputs`, next to `/publication-review-claim` and `/publication-review-result` in `backend/src/routes/callbacks/publication-review.ts` (in Scope now).
  It is authenticated exactly as the claim and result routes are, by the review's own callback token and nonce.
  It answers only while that review row is claimed and not yet reported; otherwise it returns 409.
  It is read-only, and it returns data for that one request.
- **Body returned:**
  - `enrichment`: the seven fields, read from `datasets.enrichment_json`, with its stored commit or its update instant as `enrichment_source`;
  - `lineage`: the full `resolveLicenseLineage` result, computed by the Worker with its KV cache, from the description at the reviewed head (fetched by the Worker as the admin lineage route does) plus `attestation_upstream_source`;
  - `resubmission_note`;
  - `coverage`: the per-format counts from the stored screen report, v1 or v2 (define the narrow v2 shape locally).
  The payload of the dispatch stays as it is.
- **The script** calls the endpoint after the claim and before the pre-send.
  Every text field goes through the same pre-send scan and untrusted fence.
  Nothing it returns is logged.
  When the call fails, or answers anything other than 200, the review reports a closed run error, `inputs_unavailable`; it never proceeds with partial inputs.
  Add the error, its copy and its class (not a verdict, never eligible for an automatic deny).
- **Lineage reasons:** `needs_permission`, `share_alike_mismatch`, `redistribution_prohibited`, `source_is_publication` and `unresolved` all map to `license_lineage_unconfirmed`.
  ADR 0139 decision 7 is amended to match.
  Append to that ADR a dated amendment section: "Amendment 2026-11-25 (lead, epic #2182): decision 7 also covers the lineage outcomes `redistribution_prohibited` and `source_is_publication`, which the license-lineage resolver added after this ADR was written; each needs action and never denies automatically."
  Update the index line too.
- **Scope additions:** `backend/src/routes/callbacks/publication-review.ts`, `backend/src/services/github/dispatch.ts` (only if needed), the ADR 0139 file and its index line.
