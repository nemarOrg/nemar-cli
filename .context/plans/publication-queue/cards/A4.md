## Goal

`.snirf` files are screened with SNIRF semantics, and `.h5` and `.hdf5` files with a generic string scan.
Both run through A3's reader under A1's registry.
This takes up to 204 queued datasets out of "recordings NOT screened".

## Context

- The SNIRF specification v1.1 is at https://github.com/fNIRS/snirf/blob/master/snirf_specification.md.
  The fields that carry text are:
  - `/formatVersion`;
  - `/nirs{i}/metaDataTags/` with `SubjectID`, `MeasurementDate`, `MeasurementTime`, `LengthUnit` and `TimeUnit`, plus any user tag;
  - `/nirs{i}/probe/` with `sourceLabels`, `detectorLabels` and `landmarkLabels`;
  - `/nirs{i}/stim{k}/name`;
  - `/nirs{i}/aux{k}/name`.
- A file can hold several `nirs{i}` groups; screen every one.
- The `/nirs{i}/data{j}/dataTimeSeries` signal is never read; A3 skips it by size.
- `.nwb` stays unscreened, with its own later card.
- Use A3's `shared/hdf5-meta.ts`, A1's `RangeSource` and registry, the copy table, and the existing text rules in `shared/identifier-scan.ts`.

## Scope

New `shared/readers/snirf.ts` and `shared/readers/hdf5-generic.ts`, their registration, new finding kinds with their `KIND_COPY` entries, tests, and fixtures that reuse A3's SNIRF fixtures plus any new ones.

## Decided design

Settled:
- **`SubjectID`:**
  - No finding when the value equals the BIDS subject label of the file's path, or is a short code: letters and digits of length 12 or less that the name-like test does not flag.
  - `snirf-subject-name` (identifier) when the value is name-like.
  - Otherwise `snirf-subject-freetext` (review).
- **`MeasurementDate` finer than year and month:** `snirf-measurement-date`, a date kind under ADR 0090 policy B.
  It never gates on its own.
- **Any other string attribute or dataset** goes through the existing free-text rules (name-like, local path, email or phone shape if the module has them).
  A hit is `hdf5-freetext` (review), or `hdf5-freetext-name` (identifier) only when it is name-like in a field whose name contains `name`, `subject`, `patient`, `operator` or `experimenter`.
- **Probe, stim and aux labels** are scanned with the same rules; labels such as `S1`, `D3` or `Nz` never fire.
- **Generic HDF5** (`.h5`, `.hdf5`) applies the free-text rules to every string value.
  It counts as read under reader `hdf5`, separately from `snirf`.
- **A3 returning `complete: false`** makes the file `partial`.
  This card owns the one mapping from A3's `Hdf5Incomplete` to A1's incomplete reasons, in `shared/readers/hdf5-incomplete.ts`; A5 imports it.

The implementer may choose: the short-code length (between 8 and 16, stated in the PR), and the helper structure.

## Acceptance

- **False-positive gate (owner rule).**
  Run the reader over at least 200 public files of its format.
  Get them from OpenNeuro's public bucket (`aws s3 cp --no-sign-request s3://openneuro.org/<ds>/...`, headers or metadata only where the format allows a ranged read) or from PhysioNet open data.
  Report the findings per kind per 100 files in the PR.
  - Identifier-severity findings must be 0, or each one is explained without its value.
  - Review-severity findings must be at most 5 per 100 files.
  - The script is `scripts/dev/reader-fp-measure.ts` (shared; create it if absent).
  - The downloaded files stay in the OS temp directory and are deleted afterwards.

- `bun test test/readers-snirf.test.ts test/readers-hdf5-generic.test.ts test/identifier-fleet.test.ts` passes.
- **Multiple groups:** a fixture with at least two `nirs` groups shows findings from both.
  Build it from a real file by copying the group with the A3 oracle script's writer, and record that in the README.
- **Kinds fire:** a copy of a real fixture with `SubjectID` set to a made-up name fires `snirf-subject-name`.
  A real fixture with a coded `SubjectID` fires nothing.
- **Signals are not read:** no read range overlaps any `dataTimeSeries` data region, and the bytes read for each fixture are at most 512 KiB.
- A truncated SNIRF is `partial`, never `clean`.
- A revert check per new rule.
