## Goal

A dependency-free TypeScript module lists every group, dataset and attribute of an HDF5 file through random-access reads, and returns string values and small scalars.
It never reads a large numeric dataset.
Its output on real files equals h5py's on the same files.

## Context

- SNIRF and MATLAB v7.3 (EEGLAB `.set` v7.3, `.mat` v7.3) are HDF5; cards A4 and A5 build on this module.
- The module runs inside the screen workflow next to storage credentials, so it must be pure TypeScript with no npm dependency (owner decision 2026-11-25).
- Input is untrusted: every structure is bounded and checked.
  An offset outside the file, a cycle, a size over a limit, or an unsupported version is a closed error, never a hang or an unbounded allocation.
- The HDF5 file format specification, version 3.0, is the reference (https://docs.hdfgroup.org/hdf5/develop/_f_m_t3.html).
- A1 defines `RangeSource`.
  If A1 has not merged, define the same interface locally in this module: `{ size: number; read(offset: number, length: number): Promise<Uint8Array> }`.
  Note it in the report, and A4 will import A1's.
- MATLAB v7.3 files carry a 512-byte user block; find the superblock signature at 0, 512, 1024 and so on, as the spec says.

## Scope

A new `shared/hdf5-meta.ts` (split into `shared/hdf5/` if it passes about 1,200 lines), `test/hdf5-meta.test.ts`, `test/fixtures/hdf5/` (files plus a README.md with each file's source, license and size), and a dev-only oracle script `scripts/dev/hdf5-oracle.py`, run with `uv run --with h5py`.
Nothing else.

## Decided design

Settled:
- **Supported structures:**
  - superblock versions 0, 1, 2 and 3;
  - object header versions 1 and 2, with continuation blocks;
  - old-style groups (symbol table message, v1 B-tree, local heap);
  - new-style groups with compact link messages and dense links (fractal heap with direct and indirect blocks, and the v2 B-tree name index);
  - attribute messages, compact and dense, including the attribute info message;
  - datatypes: fixed and variable-length strings (global heap), integers, floats, enums, and arrays of strings;
  - dataspaces: scalar and simple;
  - layouts: compact and contiguous, and chunked with filters deflate (1) and shuffle (2) only, inflated with `DecompressionStream("deflate")`.
- **Values:**
  - a string value of at most 64 KiB is returned;
  - a numeric dataset or attribute with at most 64 elements is returned as numbers;
  - anything larger is listed with its shape and type and `value: null, skipped: "size"`;
  - a dataset whose type is not a string is never read past 64 elements.
- **Output:** `{ entries: Hdf5Entry[]; complete: boolean; incomplete?: Hdf5Incomplete }`.
  - `Hdf5Entry = { path; kind: "group" | "dataset" | "attribute"; name; dtype; shape; value: string | number[] | null; skipped? }`.
  - `Hdf5Incomplete` is a closed union: `limit-bytes`, `limit-reads`, `limit-objects`, `limit-depth`, `unsupported-version`, `unsupported-filter`, `unsupported-datatype`, `external-link`, `corrupt`.
  - An unsupported construct is skipped and recorded, the walk continues, and `complete` is `false`.
- **Limits:** 20,000 objects, depth 32, 8 MiB total bytes read, 2,000 reads.
  Each object address is visited once, which also detects cycles.
- **External links and external storage** are never followed; they are recorded as `external-link`.
- **Oracle:** `scripts/dev/hdf5-oracle.py <file>` prints the same entry list as sorted JSON from h5py.
  The test compares the TypeScript output with a committed oracle JSON for every fixture.
  CI does not need Python.

The implementer may choose: the internal parsing structure, and the file split.

## Acceptance

- **Fixtures:** at least five real files, totaling at most 6 MiB, with sources and licenses recorded.
  - (1) A real SNIRF recording from a public, permissively licensed source; an MNE testing-data SNIRF or an OpenNeuro CC0 fNIRS dataset are examples.
  - (2) A second SNIRF from a different writer: a NIRx, Kernel or Homer3 export.
  - (3) A real MATLAB v7.3 EEGLAB `.set` from a public CC0 or BSD source.
  - (4) A file written by h5py 3.x with `libver="latest"` and more than 8 links in one group, so dense storage is exercised.
    Generate it with the oracle script, and note that the format is real but the content is not a recording.
  - (5) A chunked, deflate-compressed string dataset.
- `bun test test/hdf5-meta.test.ts` passes, and for every fixture the entry list equals its oracle JSON.
- **Bounds tests:**
  - truncating a fixture to half its size gives `complete: false` with reason `corrupt`, without throwing;
  - setting the byte limit to 4 KiB gives `limit-bytes`;
  - a crafted self-referencing group address terminates with `limit-objects` or a visited-once skip.
- **Signals are not read:** on the SNIRF fixture, the bytes read are less than 5 percent of the file size.
  Assert the count from the source's tally.
