## Goal

BrainVision (`.vhdr`, `.vmrk`, with the `.eeg` companion) and NIRx (`.hdr`, `.inf`, with `.wl1`, `.wl2`, `.dat` and `.evt` as companions) are read by registered readers.
This takes 86 and about 20 queued datasets out of "recordings NOT screened".

## Context

- Use the A1 registry, `FormatReader`, `RangeSource`, the copy table and report v2 on the epic branch.
- **BrainVision** `.vhdr` and `.vmrk` are INI-like text.
  - Encoding: UTF-8, or the `Codepage` the file declares.
  - Sections that carry text:
    - `[Common Infos]` with `DataFile`, `MarkerFile` and `Codepage`;
    - `[Comment]`, free text that often holds amplifier setup and sometimes a name;
    - `[Channel Infos]`, the labels.
  - In `.vmrk`, `[Marker Infos]` lines can include `New Segment` with a timestamp of the form `YYYYMMDDhhmmssuuuuuu`.
- **NIRx** `.hdr` holds `[GeneralInfo]` with `FileName`, `Date` and `Time`.
  NIRx `.inf` holds `[Subject Demographics]` with `Name=`, `Age=` and `Gender=`, which can be a direct identifier.
- Reuse the existing text rules in `shared/identifier-scan.ts` (`shapeOf`, the name-like test, the local-path rule, the acquisition-date rules) rather than writing new ones.

## Scope

New `shared/readers/brainvision.ts` and `shared/readers/nirx.ts`, registration in `shared/identifier-readers.ts`, new finding kinds with their `KIND_COPY` entries, and tests and fixtures under `test/`.

## Decided design

Settled:
- **What is read:** each header file is read whole, up to 1 MiB; past that the read is `partial` with reason `limit`.
  `.eeg`, `.wl1`, `.wl2`, `.dat` and `.evt` are never read; they count as companions of their header.
- **Companions:**
  - The `.vhdr` `DataFile` and `MarkerFile` must resolve to a sibling in the same directory, with no `..`, no absolute path and no other directory.
    A miss is `companion_missing`, which is not a finding.
  - An absolute or user path in those fields is a `local-user-path` finding.
- **New finding kinds** (each with its copy entry):
  - `brainvision-comment-name`: review, never identifier.
    It fires on a name-like token in `[Comment]`.
    Free text there that is not name-like (amplifier setup, software names) fires nothing, because Recorder always writes that section.
  - `brainvision-segment-date`: a date kind under ADR 0090; a timestamp finer than year and month.
  - `nirx-subject-name`: identifier, but only when `Name=` is non-empty, name-like, and differs from the BIDS subject label of the path.
  - `nirx-demographics`: review.
    It fires only for a birth date, or for an `Age=` whose value is not empty, `0` or a default.
  - `nirx-header-date`: a date kind.
- `.dat` is a companion only when an `.hdr` in the same directory names it, or shares its basename; any other `.dat` stays unscreened.
- **Coverage:** a `.vhdr` with all its companions present counts as one BrainVision recording read.
  An orphan `.eeg` or `.vmrk` counts as unscreened under its extension.

The implementer may choose: the INI parser's internals, and how the codepage is detected.

## Acceptance

- **False-positive gate (owner rule).**
  Run the reader over at least 200 public files of its format.
  Get them from OpenNeuro's public bucket (`aws s3 cp --no-sign-request s3://openneuro.org/<ds>/...`, headers or metadata only where the format allows a ranged read) or from PhysioNet open data.
  Report the findings per kind per 100 files in the PR.
  - Identifier-severity findings must be 0, or each one is explained without its value.
  - Review-severity findings must be at most 5 per 100 files.
  - The script is `scripts/dev/reader-fp-measure.ts` (shared; create it if absent).
  - The downloaded files stay in the OS temp directory and are deleted afterwards.

- **Fixtures:** real public BrainVision and NIRx headers, with provenance and license in the README.
  - The MNE testing data and the BrainVision example files are BSD or CC0; any CC0 dataset on OpenNeuro also works.
  - Only header files are needed, not signals.
  - Add one fixture whose `[Comment]` and `Name=` fields are edited to hold a made-up name.
    Record that edit in the README.
- `bun test test/readers-brainvision.test.ts test/readers-nirx.test.ts test/identifier-fleet.test.ts` passes.
  - Each new kind fires on its fixture.
  - A clean real header gives no finding.
  - A missing companion gives `companion_missing` and not `clean`.
- A revert check per new rule: comment out the rule's line, show the test failing, and restore it.
