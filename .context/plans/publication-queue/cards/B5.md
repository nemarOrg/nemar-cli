## Goal

## Decided design

Settled:
- **Eligibility,** one pure function in `shared/publication-auto-deny.ts`.
  The first-run review is eligible when all of these hold:
  - the derived verdict is `fail`;
  - its reasons include `steering_attempt`, or `question_failed` with at least one model finding of severity `blocker` whose code is in `AUTO_DENY_FINDING_CODES`:
    `readme_missing_or_stub`, `description_incomplete`, `ethics_statement_missing`, `authors_placeholder`, `license_missing`, `license_inconsistent`, `name_not_descriptive`;
  - the run completed and parsed;
  - the review is the current one for the request's head and anonymous flag;
  - the request is `requested`;
  - `anonymous` is 0;
  - the dataset has fewer than 2 earlier requests with `auto_denied = 1`.
  `license_lineage_unconfirmed`, every screen reason, every infrastructure reason and `source_license_conflict` are never eligible.
- **Confirmation:** when eligible and the mode is not `off`, the Worker dispatches a confirming run with model `claude-sonnet-5-5`, effort max, over the same input digest, as a new review row with `confirm_of` set.
  On its callback:
  - It confirms when it is also eligible and shares at least one eligible code (finding codes, or `steering_attempt`).
    It disagrees otherwise, and the request goes to the administrators as today, with "automated review disagreed".
- **Mode:** `PUBLICATION_AUTO_DENY_MODE` is `off`, `shadow` or `on`; anything else, absent included, is `off`.
  The daily cap is `PUBLICATION_AUTO_DENY_DAILY_CAP` (default 25).
  It is claimed atomically before a deny or a would-deny is recorded; past the cap the state is `capped`, and the administrators' mail says "recommended: deny".
- **Deny** (mode `on`): the shared deny function, called with `denied_by` set to nemarAdmin's id and `denied_reason` set to the eligible codes joined.
  - The request gets `auto_denied = 1`, and an audit row `auto_deny` records the two review ids, the head, the models, the prompt version and the digest.
  - The UPDATE is guarded on `status = 'requested'` and on no approval being in flight; a lost race records `not_eligible`.
- **Shadow:** everything except the deny.
  `would_deny` is recorded and included in the daily digest.
- **Depositor mail** (on deny), every sentence from the copy table:
  - "An automated agent reviewed this request and denied it";
  - each reason with its remedy and docs link;
  - the reproduce commands (`nemar dataset screen --committed`, `nemar dataset license-check`);
  - the review record;
  - "a model's verdict may differ on another run; the inputs are what you can check";
  - how to resubmit with `--note`;
  - "reply to this mail to reach a person".
  It goes to the requester and every owner.
  It never includes model-written text, README text or finding values.
- **Daily admin digest** of `denied`, `would_deny`, `capped` and `disagreed`, sent once a day by an atomic claim.
  It is production-only, through `getAdminEmailsForCategory`.
- **Restore:** `POST /admin/publish/:id/restore` sets a denied request back to `requested` when no newer request exists, and writes an audit row.
- **Pass mail:** a `pass` with screen gate `clear` uses the headline "Ready to approve" and lists the gate, the minimums, the lineage outcome with its sources, the four answers and the exact approve command.
  A `pass` with gate `acknowledge` says "Review passed; the identifier screen still needs an acknowledgment" and quotes the screen's status line.

The implementer may choose: the module layout, and the digest's layout.
