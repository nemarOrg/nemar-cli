## Goal

An administrator acknowledges, in one documented act, the identifier screens of every queued request that is a conversion of a public, redistributable upstream dataset.
The acknowledgment covers only unread formats and image or document files.
Each acknowledgment records a reason that names the upstream, its license and its evidence, and links to a published policy section.
Everything else stays for individual review.

## Decided design

Settled:
- **A request is eligible when all of these hold:**
  - status `requested`;
  - a stored screen for the current head;
  - screen state `not-screened`, `partially-screened`, `clean-edf-only-others-unscreened`, or `review` whose only finding kinds are `image-or-document-file` and `tooling-debris`;
  - no acknowledgment already recorded;
  - lineage outcome `compatible`, `compatible_attribution` or `compatible_nc`, with at least one source whose resolver read it from the source's own record (`datacite`, `openneuro` or `physionet`);
  - the request is not in the excluded list.
- **Not eligible, ever:** any screen with another finding kind (a content finding such as `local-user-path`, an EDF header kind, `json-identifier-key`, `acq-time-dated`, `path-subject-label`), `direct-identifiers`, `unchecked`, `error`, or a stale screen.
- **Excluded list:** the requests D2 found holding a file of name class `photo`/`face` or `questionnaire`.
  D2's JSON lists them by dataset id; read them from it at run time, and never hard-code them.
- **The recorded reason**, built from the copy table and kept within 500 characters:
  `public-upstream: same recordings as <first source id> (<license>, read from <resolver>); not read by NEMAR: <unscreened formats, comma-separated>; images/documents acknowledged; policy <docs URL>#public-upstream-acknowledgment`.
  - When there are several sources, the first is named and the rest are counted ("+2 more").
  - The full lineage result is stored in the audit row's details.
- **The act is the caller's own:**
  - the route records with the calling administrator's id, conditional on the state it read;
  - it prints a per-request outcome (`acknowledged`, `not_eligible:<reason>`, `state_moved`);
  - the CLI prints the dry run first and needs `--apply` to record;
  - a batch is capped at 100 requests per call (the CLI pages through larger selections).
- **Selection:** `--all-requested` or `--ids <file>`.
- **ADR 0086 amendment text** (append as written, dated 2026-11-25):
  "An administrator may acknowledge many screens in one act when each request is a conversion of a public, redistributable upstream dataset whose license NEMAR read from the source's own record. Such an acknowledgment covers only formats the scanner does not read and image or document files; a content finding, a direct identifier, an unchecked or stale screen, or a request holding a photo or questionnaire file is never acknowledged this way. Each acknowledgment records a reason naming the upstream, its license and the unread formats, and is the calling administrator's own act. The weekly re-screen (ADR 0088) reads these datasets again as readers are added."
- **Policy section text:** a new copy entry `public-upstream-acknowledgment`.
  A10 publishes it on the docs page.

The implementer may choose: the module structure, and the page size of the dry-run output.
