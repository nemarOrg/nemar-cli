Issue 1 title: `Initial mixture locations differ from the reference when n_mix is not 3`

```text
The reference starts each source's mixture locations at mu(j,k) = j - 1 - (num_mix - 1)/2 (pamica/amica15.f90:750), plus jitter unless fix_init is set.
All three array backends start them at numpy.linspace(-1, 1, n_mix) plus jitter (torch_impl/core.py:1220, numpy_impl/core.py:1794, mlx_impl/core.py:1146).
The two agree only for n_mix = 3 (-1, 0, 1). For n_mix = 2 the reference uses -0.5 and 0.5 and pamica -1 and 1; for n_mix = 4 the reference uses -1.5, -0.5, 0.5, 1.5 and pamica -1, -1/3, 1/3, 1.
The difference is not recorded in docs/guides/amica-differences.md.
Shared-start comparisons through AMICANative(start="pamica") are not affected, because the binary loads pamica's own locations.
Options: port the reference's formula (default starts for n_mix other than 3 change, which needs a changelog warning and an ADR), or record the divergence with the reason and how to restore the reference.
Found while planning same-seed parity (epic #EPIC).
```

Issue 2 title: `fix_init is not ported to the array backends`

```text
The reference's fix_init 1 starts every model from A = I, the mixture locations at their fixed centers and sbeta = 1, with no random draw for them (pamica/amica15.f90:753-771 and 805-810; the restart after an early non-finite likelihood redraws the same way, 1027-1031).
pamica: pamica.initialization.initial_mixing(fix_init=...) exists; the NumPy backend honors an undocumented fix_init attribute (numpy_impl/core.py:1761, 1795, 1803); the PyTorch and MLX backends have no parameter; pamica/fortran_params.py lists fix_init as not ported.
Same-start comparisons with the binary no longer need it: AMICANative(start="pamica") loads pamica's seeded start into the binary (PA-02 PR).
Porting it is a reference-feature gap, not a parity blocker, and depends on the mixture-location issue for n_mix other than 3.
Found while planning same-seed parity (epic #EPIC).
```

Issue 3 title: `Shared start for the native engine needs full rank`

```text
AMICANative(start="pamica") refuses a rank-reduced fit (pcakeep below the channel count, or rank-deficient data): the error text.
The binary computes its own sphere because its load_sphere path crashes (see pamica/tests/native_oracle.py), so a reduced basis cannot be handed to it the way the full-rank start is.
A same-seed comparison on average-referenced recordings, whose rank is the channel count minus one, needs this; NEMAR's ICA recipe records such fits.
Possible routes: reduce the data before the binary sees it and seed in the reduced space, or fix the reference's load_sphere path in pamica's maintained amica15.f90.
Found while planning same-seed parity (epic #EPIC).
```
