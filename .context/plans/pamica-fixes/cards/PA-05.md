## Goal

`AMICA.did_converge_` is true exactly when the last fit stopped on one of the reference's convergence criteria, and an allocation failure raised inside any fit, including under `n_restarts > 1`, leaves `fit` as the original exception object, unwrapped and unrecorded as a degenerate restart.

## Context

- Read `pamica/amica.py` (attributes `converged_`, `stop_reason_`, `is_fitted_`; lines 270-310 and 640-690), `pamica/torch_impl/core.py` (stop reasons near lines 2737-3049, `_DEGENERATE_STOP_REASONS` near 4053, the restart loop near 2462-2510), `pamica/mlx_impl/core.py` (its restart loop near 2614), `pamica/blocktune.py` (`is_allocation_failure`, near 220-240), `pamica/restarts.py`, `pamica/mne_compat/core.py` (where it mirrors `converged_`).
- Facts: `converged_` is true for every non-degenerate stop, `max_iter` included (`amica.py:282-289, 657`). The reference's convergence stops are `lrate_floor`, `grad_norm_floor`, `min_dll` and `grad_norm`. With `n_restarts > 1` the torch and MLX restart loops catch every `RuntimeError`; `torch.cuda.OutOfMemoryError` and the MPS out-of-memory error are `RuntimeError` subclasses or instances, so today they become a degenerate restart with a warning.
- This machine has MPS (Apple M4); the `macos-26` runner has an Apple GPU (the weekly job asserts MLX sees one). No CUDA here: the CUDA case runs in the owner's PA-07.
- Q2, passed as a live fact: A: add `did_converge_` beside `converged_` (no rename; reword `converged_`'s docstring to "usable"); B: rename `converged_` to `usable_` everywhere it is defined or read (wrappers, MNE compatibility, docs, tests) and add `did_converge_`, with a changelog warning; C: no flag; only the allocation part of this card.

## Decided design

Settled:
1. `pamica/stop_reasons.py`: `CONVERGENCE_STOP_REASONS = frozenset({"lrate_floor", "grad_norm_floor", "min_dll", "grad_norm"})`, with a docstring citing the reference's stop branches. `AMICA.did_converge_` (and `AMICAICA`'s, if it mirrors fit attributes) is `stop_reason_ in CONVERGENCE_STOP_REASONS` after every `fit` and `load`, False before any fit.
2. The restart loops (torch, MLX): inside `except RuntimeError as exc:`, first `if blocktune.is_allocation_failure(exc): raise` (a bare `raise`, so the same object and traceback leave `fit`); everything else unchanged. The single-restart path stays unwrapped; a test pins it.
3. Tests in `pamica/tests/test_fit_outcome.py`, on the bundled sample:
   (a) a 5-iteration torch fit: `stop_reason_ == "max_iter"`, `converged_` (or `usable_`) true, `did_converge_` false;
   (b) a torch fit that stops on a convergence criterion: find a real setting on the bundled sample (for example `use_min_dll=True` with a larger `min_dll`) that stops on `min_dll` before 300 iterations; assert the stop reason and `did_converge_` true; the same setting on MLX (`importorskip`) gives the same `did_converge_` (cross-backend);
   (c) MPS out of memory (skip when MPS is unavailable), single restart and `n_restarts=2`: cap MPS memory with `torch.mps.set_per_process_memory_fraction` to a fraction that makes the fit's first large allocation fail, restore it in a `finally`; first record the exception a direct allocation of the same size raises under the same cap, then assert the fit raises an exception of exactly that type whose message contains "out of memory", and that no `restart_error` warning was logged (`caplog`);
   (d) a CUDA twin of (c) with `torch.cuda.set_per_process_memory_fraction`, skipped without CUDA, asserting `type(exc) is torch.cuda.OutOfMemoryError` (the owner runs it in PA-07).
The implementer may choose: the exact fraction and data slice for (c), helper names.
