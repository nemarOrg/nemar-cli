# Card PA-10: Owner step: merge the epic into dev, then release a minor version

Status: ready
Tier: owner (never dispatched to an agent; releases are the owner's)
Timebox: the owner's
Needs: the owner's repository permissions
Depends: PA-01, PA-02, PA-03, PA-04, PA-05, PA-06, PA-08
Branch: the epic PR into `dev` that the manager opens (Q1 A), or `dev` itself (Q1 B)
Worktree: the owner's own checkout
Plan: .context/plans/pamica-fixes/plan.md, decision D8; pAMICA `.rules/git.md` and `.rules/changelog.md`
Review: none; the manager records the released version

## Goal

The parity work reaches `main` as a released pamica version on PyPI with its native binaries, so NEMAR can pin it.

## Context

- pAMICA's release chain (`.rules/git.md`): merging `dev` into `main` strips `.devN`, tags, publishes the GitHub release, uploads to PyPI and attaches the binaries; then `main` returns to `dev`.
- This epic adds public API (`AMICANative(start=...)`, `run_record()`, `presets`, the convergence flag), so a minor release fits (0.5.0); `dev` is at 0.4.1.devN.
- `dev` also carries the Linux glibc 2.28 floor (#370, PR #371), so the new Linux binaries load on older systems than 0.4.0's.

## Scope

- The owner's merges and the release-prep PR. Agents do none of it.

## Decided design

Settled: the owner's steps, in order:
1. Q1 A: review and merge the epic PR into `dev` with a regular merge commit (pAMICA keeps epic history). Q1 B: the PRs are already in `dev`.
2. A release-prep PR into `dev`: rename `## Unreleased` to `## 0.5.0 - YYYY-MM-DD` in `docs/changelog.md`, re-read it as one release note, run `uv run python scripts/sync_version.py sync 0.5.0.dev0` and `uv lock`, and use a commit subject that does not start with "Bump version to".
3. Merge `dev` into `main` with a regular merge commit.
4. Check: `gh release view v0.5.0 -R sccn/pAMICA` lists the binaries and their `.sha256` files; `uv pip index versions pamica` or the PyPI page shows 0.5.0.
5. Tell the manager the version; NEMAR's pin bumps (eegprep after PR #617, nemar-process PX-05 and PX-06, with the new `amica15-linux-x64` SHA-256) are the NEMAR program's work.
The implementer may choose: the release date.

## Acceptance

- `gh release view v0.5.0 -R sccn/pAMICA --json tagName,assets` shows the tag and the `amica15-*` assets.

## Gates

- `gh pr checks <release-prep PR> -R sccn/pAMICA` green before step 3 (the changelog check requires the release section and no leftover `## Unreleased`).

## Stop conditions

- The owner decides on a different version or to wait: the manager records it and sets PA-09 `dropped` or leaves it `outline` as the owner says.

## Report

The owner tells the manager the released version; the manager records it with `decide`.
