## Goal

`pamica.presets.RUNAMICA15` holds EEGLAB `runamica15.m`'s settings under pAMICA's names, every `AMICA` and `AMICANative` fit returns a JSON-serializable `run_record()` with everything needed to rerun it, and a test proves that a PyTorch CPU float64 refit from a record, in a new process, is bit-identical on macOS and Linux CI.

## Context

- Read `docs/guides/amica-differences.md` (the defaults table with the `runamica15.m` column, rows 1, 3 and 16), `pamica/sample_data/input.param` (what `runamica15.m` wrote for the bundled sample: its defaults plus `block_size 512`), `pamica/fortran_params.py` (`FORTRAN_TO_PAMICA_KEY`), `pamica/amica.py` (fit keywords, `state_dict` and save metadata), `pamica/torch_impl/core.py` (the saved `config`, near line 4172), PA-02's native fields (`binary_sha256_`, `binary_name_`, `params_`, `start_`) and PA-05's `did_converge_` (or the name Q2 chose).
- The NEMAR pipeline this names: pamica version, engine torch, device cpu, dtype float64, threads 1, seed, `RUNAMICA15` plus `block_size` (NEMAR uses 131072).
- Lead's local measurement (Apple M4, torch 2.12.1, `dev` at 0e93728): seed 5489, `block_size` 131072, Newton on from 50, `lrate` 0.05, 200 iterations: weights and LL history bit-identical across two processes and across 1, 4 and 8 threads. Linux is unmeasured.

## Decided design

Settled:
1. `RUNAMICA15` is a read-only mapping (`types.MappingProxyType`) of the `runamica15.m` column under pAMICA keyword names (map each `input.param` key through `FORTRAN_TO_PAMICA_KEY`): `lrate` 0.05, `minlrate` 1e-8, `lratefact` 0.5, `max_decs` 3, `do_newton` True, `newt_start` 50, `newtrate` 1.0, `newt_ramp` 10, `pdftype` 0, `do_opt_block` False, `max_iter` 2000, `n_mix` 3, `rho0` 1.5, `minrho` 1.0, `maxrho` 2.0, `rholrate` 0.05, `rholratefact` 0.5, `invsigmin` 0.0 (what the binary receives from `runamica15.m`'s `%f`), `invsigmax` 100.0, `mineig` 1e-12, `do_mean`, `do_sphere`, `doscaling` True, `share_comps` False, `share_start` 100, `share_iter` 100, `comp_thresh` 0.99, `do_reject` False, `use_min_dll` True, `min_dll` 1e-9, `use_grad_norm` True, `min_grad_norm` 1e-7, plus the reference-restoring `keep_best=False` and the absolute `mineig` floor as row 1 of the differences guide documents its restore. It excludes `block_size`, `max_threads`, `seed`, `pcakeep`: the caller's, recorded.
   Where a pAMICA spelling differs from these names, use pAMICA's and say so in the module docstring.
2. `run_record()` returns a dict with `schema` `"pamica.run-record.v1"`, `pamica_version`, `engine` (`"torch"`, `"mlx"`, `"native"`), `device` (type, and the device name for CUDA and MPS), `dtype`, `versions` (torch, mlx when used, numpy, python), `threads` (`torch.get_num_threads()` at fit start; `max_threads` for native), `seed`, `restart_seeds`, `settings` (every constructor and fit setting after defaults are resolved), `data` (`n_channels`, `n_samples`, `sha256` of the C-contiguous float64 data bytes), `result` (`iterations`, `stop_reason`, the Q2 flag, `final_ll`, `best_iter`, kept components), and for native also `binary_sha256`, `binary_name`, `start` and the written `params`. Calling it before `fit` raises `RuntimeError`. It contains no path: a test asserts that no string value in the record contains `/` or `\` (`binary_name` is a basename).
3. `pamica/tests/test_reproducible_runs.py` (not gated, runs in `ci.yml`'s Linux and macOS jobs): with `RUNAMICA15`, `block_size` 131072, seed 5489, float64 CPU, `max_iter` 60, fit in two fresh subprocesses at threads 1 and assert `numpy.array_equal` of the unmixing matrix and the LL history (D1); refit in a third subprocess from `json.loads(json.dumps(record))["settings"]` plus the record's seed and threads and assert the same equality; fit at threads 2 and 4 and print `D2 os=<os> threads=<t> equal=<bool> max_abs_dW=<x>` without asserting it. A CUDA twin of D1 skips without CUDA (PA-07 runs it).
4. `pamica/tests/test_presets.py`: for every key of the bundled `input.param` that `RUNAMICA15` covers, the value `AMICANative(**RUNAMICA15)._input_params(...)` writes parses to the same number as the file's value.
5. `docs/guides/reproducible-runs.md` names the pipeline, shows a five-line example (fit, `run_record()`, `json.dump`), and states what is and is not reproducible: bit-identical within one engine, device, dtype and thread count (D1); across thread counts as measured per operating system (D2, the CI values); CUDA as PA-07 measures it; float32 is not a reproduction of a float64 record; across engines see the same-seed tiers in the validation guide.
The implementer may choose: the record's key order, helper names, how subprocesses receive the data path.

## Stop conditions

- D1 fails on any CI operating system: stop and report the run id and the lines (the reproducibility promise is at stake; the manager asks the owner).
- A `runamica15.m` value cannot be expressed in pAMICA (for example `invsigmin` 0.0 breaks a fit): report it; do not substitute another value without the lead.
- The record would need a change to a saved-model format: stop and report.
