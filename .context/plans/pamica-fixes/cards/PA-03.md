## Decided design

Settled:
1. One fixture runs each binary fit once per (seed, iterations, settings) through `AMICANative(start="pamica", seed=s, threads=1, **settings)` and caches it for the module; pamica fits run through `AMICA(backend=...)` or `AMICA_NumPy` with the same settings and seed and `keep_best=False`.
2. Each tier test prints exactly one line per backend and seed, `PARITY tier=<T> backend=<b> seed=<s> iters=<n> dll=<x> min_corr=<y> median_corr=<z> amari=<w>` (with `capsys.disabled()`), then asserts the tier's thresholds. A and B are not marked slow; C and C32 are `@pytest.mark.slow`.
3. Negative control (not slow, gated): `AMICANative(start=None, seed=42)` against pamica seed 42 does not meet A1 (first-iteration LL difference above 1e-6), proving the A gates discriminate.
4. `validate_implementations.py --start {independent,shared}`, default `independent` (the default report stays byte-identical); `shared` adds a block "shared start (AMICANative start="pamica")" with the same columns per backend.
5. Parity budget (R5): for A or B, a miss is a probable defect: at most two approaches (re-check the settings both sides received with `params_`; re-check the start with PA-02's A1 line), then stop and report without xfail. For C or C32, a miss after one weekly run is "not attained": post Appendix B (plan) with the measured numbers, mark that test `xfail(strict=True, reason="#<issue>: not attained, see validation.md")`, and write the docs row. Comment the C32 numbers on #362 either way, one comment.
6. Docs: what "same seed" means (plan section 1), the tier table with the measured CI values, the run ids, the binaries' SHA-256 and the conditions, and the per-backend reading from plan section 5's last column.
The implementer may choose: fixture structure, how the binary's per-iteration LL is read (from `output_`), helper names.
