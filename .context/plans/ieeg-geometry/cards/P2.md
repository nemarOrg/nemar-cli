## Goal

A mirror that carries NEMAR's iEEG geometry files re-pulls cleanly: those paths are never counted or replayed as corrections, and the N.0.1 regenerates them from the new snapshot, deterministically.

## Decided design

Settled:
- Read `.nemar/ieeg-geometry.json` at the plan's base. Every path it lists is classified `pipeline-owned`: not a correction, not an unexplained path, not counted in `counts.corrections`, not a ledger concern; the plan lists them in their own section with count.
- If upstream has a file at a pipeline-owned path, upstream wins and the path leaves ownership (amendment item 2).
- N.0.1 is made when there are corrections or when pipeline-owned paths exist at the base. Its tree is the new `main` plus replayed corrections plus the pipeline's regenerated outputs (run the pipeline in `--apply` mode on a checkout of the new `main` via the new subprocess module, then take exactly the report's `changes`), plus the regenerated ownership file. The commit must stay deterministic so resume can re-derive it: the pipeline's outputs are deterministic for a given snapshot and pipeline version; pin the version and assert it.
- A regeneration that fails leaves the previous pipeline files out of N.0.1 and records the failure on the re-pull record (amendment item 4); the snapshot's own files are never held back.
- The automatic path (`automaticPlanRefusal`) is not refused for pipeline-owned paths alone.
- The pipeline's outputs are small git (not annexed) files; assert that, so `assertReplayedKeys` needs nothing new.

The implementer may choose: where the subprocess module lives, how the plan records pipeline-owned paths.
