## Goal

`ieeg_geometry.surfaces_out` turns a dataset's subject cortical surfaces into `brain-mesh v1` files in the contacts' own frame, with an index the website reads, for every subject whose surface verifiably fits its contacts (77 subjects in 11 datasets by the census).

## Context

- Read the plan, `census.md` (track A, pitfalls), the L1 package (its `brain-mesh v1` reader, `surfaces.py`, `verify.py`).
- The website reads `brain-mesh v1` with 16-bit indices: each hemisphere must have at most 65,535 vertices. Its decoder is `nemarOrg/website` `src/lib/ieeg-spatial/mesh-format.ts`; its Python writer `scripts/vendor-brain-template.py` (`encode_brain_mesh`).
- Surfaces to expect: FreeSurfer `surf/?h.pial` (and `?h.pial.T1`), GIfTI `pial.L/R.surf.gii`, MATLAB `cortex` structs, possibly under `sourcedata/` (nm000369). One hemisphere per subject is real (on004457, on005953).

## Scope

`scripts/ieeg_geometry/ieeg_geometry/surfaces_out.py`, a `brain-mesh v1` writer in the package, the index JSON Schema `scripts/ieeg_geometry/schema/geometry-index.v1.json`, tests and fixtures; nothing else.

## Decided design

Settled:
- Per subject and electrodes file: pick the surface whose L1 `fit_with_offset` passes (prefer as declared over c_ras when both pass; prefer the subject's own folder over shared ones); apply c_ras to the vertices when the offset was needed, so the mesh is in the contacts' frame. A subject with no passing surface is skipped and reported.
- Decimation to at most 65,535 vertices per hemisphere by vertex clustering on a regular grid, then removal of degenerate faces; the face winding stays counter-clockwise from outside (test it with the signed volume, as the website's vendoring script does). Keep each hemisphere under 1.5 MB.
- Output layout under an output directory (the data plane path is P3's job): `geometry/index.json` and `geometry/<subject>/<electrodes file stem>/{lh,rh}.mesh.bin` (only the hemispheres present).
- `index.json` (schema `nemar-ieeg-geometry-index`, version 1, a JSON Schema committed in this card): `pipeline_version`, `source_commit`, and one entry per electrodes file with `subject`, `session`, `electrodes` (the dataset path), `frame` (the electrodes file's declared frame), `offset_applied` (`c_ras` vector or null), `hemispheres`, `fit` (L1's fields), `sources` (paths of the surface files), `meshes` (relative paths and SHA-256 of each mesh file). Written deterministically.
- The index schema is frozen in this card's PR; card A2 builds against it.

The implementer may choose: the clustering cell size search, helper structure.

## Acceptance

- `uv run --project scripts/ieeg_geometry pytest -q` passes with tests that each fail without the code, including: a FreeSurfer fixture needing c_ras produces vertices in the contacts' frame (its contacts' median distance to the written mesh is at most 2.0 mm for ECoG); a GIfTI column-major one-hemisphere fixture produces only that hemisphere; decimation keeps at most 65,535 vertices and outward winding; a subject whose surface does not fit is skipped and listed; the index validates against the schema and is byte-identical on rerun; the written mesh decodes with L1's reader.
- `python -m ieeg_geometry inspect` (or a new `surfaces` subcommand) on the fixtures prints the per-subject decision; quote it in the PR.

## Stop conditions

- A hemisphere cannot be brought under 65,535 vertices while its contacts stay within the fit threshold of the decimated mesh.
- More than one of the census's same-frame subjects in your fixtures fails the fit.
