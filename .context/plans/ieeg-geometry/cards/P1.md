## Goal

`python -m ieeg_geometry run <dataset_id> [--version V] --workdir DIR [--apply] [--surfaces-out DIR]` fetches exactly the files a dataset's geometry needs, runs the label (C1), FreeSurfer (B1) and SPM (B2) tracks and the subject-surface builder (A1), and prints one machine-readable report, writing nothing unless `--apply` is given.

## Context

- Read the plan's rulings in full, the package README, and each track's module (`labels.py`, `freesurfer.py`, `spm.py`, `surfaces_out.py`) for its plan and write functions.
- Data access: the file tree from `git clone --no-checkout --filter=blob:none https://github.com/nemarDatasets/<id>` (or the GitHub trees API), small git files from the clone, annexed content from `https://data.nemar.org/<id>/<version>/<path>` with urllib (curl returned empty bodies in a sandbox; use urllib), version from `https://api.nemar.org/datasets/<id>`. Fetch only what the tracks read: electrodes, coordsystem, channels, README, `dataset_description.json`, `.nemar/ieeg-geometry.json`, the subject surfaces and `sphere.reg` the tracks select, and SPM `y_` fields; never the recordings.
- The tracks share `.nemar/ieeg-geometry.json`; each already merges its entries and keeps hand-edited owned files.

## Scope

`scripts/ieeg_geometry/ieeg_geometry/pipeline.py` (new), `fetch.py` (new), `__main__.py` (the `run` subcommand), the report JSON Schema `schema/geometry-report.v1.json` (new), tests and fixtures, README rows. Nothing outside the package.

## Decided design

Settled:
- Order inside one run: labels first, then FreeSurfer, then SPM, each planned against the same snapshot; a later track never writes a subject-and-space the authors or an earlier track already covers in this run (ruling 4 applied across tracks); then the subject surfaces for the display index.
- The report (`nemar-ieeg-geometry-report`, version 1): dataset id, version, source commit, pipeline version, and per electrodes file the decision of each track (written, unchanged, kept as hand-edited, needs-human, refused, skipped) with its reason, evidence grade and the key numbers; dataset-level suppressions; warnings; counts; the files a `--apply` would add, change or remove; and the subject-surface entries. Deterministic.
- `--apply` writes into the work tree only (the git checkout under `--workdir`) and the surfaces into `--surfaces-out`; it never commits, pushes, opens a pull request or uploads. P2 and P3 do that.
- A network or fetch failure for one file makes that file's decision `skipped` with the reason; a failure to fetch the tree or the version fails the run with a clear message.
- Never touches `nm000103` to `nm000107` or `nm099998`: the run refuses those ids outright (test it).
- One strict `pipeline_version()` for the whole package (C1's, in `labels.py`, moved to a shared module if cleaner): remove `surfaces_out.py`'s own fallback to "unknown" (B1 review), so every output names the same version or the run fails.

The implementer may choose: the fetch cache layout, internal function boundaries.
