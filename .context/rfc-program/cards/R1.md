## Decided design

- **Why the window is short** (owner, 2026-11-20): state this rationale in the text. Reviews today are often helped by AI; NEMAR welcomes AI-assisted review and contributions when knowledgeable people use the AI and check what it produces. With that help, a careful review fits in three weeks, so NEMAR RFCs are fast-paced: at most 21 days, with one extension of at most 14.
Settled:

- Record format: Markdown with YAML front matter, fields exactly
  `number, title, scope (org | dataset), dataset (null or an id such as nm000123), shepherd, authors, discussion, opened_at, window_days, extension (null or {granted_at, days, reason}), final_comment_at, proposed_disposition (null | accept | reject), decision (null | accepted | rejected | withdrawn), decided_at, decided_by, adr, supersedes_rfc, withdrawn_at, withdrawn_reason`.
- Body sections of the template, in order: Summary; Scope; Problem; Proposal; Who is affected; What does not change, and what is irreversible; Options considered; Prior art; Questions for commenters; How the decision will be made; Rollout and cost; Change log.
  The PR body of a draft carries the opening post: the summary, the questions, the close date in UTC, and how to comment without a GitHub account.
- Files are `text/NNNN-kebab-title.md`; the draft PR takes the next number unused by merged files and by every PR, open or closed, that ever added a `text/` file; numbers are never reused.
- One pure function `rfcStatus(record, now)` in `src/status.ts` returns `draft | open | extended | final-comment | closed | accepted | rejected | withdrawn`; both checks import it.
- The close is an instant: `opened_at` (UTC, to the minute) plus `window_days` (plus `extension.days`) times 24 hours; the opening post prints it.
- Rules `rfc-check` enforces: `window_days` is an integer from 7 to 21; at most one extension; an extension is at most 14 days, `granted_at` is before the close, and a PR that adds or changes `extension` is refused when the check runs after the close (the check's own clock, not the asserted date); at most one RFC is open for comment at a time (`open`, `extended` or `final-comment`) across the repository, so a PR that sets `opened_at` while another RFC is open is refused; `accepted` only if `final_comment_at` is at least 7 days before the close (5 days when `window_days` is 7 to 10) and `proposed_disposition` is set; decision fields only after the close, except `withdrawn`, which may be set at any time with `withdrawn_at` and `withdrawn_reason`; a non-null `decision` requires `decided_at` and `decided_by`; `accepted` requires `adr` (a link); a non-null `decision` other than `withdrawn` requires a body section `## Disposition of comments` that is not empty; status never moves backward against the base branch's copy; `number` matches the file name and is unique; the index between `<!-- rfc-index:start -->` and `<!-- rfc-index:end -->` in `README.md` equals the generated index; the front matter validates against the schema.
- `rfc-check.yml`: on `pull_request` and `push` to `main`, job name `rfc-check`, `concurrency` cancelling superseded runs, `timeout-minutes: 10`, steps `bun install --frozen-lockfile`, `bun run lint`, `bun run typecheck`, `bun test`, `bun run src/check.ts`.
- `rfc-clock.yml`: `cron: "0 14 * * *"` and `workflow_dispatch`, `permissions: {contents: read, discussions: write}`, `timeout-minutes: 10`.
  For each RFC in `open`, `extended` or `final-comment`, it posts one reminder 7 days and one 2 days before the close, each marked by a hidden HTML comment so a rerun posts nothing twice; at the close it posts a closing comment and locks the thread (`lockLockable`).
  It edits no file and decides nothing; when GitHub's state disagrees with the record (a thread unlocked after its close, a thread missing) it fails the run and says so, and it also fails the run for an RFC that has been `closed` with no decision for more than 14 days.
  The plan of actions is a pure function `planClockActions(records, threads, now)`; execution goes through `GITHUB_GRAPHQL_URL` (default `https://api.github.com/graphql`) so tests point it at a `Bun.serve` stand-in.
- `ops/ruleset-main.json`: a repository ruleset on `main` requiring the status check `rfc-check`, blocking force-pushes and deletion; the owner applies it (step O1b).
- `PROCESS.md` states the process in plain language, including the owner answers to Q1 to Q7, the one-RFC-at-a-time rule, the exact close instant, that comments sent to the support address before the close are posted by a maintainer even after the thread locks, and that every comment gets a written disposition before a decision, and lists the announcement channels: the thread, a news post, a command-line interface (CLI) notice expiring at the close, and broadcast mail that honors the `announcements` preference (production only).
- `LICENSE.md` and `LICENSES/` follow the owner's answer to Q6.
- Tooling: Bun, TypeScript, Biome; `package.json` scripts `lint` (`biome check .`), `typecheck` (`tsc --noEmit`), `test` (`bun test`).

The implementer may choose: module layout under `src/`, the YAML parser (a maintained package), and wording.

## Acceptance

`bun test` passes and includes one named test per rule above, each failing when its rule is removed: for each rule, report the one-line mutation you applied and the failing test's name.
`bun test` includes these named cases: `rfcStatus` returns each of the eight states; `window_days: 22` is refused; a second extension is refused; a 15-day extension is refused; an extension granted after the close is refused; `accepted` with `final_comment_at` 6 days before the close is refused; a status moving from `closed` to `open` is refused; a stale index is refused; the clock posts each reminder once across two runs against the stand-in; the clock locks at the close; the clock fails the run on an unlocked closed thread; the clock fails the run on an RFC closed and undecided for 15 days; a second RFC opened while one is open is refused; a number used by a closed, unmerged PR is refused; `withdrawn` before the close is accepted; `accepted` with `adr: null` is refused; a decision without `decided_at` is refused; a decision without `## Disposition of comments` is refused; an extension added after the close (check clock past the close) is refused.
`bun run src/check.ts` exits 0 on the repository as committed (empty `text/`), and exits non-zero on a fixture with `window_days: 22`.
