## Decided design

Settled:

- Record format: Markdown with YAML front matter, fields exactly
  `number, title, scope (org | dataset), dataset (null or an id such as nm000123), shepherd, authors, discussion, opened_at, window_days, extension (null or {granted_at, days, reason}), final_comment_at, proposed_disposition (null | accept | reject), decision (null | accepted | rejected | withdrawn), decided_at, decided_by, adr, supersedes_rfc, withdrawn_at, withdrawn_reason`.
- Body sections of the template, in order: Summary; Scope; Problem; Proposal; Who is affected; What does not change, and what is irreversible; Options considered; Prior art; Questions for commenters; How the decision will be made; Rollout and cost; Change log.
  The PR body of a draft carries the opening post: the summary, the questions, the close date in UTC, and how to comment without a GitHub account.
- Files are `text/NNNN-kebab-title.md`; the draft PR takes the next unused number; numbers are never reused.
- One pure function `rfcStatus(record, now)` in `src/status.ts` returns `draft | open | extended | final-comment | closed | accepted | rejected | withdrawn`; both checks import it.
- Rules `rfc-check` enforces: `window_days` is an integer from 7 to 21; at most one extension; an extension is at most 14 days and `granted_at` is before the close; the close is `opened_at + window_days (+ extension.days)` in calendar days UTC; `accepted` only if `final_comment_at` is at least 7 days before the close (5 days when `window_days` is 7 to 10) and `proposed_disposition` is set; decision fields only after the close; status never moves backward against the base branch's copy; `number` matches the file name and is unique; the index between `<!-- rfc-index:start -->` and `<!-- rfc-index:end -->` in `README.md` equals the generated index; the front matter validates against the schema.
- `rfc-check.yml`: on `pull_request` and `push` to `main`, job name `rfc-check`, `concurrency` cancelling superseded runs, `timeout-minutes: 10`, steps `bun install --frozen-lockfile`, `bun run lint`, `bun run typecheck`, `bun test`, `bun run src/check.ts`.
- `rfc-clock.yml`: `cron: "0 14 * * *"` and `workflow_dispatch`, `permissions: {contents: read, discussions: write}`, `timeout-minutes: 10`.
  For each RFC in `open`, `extended` or `final-comment`, it posts one reminder 7 days and one 2 days before the close, each marked by a hidden HTML comment so a rerun posts nothing twice; at the close it posts a closing comment and locks the thread (`lockLockable`).
  It edits no file and decides nothing; when GitHub's state disagrees with the record (a thread unlocked after its close, a thread missing) it fails the run and says so.
  The plan of actions is a pure function `planClockActions(records, threads, now)`; execution goes through `GITHUB_GRAPHQL_URL` (default `https://api.github.com/graphql`) so tests point it at a `Bun.serve` stand-in.
- `ops/ruleset-main.json`: a repository ruleset on `main` requiring the status check `rfc-check`, blocking force-pushes and deletion; the owner applies it (step O1b).
- `PROCESS.md` states the process in plain language, including the owner answers to Q1 to Q7, and lists the announcement channels: the thread, a news post, a command-line interface (CLI) notice expiring at the close, and broadcast mail that honors the `announcements` preference (production only).
- `LICENSE.md` and `LICENSES/` follow the owner's answer to Q6.
- Tooling: Bun, TypeScript, Biome; `package.json` scripts `lint` (`biome check .`), `typecheck` (`tsc --noEmit`), `test` (`bun test`).

The implementer may choose: module layout under `src/`, the YAML parser (a maintained package), and wording.

## Acceptance

`bun test` passes and includes one named test per rule above, each failing when its rule is removed: for each rule, report the one-line mutation you applied and the failing test's name.
`bun test` includes these named cases: `rfcStatus` returns each of the eight states; `window_days: 22` is refused; a second extension is refused; a 15-day extension is refused; an extension granted after the close is refused; `accepted` with `final_comment_at` 6 days before the close is refused; a status moving from `closed` to `open` is refused; a stale index is refused; the clock posts each reminder once across two runs against the stand-in; the clock locks at the close; the clock fails the run on an unlocked closed thread.
`bun run src/check.ts` exits 0 on the repository as committed (empty `text/`), and exits non-zero on a fixture with `window_days: 22`.
