## Decided design

**Where things land.**
Settled: everything this card makes lands on `draft/3.0.0`, through a PR whose base is `draft/3.0.0`, and nothing lands on `main`.
`GOVERNANCE.md` makes any change to a JSON Schema normative, and `main` carries only accepted text, so even the version 2 schemas, which only transcribe the `2.0.0` text, wait for RFC-0001's acceptance to reach `main`.
`schemas/v2/` describes format version 2 as tag `2.0.0` specifies it; `schemas/v3/` describes the `3.0.0-draft` text.
The version 1 and version 2 vectors belong to the version 3 suite, because the draft requires a version 3 reader to read version 2 stores and to refuse a store with no `format_version`.
The release that carries all of it is `3.0.0-draft.2`, tagged after this PR merges into `draft/3.0.0` (step O4c).

**Schemas.**
Settled: JSON Schema draft 2020-12; one file per attribute document, named for it
(`root`, `uniform-group`, `level0-array`, `view-array` and `events-group` in both versions, plus `timestamped-group`, `time-array` and `values-array` in `v3`),
with shared definitions (`valid_intervals`, `derivation`, the source fields of "Sample resolution", `zarr_conventions`, `missing_value`) in `schemas/v3/defs.schema.json`.
`$id` is `https://w3id.org/biosig-zarr/schemas/vN/NAME.schema.json` and matches the file's path.
A schema transcribes the text and adds nothing: a constraint the text does not state is not in a schema, and every `required`, `enum`, `const` and `pattern` carries a `$comment` naming the spec heading it comes from.
CONDITIONAL attributes are written with `if` and `then`.
Unknown attributes are allowed (no `additionalProperties: false` on attribute documents), because the text says a reader MUST ignore attributes it does not recognize; the `zarr_conventions` entry is the exception, closed as the text requires.
The NEMAR profile's attributes are not in the format schemas.

**Vectors: the source.**
Settled: every vector is cut from one real recording dedicated to the public domain:
nemar `on009081` version `v1.0.0` (OpenNeuro `ds009081`, license CC0), file `sub-01/eeg/sub-01_task-rest_eeg.edf` (224,464 bytes, 100 Hz, European Data Format (EDF)),
read only, from `https://data.nemar.org/on009081/v1.0.0/sub-01/eeg/sub-01_task-rest_eeg.edf`, with a named User-Agent.
Record in `conformance/SOURCES.md` the dataset, version, path, the source file's SHA-256, its license, the channels and seconds kept, and every step applied, including each alteration made to an invalid vector or to a gap.
If that file is unavailable or its license is not CC0 when you read it, stop (see Stop conditions); do not substitute a recording on your own.
Optional: if S1 has merged and lists a CC0 EDF+D file with a real gap, you MAY add one vector cut from it with Range reads; the suite does not depend on it.

**Vectors: how they are made.**
Settled: version 2 vectors are written by biosigIO 1.2.13 from a crop of the source (`uvx --from biosigio==1.2.13`, subject-information exclusion on), and stay byte-identical to that writer's output except for the one recorded alteration a vector names.
No writer of version 3 exists, so version 3 vectors are built by `tools/vectors/` from the same crop with stock zarr-python and NumPy:
it writes the metadata documents the text specifies and the arrays with the codec chains the text names, and every resampling, quantization or alteration it applies is recorded in the store's `derivation` lists and in `SOURCES.md`.
It is a one-purpose vector builder, not a library: it exports nothing, and nothing outside `tools/` imports it.
Invalid vectors are valid vectors altered in one controlled, recorded way, so each failure is attributable to one rule.
Keep every vector small: a few channels and a few seconds; the whole of `conformance/` stays under 20 megabytes (MB).

**Vectors: the minimum set.**
Settled, by `id` (the implementer may add a vector, never drop one):

| `id` | What it is | Expected outcome |
| --- | --- | --- |
| `v2-legacy-name` | biosigIO 1.2.13 store, `format` `biosigio-zarr`, `format_version` 2, zero events | accepted; read as version 3 with the defaults of "Reading earlier versions" (one interval, `start_time` 0, `missing_value` null, `onset_source_basis` `unknown`) |
| `v2-new-name` | the same with `format` `biosig-zarr` | accepted, identical to `v2-legacy-name` |
| `v1-no-format-version` | the same with no `format_version` and `recording_metadata` as a JSON string | refused as unsupported (layer 1) |
| `v3-continuous` | `format_version` 3, one uniform `int16` group, one interval, `missing_value` -32768, the `zarr_conventions` entry | accepted, with goldens; a reader without `missing_value` refuses, naming it (layer 4) |
| `v3-gap-10hz` | 10 Hz, `n_samples` 40, intervals `[0, 20)` and `[24, 40)` with `source_time` 0.0 and 2.4; one sample missing inside an interval; events at 2.02 s, 0.25 s, 1.25 s and 3.25 s; view levels with factors 4 and 16 | 2.02 s has no sample (`i = 20`, in the gap); 0.25 s, 1.25 s and 3.25 s give samples 3, 13 and 33 by `floor(x + 0.5)` (a round-half-to-even reader gives 2, 12 and 32); view column 5 of factor 4 is empty by the mask rule and holds the missing value, and column 1 of factor 16 is not empty; a reader without `valid_intervals` refuses, naming it (layer 4) |
| `v3-start-time` | `v3-continuous` with `start_time` 1.5 | onsets map with the offset; a reader without `start_time` refuses, naming it (layer 4) |
| `v3-timestamped` | a uniform group plus a timestamped group whose `time` holds the source's own sample times; `zarr_conventions` holds a second entry for an unknown convention | accepted; a reader navigating by `channel_groups` sees only the uniform group (layer 3); the unknown convention is no reason to refuse |
| `v3-version-4` | `v3-continuous` with `format_version` 4 | refused by version (layer 1) |
| `v3-unknown-format` | `v3-continuous` with `format` `example-zarr` | refused |
| `v3-no-kind` | `v3-continuous` with `kind` removed from the group | refused (layer 2) |
| `v3-unknown-kind` | `v3-continuous` with `kind` `sparse` | refused (layer 2) |
| `v3-timestamped-listed` | `v3-timestamped` with its timestamped group also named in `channel_groups` | refused (layer 3) |
| `v3-bad-intervals` | `v3-gap-10hz` with overlapping intervals | refused ("Reading untrusted stores") |
| `v3-no-conventions` | `v3-continuous` without `zarr_conventions` | fails `schemas/v3/root` (writer conformance) |
| `v3-conventions-extra-member` | the `zarr_conventions` entry with a member the text does not allow | fails `schemas/v3/root` |

The 10 Hz rate comes from the 100 Hz source by resampling, recorded in each channel's `derivation`.
Check every tie in 64-bit floating point before relying on it (for example `0.25 * 10` is exactly `2.5`); a value that is not an exact tie is no tie case.
Every number in the table that a reader computes (samples, empty columns) is computed again by `tools/check-vectors.ts` from the vector's own metadata, and the test fails if the manifest and the computation disagree.

**The manifest.**
Settled: `conformance/manifest.json` lists every vector with `id`, `path`, `format_version`, `class` (`valid` or `invalid`), `layer` (1 to 4, or null), `rule` (the spec heading's anchor), `expect` (the outcome, including the capability-conditioned refusals of layer 4 and the event-to-sample results), and `files` (the SHA-256 of every file in the vector).
It is the contract that copies elsewhere pin by digest (Q9).

**The checks.**
Settled:
`tools/check-schemas.ts` compiles every schema under draft 2020-12 in strict mode, checks each `$id` against its path, validates every attribute document of every `valid` vector, and confirms each schema-invalid vector fails at the path its manifest entry cites.
`tools/check-vectors.ts` reads only metadata and decodes no chunk; it applies the four reader-safety layers, the version rules, the onset rule and the mask rule, and compares each result with the manifest.
`tools/check-vectors.test.ts` (Bun test, no mocks) proves each check can fail: it runs the checker with one check turned off through a parameter of the checker, and asserts that at least one vector's outcome then changes, for each of the four layers, the `round` ties and the mask rule.
`tools/vectors/test_vectors.py` (pytest, under uv) opens every valid vector with stock zarr-python and no other code, dequantizes with the text's formula, compares the values with `goldens/` (missing samples as missing), and recomputes every digest in the manifest.

**Continuous integration.**
Settled: B5 adds one workflow, `.github/workflows/conformance.yml`, not a separate `schemas.yml`:
two jobs, `schemas` (`bun run check:schemas` and `bun test`) and `vectors` (Ruff, ty and pytest under uv), each with `timeout-minutes`,
on pull requests and on pushes to `main`, path-filtered to `schemas/**`, `conformance/**`, `tools/**` and the workflow itself, with the same `concurrency` rule as `text.yml`, and actions pinned by commit as `text.yml` pins them.
`text.yml` keeps running as it is; `biome.json` and `_typos.toml` exclude `conformance/stores/**`, so a writer's own JSON formatting is never rewritten.

The implementer may choose: the channels and seconds kept, the JSON Schema validator package, the layout inside `tools/vectors/`, the wording of `conformance/README.md`, and any vector added beyond the minimum set.

## Stop conditions

The source file is unavailable, differs from the size above, or is not CC0;
writing a schema shows that the text is ambiguous or contradicts itself (report the lines and the two readings; do not choose, because the text is RFC-0001's and the lead decides);
a vector's expected outcome cannot be derived from the text alone;
biosigIO 1.2.13 cannot be run with uv, or its output cannot be kept byte-identical where this card says so;
building a vector would need a reader or writer library inside this repository;
`conformance/` cannot be kept under 20 MB.
