## Decided design

**Step 0, before anything is read.**
Settled: check that nothing is still writing the cache:
`pgrep -fl "scan.py"` prints nothing, and `find SCAN_DIR/cache.json -mmin -15` prints nothing (SCAN_DIR is the scan directory above).
If either prints something, stop (see Stop conditions); do not copy a cache that is being written.
Then copy `scan.py`, `cache.json` and the logs into `/Users/yahya/.cache/nemar-s1-scan/`, record the cache's SHA-256 and size at copy time, and run everything there.
If the scan directory is gone (a reboot clears it), say so and run the stages from the start with the copy of the script kept in this pack, `.context/rfc-program/research/edfd-scan/scan.py` (copied at C1; method only, no results).

Settled: measure, in this order:

1. **Finish the header pass.**
   Retry each failed header once (`scan.py heads` re-reads entries whose record is not `ok`), then classify the failures that persist by their recorded reason (HTTP status, timeout, unresolvable URL), with counts per dataset.
   The `manifests` stage used `aws s3 cp` for listings over the size limit; do not run `aws`: the listings are already in the cache, and a missing one is reported, not fetched with a credential.
   GitHub tree listings (`scan.py tree`) are reads through `gh api` and are allowed.
2. **The deep pass** on every `EDF+D` and `BDF+D` file: run `scan.py deep`; report per file and per dataset the files with real gaps (`gap_count` above 0), the total gap seconds, files whose onsets could not be parsed, and bisections that stopped at their read limit (`truncated`).
   Before running it, compute from the cache the bytes the whole-file reads will fetch (files up to 12 MB); if that exceeds 20 gigabytes (GB), stop and report the number.
3. **BrainVision** recordings with more than one `New Segment` marker (from the `.vmrk` files, Range reads only).
4. **FIF** recordings with acquisition skips (from the FIF tag directory, Range reads only); if this needs a full download per file, measure a fixed-seed sample of 50 and say so.
5. For each class, the number of stores (recordings) and datasets affected, and the license of each affected dataset (from the public API).
6. **Conversion throughput:** from the public API's `zarr_converted_at` across datasets over the last 30 days, the stores converted per day (median and 90th percentile), and the projected days to re-convert all 231,259 stores and the affected subset first.

Commit to `evidence/s1/` the scripts as run (with any change to `scan.py` stated in `s1-catalog.md`) and compact derived outputs: the tally, the per-dataset counts, the per-file deep results for `+D` files, and the classified failures, as JSON or text under 5 MB in total; never the whole cache.
Every number in `s1-catalog.md` has a `Command:` line and a `Raw output:` line naming the file it came from.

The implementer may choose: the language of the new BrainVision, FIF and throughput scripts, and the sample seed.
